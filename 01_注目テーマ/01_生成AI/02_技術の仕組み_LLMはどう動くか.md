# 生成AI｜技術の仕組み（LLMはどう動くか）

**このノートで分かること**：大規模言語モデル（LLM）が中で何をしているか。
**LLMは「次に来る単語を当てる装置」であって、それ以上でも以下でもない**。
この一点を押さえると、幻覚（ハルシネーション）もRAGもファインチューニングも、全部同じ理屈で説明できる。

## 1. 一言でいうと「次の1語を当てるゲーム」

LLM（Large Language Model＝大規模言語モデル）がやっているのは、
**これまでの文字列を見て、次に来る確率が最も高い断片を1つ選ぶ**こと。
それを1個ずつ繰り返して文章になる。

```
入力: 「日本の首都は」
        ↓ モデルが次の候補に確率を付ける
        「東京」  82%
        「江戸」   4%
        「大阪」   2%
        ...
        ↓ 1つ選んでつなげる
出力: 「日本の首都は東京」 → これを入力に戻して次の1語へ → 「です」 → …
```

- 検索して答えているのではない。**学習時に覚えた確率分布から、もっともらしい続きを生成している**
- だから「知らないこと」でも、もっともらしい続きを自信満々に作ってしまう。これが**ハルシネーション（幻覚）**の正体
- 逆に言えば、**正しい材料を入力側に入れてやれば精度は上がる**。RAG（後述）はこの発想

> ポイント：LLMは「知識データベース」ではなく「言語の確率モデル」。
> 事実性が必要な用途では、外から事実を渡す仕組みとセットで使うのが原則になる。

## 2. トークン：AIにとっての「文字の単位」

モデルは文字をそのまま扱わない。**トークン**という単位に切り刻んでから数値に変換する。

| 対象                           | おおよそのトークン数（目安）                     |
| ------------------------------ | ------------------------------------------------ |
| 英語                           | 1トークン ≒ 4文字 ≒ 0.75単語                     |
| 日本語                         | 1文字 ≒ 0.7〜1.5トークン（モデルの設計で変わる） |
| 日本語のA4文書1枚（約1,000字） | だいたい1,000〜1,500トークン                     |
| 本1冊（10万字）                | 10万〜15万トークン規模                           |

**なぜトークンが重要か**：

1. **課金の単位がトークン**。API料金は「入力100万トークンあたり◯ドル」で決まる
2. **処理できる量の上限もトークン**（次節のコンテキスト長）
3. **日本語は英語よりトークン効率が悪くなりがち**で、同じ内容でも割高・上限に早く当たることがある

```
「生成AIは便利です」
   ↓ トークナイザが分割
 ["生成", "AI", "は", "便利", "です"]
   ↓ 各トークンをID（整数）へ
 [46132, 4210, 385, 29011, 774]
   ↓ IDをベクトル（数百〜数千次元の数値列）へ
 モデル内部の計算へ
```

## 3. コンテキストウィンドウ：一度に見渡せる範囲

**コンテキストウィンドウ**＝モデルが1回のやり取りで参照できるトークンの上限。
入力（指示＋資料＋過去の会話）と出力を合わせてこの枠に収まらなければならない。

- 2023年頃は数千〜数万トークンが一般的だったが、2020年代半ばには**数十万トークン級**が実用になった
- 長くできる＝賢くなる、ではない。**枠の真ん中の情報を取りこぼす**傾向（lost in the middle）が知られる
- 長い入力はそのまま**コストと待ち時間**に跳ね返る。入力トークンが2倍なら課金も概ね2倍

> よくある誤解：「コンテキストが長いモデルを使えば社内文書を全部読ませられる」。
> 実際には、毎回すべてを入れるとコストが爆発するうえ精度も落ちる。
> だから「必要な部分だけ渡す」仕組み＝RAGが要る。

## 4. 学習（Training）と推論（Inference）の違い

生成AIのコストと産業構造は、この2つの区別なしには理解できない。

|                | 学習（Training）                                     | 推論（Inference）                  |
| -------------- | ---------------------------------------------------- | ---------------------------------- |
| やること       | 大量データからモデルの重み（パラメータ）を決める     | 完成したモデルに質問して答えを出す |
| 頻度           | モデルごとに1回（＋追加学習）                        | **利用のたび毎回**                 |
| コストの性格   | **先払いの固定費**。数十億〜数千億円規模と推計される | **使うほど増える変動費**           |
| 必要な計算資源 | 数千〜数万チップを数週間〜数ヶ月連続稼働             | 1リクエストは小さいが、件数が莫大  |
| 効くチップ性能 | 演算性能、チップ間通信、メモリ容量                   | **メモリ帯域**、電力効率、単価     |

```
【学習】 データ収集 → 事前学習 → 事後学習（指示調整・人間のフィードバック） → 評価 → 公開
         └──── ここまでが「先払いの固定費」。数ヶ月かかる ────┘

【推論】 ユーザーの入力 → トークン化 → 順伝播計算 → 1トークン出力 → …繰り返し… → 応答
         └──── 1回ごとに電気とGPU時間を消費する「変動費」 ────┘
```

**産業としての含意**：
モデル事業者は学習費を先に払い、推論の積み上げで回収する。だから
「学習で勝つ（＝賢いモデルを出す）」ことと「推論で儲ける（＝安く大量にさばく）」ことは別の競争になる。
→ [ビジネスモデルと経済性](03_ビジネスモデルと経済性.md)

## 5. 学習の中身：事前学習と事後学習

### 事前学習（Pre-training）

- インターネット規模のテキスト等を使い、ひたすら「次のトークン当て」を解かせる
- ここで文法・常識・世界知識が重みに焼き込まれる
- 規模（データ量・パラメータ数・計算量）を増やすと性能が伸びる傾向が観測されており、**スケーリング則**と呼ばれる
- **カットオフ（knowledge cutoff）**：学習データが何年何月までかで、それ以降の出来事は知らない

### 事後学習（Post-training）

| 手法                                         | やること                                         | 目的                           |
| -------------------------------------------- | ------------------------------------------------ | ------------------------------ |
| 指示チューニング（SFT）                      | 「指示と模範解答」のペアで追加学習               | 質問に答える形式を覚えさせる   |
| 人間のフィードバックによる強化学習（RLHF等） | 人が良し悪しを付け、好まれる応答を強化           | 有用性・安全性・口調を整える   |
| 推論強化（reasoning）                        | 途中の思考過程を長く生成させて正答率を上げる学習 | 数学・コーディング等の難問対応 |

**推論（reasoning）モデル**は、答える前に内部で長く「考える」ぶん出力トークンが増え、
**同じ質問でも料金と待ち時間が数倍になる**。賢さとコストが直結する分かりやすい例。

## 6. モデルを業務に合わせる4つの手段

「自社の情報を使わせたい」ときの選択肢は、軽い順に4つ。ここを混同した議論が非常に多い。

| 手段                     | 何をするか                                                     | コスト                       | 向いている用途                                |
| ------------------------ | -------------------------------------------------------------- | ---------------------------- | --------------------------------------------- |
| **プロンプト設計**       | 指示文の書き方を工夫する。例を数個入れる                       | ほぼゼロ                     | まず最初に試すべき。多くはこれで足りる        |
| **RAG（検索拡張生成）**  | 質問に関係する社内文書を検索し、入力に貼り付けてから答えさせる | 中。検索基盤の構築が要る     | **社内文書Q&A、最新情報、出典を示したい場合** |
| **ファインチューニング** | 自社データで重みを追加学習し、専用モデルを作る                 | 高。データ整備と再学習が要る | 口調・出力形式の固定、特殊な専門表現          |
| **事前学習から自作**     | ゼロからモデルを作る                                           | 極めて高い                   | 国家・大企業のソブリンAI等、限られた場合      |

> よくある誤解：「社内データを覚えさせたいからファインチューニング」。
> **知識を足す目的にはRAGのほうが適している**ことが多い。
> ファインチューニングは「振る舞いの型」を教えるのが得意で、事実を正確に覚えさせるのは不得手。
> 情報が更新されたときも、RAGなら文書を差し替えるだけで済む。

### RAGの流れ

```
① 事前準備（バッチ）
   社内文書 → 細かく分割（チャンク化） → ベクトル（数値列）に変換 → ベクトルDBに保存

② 質問が来たとき（リアルタイム）
   質問 →ベクトル化→ 似た文書を検索（上位5件など）
                          ↓
          「以下の資料を参考に答えてください：＜資料＞ 質問：＜質問＞」
                          ↓
                       LLM が回答（＋出典を提示できる）
```

RAGの利点は3つ：**①最新情報を使える ②出典を示せる ③学習し直さなくていい**。
弱点は、検索がうまくいかないと答えも外すこと（＝精度の大半は検索側の作り込みで決まる）。

## 7. マルチモーダルとエージェント

- **マルチモーダル**：テキストだけでなく画像・音声・動画を同じモデルで扱う。
  画像も「トークンの列」に変換して同じ仕組みに流すのが基本的な考え方
- **ツール利用（function calling）**：モデルに外部の関数やAPIを呼ばせる仕組み。
  計算・検索・社内システム操作など、言語モデルが不得意な処理を外に出せる
- **エージェント**：ツール利用を何回も自律的に繰り返し、目標達成まで自分で手を動かす形態。
  1タスクで数十〜数百回モデルを呼ぶため、**トークン消費が桁違いに増える**
  → 詳細は [企業導入・AIエージェントと規制](04_企業導入とAIエージェント・規制.md)

## 8. なぜ計算資源がここまで要るのか

ハードウェアとつながる部分を最後に押さえておく。

- モデルの実体は**巨大な行列**。推論のたびに重み全体をメモリから読み出して掛け算する
- つまり推論は**演算量よりメモリ帯域で詰まる**（メモリの壁）。ここがHBMが要る理由
- パラメータが多いほど、GPUの搭載メモリに載せるだけで複数枚が必要になる
- 対策として、**量子化**（重みを低精度の数値に丸めてメモリを減らす）や
  **MoE**（Mixture of Experts＝毎回モデル全体ではなく一部の専門家だけ動かす構造）が広く使われる

→ ハード側の詳細は [AI半導体とHBM](../02_半導体・先端半導体/02_AI半導体とHBM.md)、
[半導体｜後工程](../../03_電機・電子部品/02_半導体（ロジック・メモリ）/03_後工程.md)

## 用語メモ

- **LLM**：大規模言語モデル。大量のテキストで学習した「次の語を予測する」巨大モデル
- **トークン**：モデルが扱う文字の最小単位。課金・上限の単位でもある
- **コンテキストウィンドウ**：1回のやり取りで参照できるトークン数の上限
- **パラメータ（重み）**：モデル内部の数値。これが「学習した結果」そのもの
- **ハルシネーション**：事実でないことをもっともらしく生成する現象。仕組み上ゼロにはできない
- **RAG**：検索拡張生成。関連文書を検索して入力に添え、それを根拠に答えさせる方式
- **ファインチューニング**：既存モデルに追加学習をして振る舞いを変えること
- **スケーリング則**：データ・パラメータ・計算量を増やすほど性能が伸びるという経験則
- **量子化**：重みを低精度の数値に置き換え、メモリと計算量を削る技術
- **MoE**：モデルを複数の「専門家」に分け、入力ごとに一部だけ動かす構造。総パラメータは巨大でも計算は軽い
- **知識カットオフ**：学習データの収録時点。それ以降の出来事をモデル自身は知らない
