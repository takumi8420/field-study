# 規制と制度（個人情報保護法・能動的サイバー防御・経済安全保障・NIS2・SEC）

**このノートで分かること**：セキュリティ投資を動かしている**法律側の力**が何で、
2025〜2026年に日本と海外で何が変わったのか。そして、日本企業がなぜ
「自分は規制対象でない」と思っていても、EUや米国のルールに巻き込まれるのか。

> 制度は「守らないと罰される」から効くのではなく、
> **報告義務と開示義務が経営の時計を動かすから**効く。この視点で読むと整理しやすい。

## 1. 結論：規制の効き方は3種類しかない

| 効き方 | 何を強制するか | 代表例 | 経営への効き目 |
| --- | --- | --- | --- |
| **① 報告・通知の義務** | 事故が起きたら、期限内に当局と本人に知らせろ | 個人情報保護法、NIS2、CRA、SEC規則 | **期限が経営の意思決定速度を規定する**。最も実効性が高い |
| **② 水準の義務** | このレベルの対策を実装しろ | 重要インフラ向け規制、CRA、NIS2の管理措置 | 予算が付く根拠になる |
| **③ 制裁・課徴金** | 違反したら金を取る | GDPR、改正個人情報保護法（2026年） | 説明のインパクトは大きいが、発動は限定的 |

日本はこれまで①が中心で、③は弱かった。**2026年にその③が入った**のが最大の変化である。

## 2. 日本：改正個人情報保護法（2026年成立）

個人情報保護法は3年ごとの見直しが法律に組み込まれており、その2巡目の改正が2026年に動いた。

| 時点 | 出来事 |
| --- | --- |
| 2026年5月26日 | 改正案が衆議院本会議を通過（報道） |
| 2026年7月10日 | 参議院で可決・成立 |
| 2026年7月17日 | 公布 |

改正の性格は「**厳しくする部分と、緩める部分が同居している**」ことにある。

| 方向 | 内容 | 狙い |
| --- | --- | --- |
| 強化 | **課徴金制度の導入**。違法な取得・不適正利用を繰り返す事業者から、得た利益相当額を国庫に納付させる | これまでは勧告・命令を受けても**違反で得た利益を手元に残せた**。その穴を塞ぐ |
| 緩和 | 漏えい時の**本人通知・委員会報告の合理化**。権利利益を害するおそれが小さい場合は本人通知を不要に | 軽微な事案まで一律に通知していた負担を下げ、**重大事案に資源を集中させる** |

> ポイント：「緩和」の部分を「規制が甘くなった」と読むのは誤り。
> **重大な事案の報告義務は残り、悪質な事案には金銭的制裁が付いた**。
> 実務上は「何が軽微で何が重大か」の線引き作業が新たに発生する。

なお、施行時期や政令・ガイドラインの詳細は順次固まる段階にあるため、
**最新は個人情報保護委員会の公表資料で確認する**こと。

## 3. 日本：能動的サイバー防御（サイバー対処能力強化法）

正式には「重要電子計算機に対する不正な行為による被害の防止に関する法律」。
2025年5月16日に成立し、**2026年10月1日施行**が確認されている。
「**能動的サイバー防御（Active Cyber Defense, ACD）**」という通称で呼ばれる。

「能動的」という言葉から「政府が反撃する」と理解されがちだが、
実際の制度の中身は**4本柱**で、反撃はその一部にすぎない。

```
 ① 官民の情報共有         ② 通信情報の利用          ③ アクセス・無害化       ④ 体制整備
 ─────────────────    ─────────────────    ─────────────────   ─────────────────
 重要インフラ事業者は      政府が一定の条件下で       攻撃に使われている       内閣にサイバー
 攻撃を国に報告する        通信情報を分析できる       サーバー等へ            安全保障の司令塔
 国は脅威情報を還元する    ようにする                 措置を講じる             を置く
 ─────────────────    ─────────────────    ─────────────────   ─────────────────
   企業に直接効く          憲法21条（通信の秘密）      いわゆる「能動的」       警察・自衛隊の
   ＝報告義務              との関係が最大の論点        の部分                   役割分担
```

企業目線で重要なのは**①**である。基幹インフラ事業者には**報告義務**が生じ、
その取引先にも契約・運用面の対応が波及する（発注元が要求として下ろすため）。

| 立場 | 生じること |
| --- | --- |
| 基幹インフラ事業者（電力、ガス、水道、通信、鉄道、航空、金融、医療 ほか） | 攻撃検知時の国への報告。体制の整備 |
| そのシステムを納めるITベンダー | 顧客の報告義務を満たせる契約・ログ・連絡体制の提供 |
| 一般企業 | 直接の義務は限定的。ただし**取引先要求として降りてくる** |
| 電気通信事業者 | 通信情報の取扱いに関する協力の枠組み |

> ポイント：この法律の企業への実効的なインパクトは、罰則ではなく
> **「いつ・誰に・何を報告するか」を平時に決めさせる**ところにある。
> 報告のフォーマットが決まると、**ログを取っていない組織は報告できない**ことが露呈する。

## 4. 日本：経済安全保障の文脈

セキュリティは、産業政策・外交政策と地続きになった。

| 制度・方針 | 内容 | セキュリティとの接点 |
| --- | --- | --- |
| **経済安全保障推進法**（2022年成立） | 基幹インフラの設備導入の事前審査、重要物資の供給確保、特許非公開 ほか | インフラ事業者が**どこの機器を使うか**が審査対象になる |
| セキュリティ・クリアランス制度（2024年法整備） | 政府の重要情報を扱う人の適格性評価 | 防衛・先端技術分野の民間企業が対象に入る |
| 防衛産業サイバーセキュリティ基準 | 防衛装備庁の調達で求められる水準（米NIST SP 800-171を参照） | 防衛関連の取引に入るための**事実上の入場券** |
| 政府調達の基準（政府機関等の対策基準群） | 政府システムに求められる水準 | 受注する事業者に波及 |

> 経済安全保障の文脈では、「攻撃されないこと」より
> **「重要な技術・情報が国外に流出しないこと」**が主眼になる。
> 対策の重心が、ランサムウェア対策（可用性）から、情報の持ち出し対策（機密性）へ動く。
> 関連：[半導体・先端半導体](../02_半導体・先端半導体/README.md)、[航空機・防衛](../../02_自動車・機械/13_航空機・防衛/README.md)

## 5. EU：NIS2 と サイバーレジリエンス法（CRA）

EUの2本立てを「**組織を規制するNIS2**」「**製品を規制するCRA**」と覚えると整理できる。

| | NIS2指令 | サイバーレジリエンス法（CRA） |
| --- | --- | --- |
| 規制対象 | **組織**（重要・重要度の高いサービスの提供者） | **製品**（デジタル要素を持つ製品の製造者・輸入者・販売者） |
| 主な義務 | リスク管理措置、インシデント報告、**経営陣の責任** | セキュア・バイ・デザイン、SBOM（機械可読）、脆弱性の調整開示、サポート期間中の更新提供 |
| 報告の期限 | 重大インシデントの早期警告は原則24時間以内 | **実際に悪用されている脆弱性は24時間以内**に報告（2026年9月11日から適用） |
| 時期 | 2023年発効、各国法への転換が進行中。2026年1月にEU委が**明確化のための改正提案**を公表 | 2024年12月10日発効。主要要件の適用は**2027年12月11日**から |
| 日本企業への影響 | 欧州子会社・欧州でサービスを出す場合に直接適用。それ以外も**顧客からの要求として波及** | **EUで製品を売るなら直接対象**。ソフトを積んだハードも含む |

CRAが日本の製造業にとって重い理由は、対象が「ソフトウェア企業」に限られないためである。
**ネットにつながる家電・産業機器・車載機器**は広く対象になり、
「作って売って終わり」から「**売った後も期間中は更新を出し続ける**」へ、
製品ライフサイクルの前提が変わる。

> ポイント：CRAは規制であると同時に**コスト構造の変更**である。
> 出荷後の保守が義務になるので、**製品原価に将来の更新費用を織り込む**必要が出る。
> 関連：[ロボット](../09_ロボット/README.md)、[EV・電動化](../03_EV・電動化/README.md)

## 6. 米国：SEC開示規則と、政府調達を通じた波及

米国は罰則より**開示**と**調達**で効かせるのが特徴。

| 制度 | 内容 | 効き方 |
| --- | --- | --- |
| **SECサイバーセキュリティ開示規則**（2023年施行） | 上場企業は「重要」と判断したインシデントを**判断から4営業日以内**にForm 8-Kで開示。年次報告ではリスク管理体制も開示 | 開示が株価に直結するため、**取締役会の議題に強制的に上がる** |
| CMMC（防衛産業向け） | 国防総省のサプライチェーンに対する成熟度認証 | 認証がないと**受注できない**。日本の防衛関連サプライヤーにも波及 |
| 大統領令・CISAの指令 | 政府機関へのKEV対応期限の設定など | 政府が期限を切ることで、事実上の民間の基準になる |
| 州法（カリフォルニア等） | 個人情報の保護・通知 | 州ごとに異なり、対応コストが積み上がる |

SEC規則の実務的な難しさは「**重要性（materiality）の判断**」にある。
「重要と判断してから4営業日」なので、**いつ重要と判断したかの記録**が問われる。
判断を先送りしたように見えると、それ自体が問題になる。

## 7. 全体図：規制はどこから降りてくるか

日本企業が直面する要求は、必ずしも日本の法律から来るとは限らない。

```
  【日本の法律】          【海外の法律】            【取引先からの要求】
  改正個情法(2026)        EU: NIS2 / CRA / GDPR     チェックシート
  サイバー対処能力強化法    米: SEC規則 / CMMC        契約条項（報告義務・監査権）
  経済安全保障推進法       各国のデータ規制           ISMS・SOC2の提示要求
       │                       │                          │
       └───────────┬───────────┴──────────┬───────────────┘
                     ▼                          ▼
              直接適用される               ★ 実際に多くの日本企業が
              （対象企業のみ）                 最初に殴られるのはここ
                     │                          │
                     └──────────┬───────────────┘
                                ▼
                      社内の予算・体制・ログ設計へ
```

> ポイント：**規制対象でない企業ほど、取引先経由で実質的に規制される**。
> 法律を読んで「自社は対象外」と判断しても、顧客の要求は避けられない。
> この経路は [03_サプライチェーンと組織の実務](03_サプライチェーンと組織の実務.md) で扱った話と表裏一体。

## 8. 制度が追いついていない論点

| 論点 | 状況 |
| --- | --- |
| **AIの安全性とセキュリティの線引き** | AI規制（EU AI法など）とセキュリティ規制が別体系で走っており、AIエージェントの権限管理は**どちらの担当かが曖昧** |
| 身代金支払いの是非 | 支払い禁止の法制化を議論する国はあるが、主要国で全面禁止は実現していない。**制裁法制での間接規制**にとどまる |
| 通信の秘密との緊張 | 日本の能動的サイバー防御における通信情報の利用は、憲法21条との関係で運用の具体が注視されている |
| 越境データと捜査 | 攻撃者も証拠も国外にある。国際的な司法協力が追いつかない |
| 中小企業の実装能力 | 規制は増えるが、実装する人がいない。**制度と現場の乖離**が最大の実務課題 |

## 用語メモ

- **個人情報保護法**：日本の個人データ保護の基本法。3年ごと見直しが組み込まれている
- **課徴金**：違反で得た利益相当額を国庫に納めさせる金銭的制裁。2026年改正で導入
- **個人情報保護委員会（PPC）**：個人情報保護法を所管する独立性の高い行政委員会
- **サイバー対処能力強化法／能動的サイバー防御（ACD）**：2025年5月成立、2026年10月1日施行。官民連携・通信情報利用・無害化措置・体制整備の4本柱
- **経済安全保障推進法**：基幹インフラの設備審査、重要物資の確保、特許非公開などを定める（2022年）
- **セキュリティ・クリアランス**：重要情報を扱う人の適格性評価制度
- **NIS2**：EUの「組織」向けサイバーセキュリティ指令。経営陣の責任とインシデント報告が柱
- **CRA（サイバーレジリエンス法）**：EUの「製品」向け規則。SBOMと出荷後の更新提供を義務化
- **GDPR**：EUの個人データ保護規則。高額な制裁金で知られる
- **SEC開示規則**：米上場企業に重大インシデントの4営業日以内の開示を求める規則（2023年）
- **CMMC**：米国防総省のサプライチェーン向けサイバーセキュリティ成熟度認証
- **NIST SP 800-171**：非機密だが管理すべき情報を守るための米国基準。日本の防衛調達も参照
- **CISA**：米国のサイバーセキュリティ・インフラセキュリティ庁。KEVリストの公表元
- **NISC**：内閣サイバーセキュリティセンター。日本の司令塔機能を担う
