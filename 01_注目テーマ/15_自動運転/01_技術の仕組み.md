# 自動運転｜技術の仕組み（認識・予測・計画・制御）

**このノートで分かること**：自動運転車が「何を見て、どう考えて、どうハンドルを切っているか」の中身。
そして**なぜ「9割できた」ところから10年進まないのか**という、この産業最大の謎の正体。

結論を先に言うと、自動運転は**確率の商売**である。
「だいたい走れる」システムは2010年代半ばにできあがった。そこから先は、
**1万kmに1回しか起きない事態を、1万回ぶんのデータで潰す**という気の遠くなる作業であり、
技術論争（LiDARを積むか積まないか、地図を作るか作らないか）はすべて
**「その潰し込みを、どれだけ安く・速くやれるか」という一点**に還元できる。

## 1. 4段構えのパイプライン

自動運転ソフトは伝統的に4つのブロックに分かれる。まずこの並びを覚える。

```
 【センサ】      【1. 認識】       【2. 予測】        【3. 計画】        【4. 制御】
 カメラ      ─┐  周りに何がある   その物体は次の    自車はこの先      その軌跡を
 LiDAR       ─┼▶ か（物体・車線  数秒でどこへ    ▶ 数秒でどこを   ▶ 出すための
 レーダー     ─┤  ・信号・標識）   動くか            通るか            ハンドル角・
 GNSS/IMU    ─┘  ＋自車はどこに                     （軌跡の生成）     アクセル・
 （＋高精度地図）  いるか（測位）                                        ブレーキ
                    Perception      Prediction        Planning          Control
                    「見る」        「読む」          「決める」        「動かす」
```

| ブロック               | やること                                                                                                       | 難しさの正体                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **認識**（Perception） | センサの生データから「車が3台、歩行者2人、赤信号」という世界のモデルを作る。同時に**自車の位置**をcm級で求める | 珍しい見た目のものが出ると落ちる（横転したトラック、着ぐるみ、荷台の自転車）         |
| **予測**（Prediction） | 検出した他者が次の3〜8秒でどう動くかを確率つきで出す                                                           | **人間の意図が読めない**。横断歩道前で足を止めた歩行者は渡るのか渡らないのか         |
| **計画**（Planning）   | 自車の走る軌跡を決める。安全・法令・乗り心地・他車との駆け引きを同時に満たす                                   | **譲り合いが数式にならない**。強引すぎると危険、慎重すぎると永久に交差点を出られない |
| **制御**（Control）    | 軌跡どおりに動くよう操舵・駆動・制動を出す                                                                     | ここは制御工学として枯れており、**4段の中では一番易しい**                            |

> ポイント：世間が「自動運転が難しい」と言うとき、その実体はほぼ**予測と計画**にある。
> 「見えているのに、どう振る舞えばいいか分からない」場面が最後まで残る。

## 2. センサ構成の論争：カメラ vs LiDAR vs レーダー

自動運転の技術論争でいちばん有名なのがここ。3種類のセンサは**測っている物理量が違う**。

| センサ                | 測っているもの                                         | 得意                                                                | 苦手                                                                     | 価格帯（2026年）                                                                                       |
| --------------------- | ------------------------------------------------------ | ------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **カメラ**（可視光）  | 明るさと色。距離は「見え方から推定」する               | 色・文字・信号・標識。人間と同じ情報が取れる。**圧倒的に安い**      | 逆光・夜間・濃霧。距離は原理的に推定値                                   | 数千円〜1万円台／個                                                                                    |
| **LiDAR**（ライダー） | レーザーを飛ばして**往復時間から距離を直接測る**       | 暗闇でも形と距離が正確（cm級）。3次元の点の集まり（点群）が得られる | 雨・雪・濃霧で乱反射。色や文字は読めない。**高い**                       | 中国Hesaiの新型ADAS向け「ATX」で約200ドル（約3万円）と報じられる。ロボタクシー用の高性能品は数十万円〜 |
| **ミリ波レーダー**    | 電波の反射。**相手の速度がドップラー効果で直接取れる** | 悪天候に強い。遠距離の車の速度が正確。安い                          | 分解能が粗く「何か」は分かっても「何か」が分からない。金属に反応しやすい | 数千円〜／個                                                                                           |

### 2つの流派

```
【センサフュージョン派】                    【カメラのみ（ビジョン）派】
 Waymo / 中国勢 / 多くの自動車メーカー        Tesla

 カメラ + LiDAR + レーダー を重ねる            カメラだけ（レーダーも外した）
   ↓                                            ↓
 1つが騙されても他が気づく（冗長性）           人間は目だけで運転できる、が論拠
 距離は「測った値」なので検証しやすい           センサ代が2桁安く、量産車に全数載る
   ↓                                            ↓
 認証・保険・当局説明がしやすい                 全車から走行データが集まる
   ↓                                            ↓
 【弱み】車両1台が高い。量産車に載せにくい      【弱み】距離が推定値なので
        → ロボタクシー（台数が少ない）向き            誤検知の説明が難しい
                                                → 量産車のADAS向き
```

この対立は**思想の違いに見えて、実はビジネスモデルの違い**である。

- **自社で車を保有して運行する**（ロボタクシー）なら、1台500万円高くても、**年中無休で稼働させれば回収できる**。安全側に振って当局を説得するほうが重要。
- **1台売り切りの乗用車に載せる**なら、部品代1万円の差が数百万台ぶん効く。載せられないセンサは存在しないのと同じ。

近年は**LiDARの値崩れで境界が動いている**。中国Hesaiの2026年上半期のLiDAR出荷は約110万台（前年同期比＋100.8%）と発表されており、
うちADAS（運転支援）向けが約84万台。**量産車にLiDARが載る時代がすでに中国では来ている**。

## 3. 高精度地図（HDマップ）を使うか使わないか

**高精度地図**とは、車線の中心線・停止線・信号機や標識の3次元位置を**cm級**で持つ地図。
普通のカーナビの地図（道路を線で持つ）とは別物で、**車が「自分がどの車線のどこにいるか」を知るための座標系**である。

```
【地図あり方式】Waymo・中国勢・日本のレベル4バス
  事前に専用車で走って地図を作る ──▶ 走行時はLiDARの点群を地図と照合して自車位置を確定
                                      「見えなくても、そこに停止線があると知っている」
  ✔ 安全マージンが取りやすい／当局に説明しやすい
  ✘ 工事・線の引き直しで地図が古くなる ＝ 維持費が街ごとにかかる
  ✘ 地図のない街へは行けない ＝ 展開が「都市単位」になる

【地図なし方式】Tesla など
  その場で見た車線をその場で解釈する
  ✔ どこでも走れる（ように見える）／維持費ゼロ
  ✘ 標示が消えた道・雪道で一気に不利／「知っていること」が使えない
```

> ここが**展開速度の差**として表に出る。Waymoが新都市に入るのに時間がかかるのは、
> 地図作成と現地検証、そして当局・消防・警察との調整を都市ごとにやり直すからである。
> 逆にTeslaはソフト更新で全米の車に同じ機能を配れる。**「深さ」と「広さ」のトレードオフ**。

## 4. End-to-End（一気通貫）学習への転換

2023年ごろから業界の作り方が大きく変わった。

| 世代                               | 作り方                                                                                                | 長所                                                                                             | 短所                                                                                           |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| **モジュール型**（〜2022年が主流） | 認識・予測・計画を別々のプログラムとして作り、人が書いたルールでつなぐ                                | どこが悪いか分かる。責任分界が明確。認証しやすい                                                 | ルールが増えすぎて破綻する。「雨の日、路駐の陰から自転車」のような場面ごとに人が書く必要がある |
| **End-to-End**（2023年〜）         | センサ入力から操作出力までを**1つの巨大なニューラルネットで学習**する。人間の運転データを大量に見せる | 人が書ききれない微妙な振る舞い（譲り合い、割り込みの間合い）が自然に出る。データを足せば良くなる | **なぜそう動いたか説明できない**。少し直したいときに「どこを直すか」が分からない               |

現実には**完全なEnd-to-Endは使われていない**。多くの実装は
「学習ベースの大きな塊」＋「その出力を検査して危険なら止める、人が書いた安全層（セーフティモニタ）」の**二階建て**になっている。
説明責任が求められる産業では、**学習モデルの出力を最後に人間のルールが監視する構造**から当分逃れられない。

```
  センサ入力 ──▶ 大きな学習モデル ──▶ 走行軌跡の候補
                （人間の運転を模倣）        │
                                            ▼
                                  【安全層（ルールベース）】
                                   衝突判定・速度上限・
                                   ODD逸脱チェック
                                            │
                                   OK ──────┴────── NG
                                    ▼                ▼
                                  実行             減速停止／
                                                   遠隔支援を呼ぶ
```

## 5. ロングテール問題：なぜ最後の1%に10年かかるのか

自動運転で最も重要な概念。**走行場面の出現頻度は極端に偏っている**。

```
出現
頻度
 ▲
 │█
 │█
 │█▄
 │█ ▀▄▄
 │█     ▀▀▀▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄
 └──────────────────────────────────────────────────▶ 場面の種類
   ↑                    ↑                    ↑
 直進・車線維持       交差点・合流          横転トラック／誘導員の手信号／
 （9割）              （1割弱）              道路に落ちたソファ／逆走車
                                            （ここが「ロングテール」）
   数か月で作れる      数年かかる            ここが終わらない
```

- 「テール（尾）」は**1事象あたりの発生率は低いが、種類が無数にある**。合計すると無視できない頻度になる
- しかも**テールの事象ほど危険度が高い**（珍しい＝人間も慌てる状況）
- 学習で潰すには**その場面のデータが要る**が、珍しいから集まらない。→ **シミュレーションと合成データ**で水増しする
- 進捗は「**介入（ディスエンゲージメント）までの平均走行距離（MPI）**」で測るが、
  MPIが10倍になっても、**残った事象の危険度はむしろ上がる**（簡単なものから先に潰れるため）

> この構造のせいで、**デモ（決められたコースを1回走る）と商用運行（不特定の客を毎日運ぶ）の間には桁違いの壁がある**。
> 「自動運転車が走った」というニュースを読むときは、**何台が・どの範囲で・何日間・監視者ありかなしで**走ったかを必ず確認する。
> ここを区別しないと業界の話は一切読めない。詳しくは [02_レベルとODDの実際](02_レベルとODDの実際.md) へ。

参考として、Waymoは**2026年3月までに運転者なし（rider-only）で累計約2億2,060万マイル**を走行したと公表している（同社発表）。
「毎週約200万マイル」というペース（2026年初時点）で、ようやくテールを統計的に語れる規模に到達しつつある段階。

## 6. 計算機と車載ハードウェア

学習モデルを車の中で毎秒何十回も動かす必要があるため、**車載コンピュータそのものが競争軸**になっている。

| 項目       | 実情（2026年時点）                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------- |
| 演算チップ | NVIDIA の車載SoC（Orin → Thor世代）が事実上の標準。Teslaは自社設計チップ、中国勢は地場SoCも採用 |
| 消費電力   | 高性能構成で数百W。**EVでは航続距離を削る**ため、電費と冷却が設計制約になる                     |
| 冗長化     | レベル4では操舵・制動・電源・演算を**二重化**する。ここが車両価格を押し上げる最大要因のひとつ   |
| データ量   | ロボタクシー1台が1日にテラバイト級のログを出す。**通信と保管のコストが運行費に乗る**            |

演算チップ側の事情は [半導体（ロジック・メモリ）](../../03_電機・電子部品/02_半導体（ロジック・メモリ）/README.md) と
[AI半導体を含む注目テーマ](../02_半導体・先端半導体/README.md) に、
学習モデルの一般論は [生成AI](../01_生成AI/README.md) に詳しい。

## 7. 「自動運転」と紛らわしい技術との境界

| 技術                            | 中身                                           | 自動運転との関係                                                               |
| ------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------ |
| **ACC**（車間距離制御）         | 前走車に追従して速度を保つ                     | レベル1。前後方向だけの支援                                                    |
| **LKA / LKAS**（車線維持支援）  | 車線の中央を保つようハンドルを補助             | レベル1。左右方向だけの支援                                                    |
| **AEB**（衝突被害軽減ブレーキ） | ぶつかりそうなら自動でブレーキ                 | **運転を代わる機能ではない**。事故を減らす安全装置。日本では新型車に義務化済み |
| **自動駐車**                    | 駐車枠に自動で入れる                           | 低速・限定空間なので難易度が別物。レベル2相当が多い                            |
| **隊列走行**                    | 先頭の有人トラックに後続が電子的に連結して追従 | 後続無人化を狙う運用。1台単独の自動運転とは別アプローチ                        |

**ADAS（先進運転支援システム）**は上記の支援機能の総称で、**運転の主体は人間のまま**。
ADASと自動運転は連続しているようで、**責任の所在が違うため制度的には断絶している**。これが次のノートの主題。

## 用語メモ

- **ADAS**：先進運転支援システム。ACC・LKA・AEBなど、人間の運転を助ける機能の総称。運転者は人間のまま
- **知覚 / 認識（Perception）**：センサ入力から周囲の物体・車線・信号を把握する処理
- **点群（Point Cloud）**：LiDARが返す、距離を持った点の集まり。3次元の形がそのまま得られる
- **センサフュージョン**：種類の違うセンサの出力を統合して、1つの世界モデルを作ること
- **HDマップ（高精度地図）**：車線・停止線・信号位置をcm級で持つ地図。自車位置の確定に使う
- **GNSS / RTK**：衛星測位と、基準局の補正で誤差をcm級に縮める方式。トンネル・ビル街では単独では足りない
- **IMU**：加速度とジャイロのセンサ。衛星が切れた区間の位置を推測航法でつなぐ
- **SLAM**：走りながら地図を作り、同時に自車位置を求める技術
- **End-to-End**：センサ入力から車両操作までを1つの学習モデルで扱う設計
- **ロングテール／コーナーケース**：めったに起きないが種類が無数にある場面。自動運転の最大の壁
- **ディスエンゲージメント（介入）**：自動運転を解除して人間が操作を取り戻すこと。安全運転者がいる試験で計測される
- **MPI（Miles Per Intervention）**：介入1回あたりの走行距離。開発の進捗指標として使われる
- **セーフティモニタ**：学習モデルの出力を検査し、危険なら止める人間が書いた安全層
- **rider-only 走行**：運転席に人がいない状態での走行。Waymoが実績として公表している単位
