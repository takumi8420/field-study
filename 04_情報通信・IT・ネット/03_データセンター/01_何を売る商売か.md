# データセンターとは何を売る商売か

このノートで分かること：データセンター事業者が**顧客に請求しているものの正体**（床面積ではなく電力）、
事業モデルの3類型、信頼性等級（ティア）と冗長構成、電力効率指標PUEの読み方。

## 1. 一言でいうと「電気と冷却と回線を、床とセットで貸す商売」

データセンター（DC）＝サーバやネットワーク機器を安全・安定に動かすための専用建物。
一般のビル賃貸と決定的に違うのは、**貸しているものが空間ではなく電力供給能力**である点にある。

```
  一般のオフィスビル              データセンター
  ─────────────              ─────────────
  売り物：床面積（坪・㎡）        売り物：電力供給能力（kW・MW）
  単価　：坪あたり月額             単価　：1kWあたり月額
  制約　：容積率・延床面積         制約　：受電容量・冷却能力
  空けば：内装を変えて次の客       空けば：電気が余る＝収益がゼロのまま固定費だけ出る
```

> ポイント：**「何㎡貸したか」ではなく「何kW契約したか」で売上が決まる**。
> これがこの業界のすべての議論（立地・冷却・投資回収）の起点になる。

## 2. なぜ「床」ではなく「電力（kW）」が売り物なのか

サーバは消費した電力とほぼ同じ量の熱を出す。1ラック（機器を収める棚。高さ約2m、幅60cm前後）に
どれだけ機器を詰められるかは、**その建物が供給できる電気と、捨てられる熱の量**で決まる。
つまり床は余っていても、電気と冷却が尽きればそれ以上は入らない。

| 世代                   | 1ラックあたりの電力 | 冷やし方             | 主な用途               |
| ---------------------- | ------------------- | -------------------- | ---------------------- |
| 従来型（2010年代）     | 3〜6kW              | 空冷（床下から冷風） | 業務システム、Web      |
| 高密度（2020年代前半） | 10〜20kW            | 空冷＋気流制御       | 仮想化基盤、ストレージ |
| AI向け（2020年代後半） | **100〜120kW級**    | 直接液冷が前提       | GPUによるAI学習・推論  |

- NVIDIAのBlackwell世代以降のGPUサーバは1ラック100〜120kW級とされ、従来の空冷では冷やしきれない
- 同じ床面積でも、**扱える電力が10倍になれば売上も10倍になりうる**。逆に旧式の建物はAI用途に使えない
- 詳しい冷却の話は [建てる・運ぶ・冷やす](02_建てる・運ぶ・冷やす.md) を参照

### 契約電力と実消費のズレ

顧客が契約するのは「使ってよい上限」であり、実際の消費とは別。
事業者は**契約ベース（コミット）で課金**するため、顧客が使い切らなくても売上は立つ。
一方で事業者側は契約した分の受電容量を電力会社に確保しておく必要があり、
**売れていない容量は「寝かせた資産」になる**。

## 3. 事業モデルの3類型

誰が建て、誰が運用し、誰が使うかの組み合わせで、経済性がまったく変わる。

| 類型                                       | 貸す単位               | 顧客                           | 契約期間     | 特徴                                             |
| ------------------------------------------ | ---------------------- | ------------------------------ | ------------ | ------------------------------------------------ |
| **リテールコロケーション**                 | ラック単位〜数十kW     | 一般事業会社、SIer、通信事業者 | 1〜3年       | 単価は高いが営業件数が多い。回線接続が価値の中心 |
| **ホールセール（ハイパースケール向け卸）** | 数MW〜数十MW、棟単位   | クラウド事業者、大手IT         | **10〜20年** | 単価は安いが1契約が巨大。不動産賃貸に近い        |
| **自社運用（ハイパースケーラー）**         | 貸さない（自社で使う） | 自分自身                       | ―            | AWS・Google・Microsoft等。設計から自前           |

```
  ┌─ 建物だけ建てて貸す（パワードシェル）───────────┐
  │   受電設備まで用意した「箱」を渡し、中身は借り手が作る  │
  ├─ ホールセール ──────────────────────────┤
  │   空調・電源まで作り込んだ区画をMW単位で長期に貸す      │
  ├─ リテールコロケーション ────────────────────┤
  │   ラック・ケージ単位で貸し、回線接続や運用も売る        │
  └─ 自社運用 ────────────────────────────┘
       ↑ 上にいくほど不動産業寄り／下にいくほどサービス業寄り
```

- **パワードシェル**＝電気を引き込んだ箱だけ供給する形態。建設だけして運用リスクを取らない
- **ビルドトゥスーツ（BTS）**＝特定顧客の仕様に合わせて専用棟を建てる。契約が先にあるので空室リスクが小さい
- クラウド事業者は自社運用と借り上げを併用する。詳しくは [クラウド・IaaS](../04_クラウド・IaaS/README.md)

## 4. 信頼性の等級（ティア）と冗長構成

「止まらないこと」を売っているので、**どこまで二重化しているか**が商品の等級になる。
米Uptime Instituteの**ティア（Tier）**分類が事実上の国際基準として使われる。

| 等級      | 冗長の考え方                                       | 止めずに保守できるか | 年間停止時間の目安（設計値） |
| --------- | -------------------------------------------------- | -------------------- | ---------------------------- |
| ティアI   | 冗長なし                                           | 不可                 | 約28.8時間                   |
| ティアII  | 一部の機器を冗長化                                 | 不可                 | 約22.0時間                   |
| ティアIII | 電源・空調の**経路まで冗長**。保守しながら運転可能 | 可能                 | 約1.6時間                    |
| ティアIV  | 系統が完全に二重。単一故障で止まらない             | 可能                 | 約0.4時間                    |

※ 停止時間は等級の設計思想を示す目安として広く引用される値。実測の保証値ではない。

日本では日本データセンター協会（JDCC）の**ファシリティスタンダード（ティア1〜4）**も使われる。
商用DCの多くは**ティアIII相当**を名乗る。ティアIVは金融の基幹系など限られた用途で、
建設費が跳ね上がるため「必要なところだけ部分的にティアIV」という作り方が一般的。

### 冗長構成の書き方（N+1、2N）

```
  N    ：必要な台数ちょうど（予備なし）
  N+1  ：必要台数＋予備1台。1台壊れても足りる      ← 空調・UPSでよくある構成
  2N   ：必要な設備を丸ごと2系統。片系統を止められる ← ティアIV相当
  2(N+1)：2系統それぞれに予備1台。最も手厚い
```

冗長度を1段上げるごとに設備費が増え、しかも**予備側の機器は普段遊んでいる**。
信頼性と投資効率は必ずトレードオフになる。

## 5. PUE ── 電力効率を測るただ一つの物差し

**PUE（Power Usage Effectiveness／電力使用効率）**＝施設全体の消費電力 ÷ IT機器の消費電力。
1.0に近いほど「余計な電気を使っていない」ことを意味する。

```
  PUE = 1.5 のDCに、IT機器が 10,000kW 入っている場合

     IT機器          10,000kW  ← 顧客が使う。これが売上の源
     冷却・電源損失   5,000kW  ← 事業者が負担する。売上にならない
     ────────────────────
     施設全体        15,000kW  ← 電力会社に払う分
```

| PUEの水準 | 実態                                       |
| --------- | ------------------------------------------ |
| 2.0前後   | 旧式のサーバルーム、自社ビル内の機械室     |
| 1.5前後   | 2010年代の一般的な商用DC                   |
| 1.3前後   | 近年の新設大規模DC。日本の新設基準の水準   |
| 1.1台     | 外気冷却や液冷を活用した寒冷地・最新鋭施設 |

- 日本では省エネ法（省エネ・非化石転換法）でDC業がベンチマーク制度の対象になり、
  **2030年度に平均PUE1.4以下**、**2029年以降に新設する施設はPUE1.3以下**という基準が置かれた
  （資源エネルギー庁、2026年4月ガイドライン）
- 2026年度提出分から、電力消費量とPUEの報告・自社サイトでの公表が求められる
- PUEは**気候に強く左右される**（寒い土地ほど有利）ため、単純な社間比較には注意が必要
- 水の効率を測る **WUE（Water Usage Effectiveness）** も併記されるようになってきた

## 6. もう一つの売り物：つながりやすさ（接続性）

特にリテールコロケーションでは、**「どの回線とつながっているか」が価格を決める**。

```
    顧客A ─┐
    顧客B ─┼─▶ 館内クロスコネクト ─▶ IX（相互接続点）─▶ 世界へ
    顧客C ─┘        ↑
              事業者はここで
              1本あたり月額を取る
```

- **キャリアニュートラル**＝特定の通信会社に縛られず、複数キャリアを引き込める中立的なDC
- **クロスコネクト**＝同じ建物内の顧客同士を物理的な線で直結するサービス。1本ごとに課金
- 回線がたくさん集まるDCほど「ここにいないと不便」になり、**居抜きで移転しにくくなる**（解約率が下がる）
- この構造が、コロケーション事業者の価格決定力の源になっている
  → 経済性の議論は [事業としての経済性](03_事業としての経済性.md)

## 7. 価格はどう決まるか

| 契約形態               | 課金の単位            | 価格の目安                                                 |
| ---------------------- | --------------------- | ---------------------------------------------------------- |
| ラック貸し（リテール） | 1ラック月額＋電力従量 | 国内で月額十数万円〜が一案内例（事業者公開価格）           |
| kW課金（ホールセール） | 1kWあたり月額         | 東京は月280ドル前後（2026年第1四半期、CBRE、250〜500kW帯） |
| クロスコネクト         | 1本あたり月額         | 数千円〜数万円                                             |
| リモートハンド         | 作業時間単位          | 現地作業の代行。人手商売                                   |

参考までに同時点のCBRE集計では、シンガポール330〜475ドル、香港295ドル、
北バージニア190〜235ドル、シドニー188ドル（いずれも1kWあたり月額）。
**東京はアジアでは中位、世界的には高め**という位置づけになる。

> 価格が地域で数倍違うのは、**電気の値段の差ではなく、建てられる量の差**。
> 建設規制と電力系統がきついほど供給が絞られ、単価が上がる。

## 用語メモ

- **ラック**：サーバを収める標準の棚。高さは42U（1U＝4.45cm）が一般的
- **ホワイトスペース**：実際に機器を設置できる部屋の面積。設備室や通路は含まない
- **受電容量**：その建物が電力会社から受け取れる電力の上限。DCの実質的な「容積」
- **コロケーション**：他社の機器を預かって設置場所・電源・回線を貸すサービス
- **ハイパースケール**：クラウド大手が運営・利用する超大規模DC（数十MW〜）
- **ティア（Tier）**：設備の冗長度による信頼性等級。Uptime Institute の分類が国際標準
- **N+1 / 2N**：冗長構成の表記。必要台数に対してどれだけ予備を持つか
- **PUE**：施設全体の消費電力 ÷ IT機器の消費電力。1.0に近いほど効率が良い
- **WUE**：IT機器1kWhあたりの冷却水使用量。水の効率指標
- **クロスコネクト**：館内で顧客同士を直結する物理配線サービス
- **キャリアニュートラル**：特定通信事業者に依存しない中立的なDC
- **パワードシェル**：受電設備付きの「箱」だけを貸す形態
- **BTS（ビルドトゥスーツ）**：特定顧客専用に仕様を合わせて建てる方式
