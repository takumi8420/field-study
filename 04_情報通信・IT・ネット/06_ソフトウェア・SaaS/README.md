# ソフトウェア・SaaS

- 大分類: 情報通信・IT・ネット
- 状態: done
- 更新日: 2026-09-20

企業の業務そのものをソフトに置き換えて売る産業。
**売っているのはソフトではなく「使い続けてもらう権利」**であり、売り切りと違って
売った瞬間ではなく**解約されずに使われ続けるか**で損益が決まる。
設備を持たない高粗利モデルだったが、2026年はAI推論コストの流入と
シート課金の揺らぎによって、その前提が点検されている局面にある。

## 1. 業界の定義・範囲

**SaaS（Software as a Service）**＝ソフトを買い取らせず、ネット越しに月額・年額で使わせる提供形態、
およびそれを提供する事業。ここでは「企業向け業務ソフト」を主対象とし、
消費者向けアプリやゲームは別フォルダに譲る。

| 区別すべき言葉 | 中身 |
| --- | --- |
| **SaaS** | ソフト（アプリ）をサービスとして提供する。**このフォルダの対象** |
| PaaS | アプリを作るための土台（実行環境・DB）を提供する |
| IaaS | サーバ・ストレージ・ネットワークを提供する → [クラウド・IaaS](../04_クラウド・IaaS/README.md) |
| パッケージソフト | 買い切ってサーバに入れて使う従来型。保守料が別途 |
| 受託開発（SI） | 顧客ごとに作る。標準品ではない → [SIer・ITサービス](../05_SIer・ITサービス/README.md) |
| 基盤モデル・AI API | 言語モデルそのものを提供する層 → [生成AI](../../01_注目テーマ/01_生成AI/README.md) |

```
  半導体 ─▶ データセンター ─▶ クラウド ─▶ 基盤モデル ─▶ ★SaaS・業務アプリ★ ─▶ 利用企業
   GPU       電気・冷却        計算資源     AIモデル        業務そのもの          全産業
                                                                 ▲
                                            SIer・コンサルが導入と連携で横から支える
```

**隣接領域との境界**：土台を貸すのがクラウド、顧客ごとに作るのがSI、標準品を貸すのがSaaS。
同じ「企業のIT予算」を取り合う関係にあり、2026年はその配分がAIによって動いている。

## 2. 市場規模と成長性

| 指標 | 数値 | 時点・出所 |
| --- | --- | --- |
| 世界IT支出 | 6.37兆ドル（前年比+14.2%） | 2026年見通し、Gartner（2026年7月改定） |
| 世界のソフトウェア支出 | 約1.44兆ドル（前年比+15.1%） | 2026年見通し、Gartner（報道・二次引用） |
| 世界のSaaS市場（狭義） | 2025年 約4,080億ドル → 2026年 約4,650億ドル | 調査会社の推計。定義により幅が大きい |
| 国内 法人向けソフトウェア市場 | 2025年度に3兆円超 | 富士キメラ総研調査（報道ベース） |
| 国内 SaaS／PaaS市場 | 2029年度に約3兆3,975億円（2024年度比+73.0%） | 富士キメラ総研の予測（推計） |
| 国内 SaaS市場（狭義） | 2026年に約1.67兆円とする民間推計 | 出所により1兆〜2兆円と幅がある |
| 国内 SaaS分野の資金調達 | 2025年は1,374億円（2022年比でほぼ半減） | 報道ベース |

- 支出額そのものは2026年も二桁成長。**売られたのは業績ではなく「将来もこの成長が続く」という前提**
- 国内は**レガシーシステムの刷新需要**という米国にない追い風がある
- 「SaaS市場」の数字は定義（パッケージ込みか、PaaS込みか、外資の国内売上を含むか）で桁が変わる。単独の数字を根拠にしない

## 3. バリューチェーン（川上 → 川下）

```
① 開発 ─▶ ② インフラ ─▶ ③ 販売・獲得 ─▶ ④ 導入・定着 ─▶ ⑤ 継続・拡張 ─▶ ⑥ 利用企業
 エンジニア   クラウド      マーケ/営業     CS・SIer        CS・営業         全産業
 プロダクト   AI API        広告・展示会    オンボーディング  アップセル

  ◀────────── お金はこの向きに流れる（利用企業 → 開発・インフラ） ──────────

  ▲ 費用の山は③（CAC）。売上の山は⑤（NRR）。この時間差が「初年度赤字」の正体
```

| 工程 | 担い手 | どこに価値が集まるか |
| --- | --- | --- |
| ① 開発 | 自社エンジニア、プロダクトマネージャー | 1本を全顧客で共用できるほど高粗利になる |
| ② インフラ | AWS／Azure／Google Cloud、AI API提供者 | SaaS側から見れば原価。AI機能は**変動費**になる |
| ③ 販売・獲得 | マーケ、インサイドセールス、フィールドセールス | ここの効率（CAC）が成長速度を決める |
| ④ 導入・定着 | カスタマーサクセス、SIer、販売代理店 | 日本では**SIerが大企業への販路**として効く |
| ⑤ 継続・拡張 | カスタマーサクセス、営業 | **利益の源泉**。NRR100%超なら既存だけで成長する |
| ⑥ 利用企業 | 全産業 | 買う側の論点は予算の読みやすさと乗り換えコスト |

## 4. 主要プレイヤーとシェア

| 企業 | 立ち位置 | 特徴 |
| --- | --- | --- |
| Salesforce | 世界最大級のCRM／SFA | SaaSという形態を広めた先駆者。AIエージェント（Agentforce）で反転を図る |
| Microsoft | Microsoft 365／Dynamics／Copilot | **束ね売り**が最大の武器。単機能SaaSを飲み込む側 |
| SAP／Oracle／Workday／ServiceNow | 大企業向け基幹・人事・IT運用 | 乗り換えコストが極めて高く、解約されにくい |
| Adobe／Atlassian／HubSpot／Datadog 等 | 制作・開発・マーケ・監視 | PLGで現場から入り込む型が多い |
| freee／マネーフォワード | 国内の会計・バックオフィス | 制度対応（インボイス、電帳法）に密着。中小企業に強い |
| ラクス | 経費精算・請求（楽楽シリーズ） | 高い営業効率と収益性で知られる |
| Sansan | 名刺・請求書受領（Bill One） | 連結ARR 459億円、Bill Oneが牽引と報じられる（2026年1月時点） |
| SmartHR／カオナビ／kubell 等 | 人事労務・チャット | 国内の主要ホリゾンタルSaaS |
| アンドパッド／カケハシ／atama plus／キャディ 等 | 建設・薬局・教育・製造のバーティカルSaaS | 業界知識が参入障壁。未上場で評価額300億円超とされる企業も |
| NTTデータ／富士通／日鉄ソリューションズ 等 | SIer | 競合でありながら**SaaSの販路**でもある → [SIer・ITサービス](../05_SIer・ITサービス/README.md) |

**シェアの見方**：SaaSのシェアは売上より**領域ごと**に見る。会計・人事は国産が強く、
CRM・開発・IT運用は外資がほぼ押さえる。全体を一枚のシェア表で語ると実態を外す。

## 5. 収益モデル・コスト構造

| 収益モデル | 課金の単位 | 特徴 |
| --- | --- | --- |
| シート課金 | 利用者1人あたり月額 | 分かりやすい。**AIエージェントで席が減ると弱る** |
| 階層（プラン）課金 | 機能の束ごと | アップセルの階段になる |
| 従量課金 | 処理件数・保存量・API回数 | 価値と一致するが売上が読みにくい |
| 成果課金 | 解決件数・成約件数 | 顧客の納得感は高いが、計測でもめる |
| 初期費用・導入支援 | 一時金 | **ARRには含めない**（積み上がらないため） |

**コスト構造の核心**：

- 従来は**原価がほぼ固定費**（サーバ＋サポート）で、粗利率75〜85%が標準だった
- 赤字の正体は販売・マーケティング費。**来期以降のARRを買っている費用**なので、絞れば即黒字化できる
- 2026年の変化は、AI推論コストという**使われるほど増える変動費**が原価に入ったこと。粗利率に低下圧力
- 指標の詳細は [SaaSの経済学](01_SaaSの経済学.md)

## 6. 競争要因（KSF）と参入障壁

| 要因 | 中身 | 障壁の高さ |
| --- | --- | --- |
| **業務データの蓄積** | 顧客の取引・人事・会計データが溜まるほど抜けにくい | 高い。2026年の最大の防衛線 |
| **制度対応力** | 税制・労基法・電帳法の改正に毎年追随する開発力 | 国内では高い。外資の参入を鈍らせる |
| **乗り換えコスト** | データ移行、再教育、業務手順の作り直し | 基幹に近いほど高い |
| **束ね売り（バンドル）** | 複数機能をまとめて提供できる資本力 | 非常に高い。巨大ベンダーの構造的優位 |
| 販路 | 中小企業への営業網、SIer・代理店との関係 | 中〜高。日本では特に効く |
| 開発速度 | 週単位で機能を出し続けられるか | 中。資金があれば追いつける |
| **AI機能の実装力** | 自社データを使ったAI機能を追加課金に変換できるか | 2026年に急上昇した要因 |

参入自体は容易（クラウドがあれば個人でも作れる）が、**生き残る障壁は高い**のがこの業界の特徴。
特にバーティカルSaaSは、業界の商習慣を知らない新規参入者を寄せつけない。

## 7. 規制・法制度

| 領域 | 内容 |
| --- | --- |
| 個人情報保護法 | 顧客データを預かる以上、委託先管理・越境移転の規律がかかる |
| **電子帳簿保存法** | 帳簿書類の電子保存要件。改正のたびに会計・請求SaaSの対応需要が生まれる |
| **インボイス制度**（2023年開始） | 消費税の仕入税額控除方式。請求書・経費精算SaaSの需要源 |
| 労働基準法・社会保険関連 | 人事労務SaaSの機能要件を直接規定する |
| **ISMAP** | 政府情報システム向けのクラウドサービス安全性評価制度。政府調達に入る条件 |
| 下請法・独占禁止法 | 大手プラットフォームの優越的地位、SIerとの取引慣行が論点 |
| AI関連の規律 | EU AI Act、国内のAI事業者ガイドライン等。AI機能を載せる際の説明責任 → [生成AI](../../01_注目テーマ/01_生成AI/README.md) |
| 経済安全保障・データ主権 | データの保管国、政府調達での国内保管要件 |

> 日本では **規制が参入障壁として働く**。制度対応は日本市場専用の投資になるため外資が嫌がり、
> 国産SaaSの砦になる。ただし同じ理由で、国産SaaSは海外展開が難しい。

## 8. 最近のトピック

→ 詳細と出典URLは [04_直近トピック_2026](04_直近トピック_2026.md)

1. **2026年2月、SaaS株が一斉に売られた**（SaaSpocalypse）。業界全体で1兆ドル規模の時価総額が失われたと報じられ、国内でもラクス・Sansan・freee等が下落率上位に並んだ
2. **課金モデルがシートから従量・成果へ移行中**。シート単独は1年で21%→15%、ハイブリッドは27%→41%（調査会社推計）。IDCは2028年までに純粋なシート課金は陳腐化すると予測
3. **AI売上は伸びるが本体が鈍る**構図。SalesforceのAgentforceはARR約8億ドル・前年比+169%（2026年、報道ベース）だが、株価は下落局面を経験した
4. **粗利率の前提が崩れ始めた**。AI推論コストが原価に入り、Rule of 40の達成が難化。NRR中央値も101〜103%程度まで圧縮（推計）
5. **国内は選別局面**。2026年上半期の国内スタートアップ調達額は3,779億円で前年同期比+12%だが、大型案件に集中。SaaS分野の調達額は2022年比でほぼ半減と報じられる
6. **レガシー刷新需要は続く**。国内法人向けソフト市場は2025年度に3兆円超（富士キメラ総研調査、報道ベース）。米国と異なる国内固有の追い風

## 9. 用語メモ

各ノート末尾にも分野別の用語メモを置いている。

| 用語 | 意味 |
| --- | --- |
| **SaaS** | ソフトをネット越しに月額・年額で使わせる提供形態 → [01](01_SaaSの経済学.md) |
| **ARR / MRR** | 年間／月間の継続課金売上。期末の契約が続くと仮定した理論値 → [01](01_SaaSの経済学.md) |
| **チャーン（解約率）** | 一定期間に失われた顧客数または売上の割合 → [01](01_SaaSの経済学.md) |
| **NRR** | 既存顧客群の1年後の支払額 ÷ 1年前の支払額。100%超で既存だけで成長 → [01](01_SaaSの経済学.md) |
| **CAC / LTV** | 顧客獲得コスト／顧客生涯価値。3倍以上が健全とされる → [01](01_SaaSの経済学.md) |
| **CAC回収期間** | CAC ÷ 月額粗利。資金繰りに直結する → [01](01_SaaSの経済学.md) |
| **T2D3** | 3倍・3倍・2倍・2倍・2倍で5年伸ばす成長基準（2015年提唱） → [01](01_SaaSの経済学.md) |
| **Rule of 40** | 成長率＋利益率が40以上あれば健全とみなす経験則 → [01](01_SaaSの経済学.md) |
| **PSR** | 時価総額 ÷ 売上高。赤字企業の評価に使われる倍率 → [01](01_SaaSの経済学.md) |
| **マルチテナント** | 1つのシステムを全顧客で共用しデータだけ区切る方式 → [02](02_作り方と売り方.md) |
| **PLG / SLG** | 製品主導／営業主導の成長の型 → [02](02_作り方と売り方.md) |
| **カスタマーサクセス** | 契約後の定着と拡張を担う職種 → [02](02_作り方と売り方.md) |
| **ホリゾンタル／バーティカルSaaS** | 業種横断型／業界特化型 → [02](02_作り方と売り方.md) |
| **SLA** | 稼働率などのサービス水準を保証する契約条項 → [02](02_作り方と売り方.md) |
| **ISMAP** | 政府調達向けクラウドサービス安全性評価制度 → [02](02_作り方と売り方.md) |
| **バンドル（束ね売り）** | 複数機能をまとめて売ること。単機能SaaSの脅威 → [03](03_市場の構造.md) |
| **AIネイティブ** | 最初から生成AIを前提に設計された製品・企業 → [03](03_市場の構造.md) |
| **SaaSpocalypse** | 2026年のSaaS株一斉下落を指す造語 → [04](04_直近トピック_2026.md) |
| **成果課金** | 解決件数など結果に応じた課金 → [04](04_直近トピック_2026.md) |
