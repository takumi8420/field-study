# ③ フィンテックの各領域

このノートで分かること：決済以外のフィンテックが**どこで金を稼いでいるのか**。
BNPL、家計簿アプリ、オンライン融資、法人向けSaaS、証券・ロボアド、API連携を
**「誰から、どういう名目でお金を取るか」**という1つの軸で並べ直す。

> **結論を先に**：フィンテックの収益源は結局**4つしかない**。
> **①手数料（取引のたびに取る）②利ざや（貸して金利を取る）③サブスク（月額）④送客・広告**。
> そして日本のフィンテックの多くは、**銀行の代わりになるのではなく、
> 銀行の機能をアプリの形に包み直して手数料を取る**位置にいる。

## 1. 全体地図 ── 銀行の機能を分解して誰が取ったか

```
【伝統的な銀行が1社で持っていた機能を、誰が切り取ったか】

  ┌─────────── 銀 行 ───────────┐
  │ 決済  │ 預金 │ 融資 │ 為替 │ 資産運用 │ 記帳 │
  └───┬───┴──┬──┴──┬──┴──┬──┴────┬────┴──┬──┘
      │       │      │      │         │       │
      ▼       ▼      ▼      ▼         ▼       ▼
   コード   ネット  オンライン 送金    ロボアド  家計簿
   決済     銀行    レンディング アプリ  ・ネット証券 ・会計SaaS
   PayPay   楽天銀行 LENDY等   Wise等  WealthNavi  MF/freee
   楽天ペイ  住信SBI  クレカ後払い ことら  SBI/楽天   マネーツリー
      │                                            │
      └──────────── 経済圏で再統合 ◀──────────────┘
        ▲ 一度バラバラにした機能を、PayPay・楽天が
          アプリ1本に再パッケージして囲い込む、というのが
          2020年代後半の日本の構図
```

| 領域 | 誰から取るか | 名目 | 利益率の性格 |
| --- | --- | --- | --- |
| 決済 | 加盟店 | 決済手数料（%） | 薄利。規模勝負 |
| BNPL・カード | 加盟店＋利用者 | 手数料＋遅延損害金・分割手数料 | 与信が当たれば高利益 |
| オンライン融資 | 借り手 | 金利（利ざや） | 貸倒れ率次第で一気に赤字 |
| 家計簿・PFM | 利用者＋金融機関 | サブスク＋送客手数料 | 高粗利だが単価が低い |
| 法人向けSaaS | 企業 | 月額＋決済・ファイナンス手数料 | **SaaS＋金融の二段構え** |
| 証券・ロボアド | 預かり資産 | 運用手数料（年率%） | ストック型。残高が積み上がるほど安定 |

## 2. BNPL（後払い）── クレジットカードとどう違うのか

**BNPL＝Buy Now, Pay Later。「今買って、後で払う」**。
コンビニ払い・翌月一括払いが中心で、**カードを持たない／持ちたくない層**を取り込む。

| 比較軸 | クレジットカード | BNPL（日本の主流形） |
| --- | --- | --- |
| 入会時の審査 | 収入・勤務先を審査（信用情報照会あり） | **原則なし**。氏名・電話番号・住所程度 |
| 与信の考え方 | 人を審査して枠を与える | **取引ごとに審査**（金額・配送先・過去の行動から瞬時に判定） |
| 支払回数 | 一括・分割・リボ | 翌月一括が中心。2か月超なら割賦販売法の対象 |
| 加盟店の手数料 | 2〜4%程度 | **3〜7%程度と高い**（未回収リスクを事業者が負うため） |
| 利用者の負担 | 年会費・金利 | 決済ごとの手数料（数百円）、遅延損害金 |
| 規制 | 割賦販売法（包括信用購入あっせん） | **支払期間2か月以内なら割販法の対象外＝実質的に規制が薄い** |

**代表例**：ネットプロテクションズ（NP後払い）、Paidy（PayPal傘下）、
atone、Kyashのイマすぐ入金、メルペイスマート払い。

```
【BNPLの経済性：なぜ加盟店手数料が高いのか】

  加盟店 ──(商品発送)──▶ 利用者
    │                      │
    │ 売掛債権を            │ 後日コンビニ/口座振替で支払う
    │ BNPL事業者に譲渡       │  （払わない人が一定数いる）
    ▼                      ▼
  BNPL事業者 ◀─────────────┘
    ├ 手数料 3〜7% を加盟店から受け取る
    ├ 未回収を100%かぶる（加盟店は保証される）
    └ 収益 ＝ 手数料 － 貸倒れ － 請求書発行/督促コスト

  ▲ つまりBNPLは「決済」ではなく「売掛金の買取＋保証（ファクタリング）」に近い。
    高い手数料は与信リスクの対価であり、
    貸倒れ率が数%動くだけで黒字と赤字が入れ替わる。
```

**規制動向**：日本ではBNPL単体を規制する法律は2026年時点で存在しない。
支払期間が2か月を超える場合に割賦販売法が適用されるに留まる
（日本経済新聞 2026年6月掲載の解説記事でも「法規制なし」と整理されている）。
一方、**英国では2026年7月15日からFCAによるBNPL規制が施行**される予定で、
日本でも多重債務化への懸念から制度整備の議論が続いている。
国内BNPL市場は2028年度に約2.8兆円との調査会社推計がある。
→ [消費者金融](../../05_金融/12_消費者金融/README.md)

## 3. 家計簿・PFM ── 「お金を動かさない」フィンテック

**PFM＝Personal Financial Management（個人財務管理）**。
複数の銀行・カード・証券の残高を1画面に集約する。マネーフォワード ME、Zaim、Moneytree など。

**稼ぎ方が独特**で、決済も融資もしないのに収益が立つ。

| 収益源 | 中身 | 目安 |
| --- | --- | --- |
| 個人課金（サブスク） | プレミアム会員の月額 | 月数百円 |
| **送客手数料（アフィリエイト）** | 「あなたはこのカードに変えると年◯円得」→ 申込で報酬 | **利益の主力になりやすい** |
| 金融機関向けOEM | 銀行アプリの中身としてPFM機能を提供 | BtoBのライセンス収入 |
| データ提供 | 匿名加工した消費データの提供 | 規模次第 |

```
【PFMの位置：お金は預からず「見える化」だけ担当する】

  銀行A ─┐
  銀行B ─┤
  カードC ┼──▶ 【電子決済等代行業者】──▶ PFMアプリ ──▶ 利用者
  証券D ─┤       （API経由で参照）           │
  ECポイントE ┘                              └─▶ 金融商品へ送客して手数料

  ▲ お金は1円も動かさない。動かすのは「情報」だけ。
    だから在庫も貸倒れもなく、粗利は高い。ただし単価が低いので
    黒字化には規模（会員数）が要る。
```

## 4. API連携と電子決済等代行業 ── 日本版オープンバンキングの土台

昔の家計簿アプリは、利用者から銀行のID・パスワードを預かって
**スクレイピング**（銀行サイトに代理ログインして画面を読み取る）していた。
これはセキュリティ上きわめて危うい。そこで2017年の**改正銀行法**で制度が整えられた。

| 制度 | 内容 |
| --- | --- |
| **電子決済等代行業**（2018年施行） | 銀行APIに接続してサービスを提供する事業者の**登録制**。マネーフォワード、freee、Money Forward、Moneytree 等が登録 |
| **銀行のオープンAPI努力義務** | 銀行側に、参照系（残高・明細）・更新系（振込）のAPIを整備する努力義務 |
| 契約締結義務 | 代行業者は接続先の銀行と個別に契約を結ぶ |

```
【スクレイピング方式 vs API方式】

 [旧] 利用者 ──ID/PW を渡す──▶ アプリ ──代理ログイン──▶ 銀行
      ▲ アプリが本人のIDを持ってしまう。銀行は誰が来たか分からない

 [新] 利用者 ──認可(OAuth)──▶ 銀行 ──アクセストークン──▶ アプリ
      ▲ IDは銀行にしか渡さない。銀行は「どのアプリに何を許可したか」を管理でき、
        利用者はいつでも接続を切れる。登録制で事業者の適格性も担保される
```

> **論点**：日本のオープンAPIは「参照系は普及、更新系（振込）は限定的」という状態が続いている。
> 銀行がAPI接続手数料を取るケースもあり、**欧州のPSD2のように
> 「銀行は無償でAPIを開放せよ」とまでは踏み込んでいない**。
> これが日本でオープンバンキング型のサービスが伸びにくい一因とされる。
> → [メガバンク](../../05_金融/01_メガバンク/README.md)、[地方銀行](../../05_金融/02_地方銀行/README.md)

## 5. オンライン融資とスコアリング

「決算書を見て人が判断する」代わりに、**データで自動的に与信する**。

| 類型 | 与信に使うデータ | 代表例 |
| --- | --- | --- |
| **トランザクションレンディング** | 自社プラットフォーム上の売上・取引履歴 | Amazonレンディング、楽天スーパービジネスローン、PayPay資金調達 |
| 会計データ与信 | クラウド会計の入出金・売掛金 | freee・マネーフォワードと金融機関の連携融資 |
| 銀行の非対面ローン | APIで取得した口座入出金 | ネット銀行の事業者ローン |
| 個人向けスコアリング | 購買履歴、支払遅延、属性 | 各社の独自スコア |

> **なぜ強いのか**：プラットフォーム事業者は、**借り手の売上が自分の口座を通る**。
> 返済を売上から天引きできるので、貸倒れが構造的に起きにくい。
> 実例として、PayPayの加盟店向け「PayPay資金調達」は累計4万件超の利用で
> **貸倒率0.03%**（2026年5月 決算発表、報道ベース）と極端に低い。
> 銀行が同じことをしようとしても、**取引の全体が見えないので真似できない**。
> これが「決済を握る者が融資で勝つ」と言われる理由である。

## 6. 法人向けフィンテック ── 経費精算・請求書・給与

BtoCより地味だが、**単価が高く解約されにくい**ので事業としては堅い。
さらに**SaaSの上に金融（決済・ファイナンス）を乗せる**と収益が跳ねる。

| 領域 | やること | 代表例 | 収益源 |
| --- | --- | --- | --- |
| 経費精算 | 領収書のOCR、承認ワークフロー、法人カード連携 | TOKIUM、楽楽精算、マネーフォワード クラウド経費 | 月額＋ID課金＋法人カードの手数料 |
| **請求書受領・発行** | 電子帳簿保存法・インボイス制度対応 | Bill One、マネーフォワード クラウド請求書、バクラク | 月額＋通数課金 |
| 法人カード・支出管理 | 部門別カード発行、リアルタイム利用制限 | UPSIDER、Bill One Card、freeeカード | **加盟店手数料（インターチェンジ）の取り分** |
| ファクタリング／請求書買取 | 売掛金を早期現金化 | OLTA、ペイトナー | 買取手数料（実質的な金利） |
| 給与・労務 | 給与計算、前払い（給与前払いサービス） | SmartHR、ジョブカン、Payme | 月額＋前払いの手数料 |

> **法人カードの経済性が分かりやすい**：UPSIDER等の法人カード事業者は、
> **利用額 × インターチェンジフィー**が主収入。
> 企業の年間経費が10億円なら、1%でも1,000万円。
> つまり**「経費精算SaaSを無料で配ってでもカードを使わせる」**のが合理的になる。
> SaaS単体では月額数万円でも、カードに乗れば桁が変わる。
> → [ソフトウェア・SaaS](../06_ソフトウェア・SaaS/README.md)

**制度が需要を作った領域**でもある。電子帳簿保存法の電子取引データ保存義務化（2024年1月完全移行）と
インボイス制度（2023年10月開始）が、請求書SaaSの一斉導入を生んだ。

## 7. 証券・ロボアド ── 「残高が積み上がる」ストック型

| 類型 | 稼ぎ方 | 代表例 |
| --- | --- | --- |
| ネット証券 | 売買手数料（**日本株はほぼ無料化**）→ 信用取引金利、投信の信託報酬、為替スプレッドへシフト | SBI証券、楽天証券、松井証券 |
| **ロボアドバイザー** | 預かり資産に対する**年率手数料（1%前後）** | WealthNavi、THEO、楽ラップ |
| スマホ証券 | 少額・単元未満株。手数料＋スプレッド | PayPay証券、LINE証券（終了） |
| 投資型クラファン | 募集手数料、運営手数料 | 各種不動産・事業性クラファン |

**ロボアドは典型的なストックビジネス**。預かり資産が増えれば手数料が自動的に増える一方、
獲得コスト（広告）を先に払う。**黒字化までに時間がかかるが、いったん積み上がると崩れにくい**。

実績値：WealthNaviの預かり資産は**2026年5月に2兆円を突破**（同社プレスリリース）。
2024年1月の1兆円から約2年4か月で倍増した。同社は三菱UFJフィナンシャル・グループ傘下で、
2026年度後半に三菱UFJ銀行と共同でデジタルバンクを立ち上げる計画と報じられる。
**フィンテックが銀行に買われて、銀行の顔になる**という日本的な着地の代表例。

新NISA（2024年1月開始）が個人の資金流入を押し上げており、
証券・ロボアドはフィンテックの中で最も追い風が強い領域といえる。
→ [証券](../../05_金融/05_証券/README.md)、[資産運用](../../05_金融/06_資産運用/README.md)

## 8. 銀行との協業と競合 ── 3つのパターン

```
【フィンテックと銀行の関係】

 ① 競合する      フィンテック ⇔ 銀行
    例：ネット銀行・コード決済が、決済と送金の手数料収入を奪う

 ② 銀行の裏方になる  フィンテック ──(OEM/API)──▶ 銀行 ──▶ 顧客
    例：PFMを銀行アプリに提供、BaaS（Banking as a Service）

 ③ 銀行に買われる   銀行 ──(買収/出資)──▶ フィンテック
    例：WealthNavi（MUFG）、Paidy（PayPal）、マネックス（ドコモ）、
        三井住友FG×SBI、KDDI×auじぶん銀行

 ▲ 日本では ③ が多い。理由は「免許と信用と資金調達力」を銀行が持ち、
   「UIと開発速度」をフィンテックが持つという相互補完が成り立つから。
   欧米のように銀行を置き換えるのではなく、銀行に合流する形が主流。
```

**BaaS（Banking as a Service）**＝銀行が免許と勘定系を貸し、
事業会社が自分のブランドで金融サービスを出す形。
住信SBIネット銀行の「NEOBANK」（ヤマダNEOBANK、JAL NEOBANK など）が代表例。
→ [ネット銀行](../../05_金融/04_ネット銀行/README.md)

## 用語メモ

| 用語 | 意味 |
| --- | --- |
| **BNPL** | Buy Now, Pay Later。後払い。与信を取引ごとに行い、加盟店から3〜7%を取る |
| **割賦販売法** | 分割払い・後払いを規制する法律。**支払期間2か月以内は対象外**なのでBNPLの多くが外れる |
| **PFM** | Personal Financial Management。家計簿・資産管理アプリ |
| **電子決済等代行業** | 銀行APIに接続する事業者の登録制度（2018年施行・改正銀行法） |
| **スクレイピング／API方式** | 代理ログインで画面を読む旧方式／銀行が認可トークンを発行する新方式 |
| **オープンバンキング** | 銀行データを外部事業者に開放する考え方。欧州はPSD2で義務化、日本は努力義務 |
| **トランザクションレンディング** | 自社プラットフォーム上の取引データで与信する融資。返済を売上から天引きできる |
| **ファクタリング** | 売掛金を割り引いて買い取る。融資ではないので貸金業の規制を受けにくい |
| **インターチェンジフィー** | 法人カード事業者の主収入。→ [① 決済はどう流れ誰が取り分を得るか](01_決済はどう流れ誰が取り分を得るか.md) |
| **ロボアドバイザー** | 自動で資産配分・積立・リバランスを行うサービス。預かり資産の年率1%前後が収入 |
| **BaaS** | Banking as a Service。銀行が免許と機能を他社に貸す形態 |
| **新NISA** | 2024年1月開始の非課税投資制度。証券・ロボアドへの資金流入を押し上げた |
