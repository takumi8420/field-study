# 求人メディアのビジネスモデル ─ 掲載課金と成功報酬が、事業の性格を決める

このノートで分かること：求人サイトは「広告を売る商売」と「採用が決まったら手数料をもらう商売」に
大きく分かれ、**どちらを選ぶかで営業のやり方から利益率、景気への強さまで全部が変わる**こと。
そして Indeed に代表される**求人アグリゲーター**が、その前提をどう壊して作り直したか。

## 1. 課金モデルは3つしかない

求人サービスのお金の取り方は、突き詰めると次の3つ（とその組み合わせ）に整理できる。

| 課金モデル | いつ課金するか | 誰がリスクを負うか | 代表例 |
| --- | --- | --- | --- |
| **掲載課金型**（広告型） | 求人原稿を載せた時点で前払い | **採用企業**（採用できなくても払う） | タウンワーク、マイナビ転職、リクナビNEXT（枠販売） |
| **クリック課金型**（CPC） | 求職者が求人をクリックした時 | 採用企業（ただし反響に連動） | Indeed、求人ボックス、スタンバイ |
| **成功報酬型** | 採用が決まった時（理論年収の15〜35%など） | **サービス側**（決まらなければ0円） | 人材紹介、ダイレクトリクルーティングの一部、Wantedly の一部プラン |

**掲載課金型**＝求人票を「広告枠」として売る。新聞広告と同じ発想。
**成功報酬型**＝採用が成立した時だけ課金する。仲介手数料と同じ発想。

> ポイント：掲載課金は**売った瞬間に売上が確定する**ので収益が読みやすいが、
> 採用企業から見ると「お金を払ったのに誰も採れなかった」が起こりうる。
> 成功報酬はその逆で、企業は安心だがサービス側は在庫リスク（＝人が集まらない risk）を丸ごと被る。

### なぜ日本では掲載課金が長く主流だったのか

紙の求人誌から始まった歴史的経緯に加え、**原稿制作が売り物の一部だった**ことが大きい。
中小企業は自社で魅力的な求人票を書けないので、営業担当がヒアリングして原稿を作り、
写真を手配し、掲載枠の大きさを提案する。この**「制作込みの営業」を有料で売る**構造だったため、
掲載課金でないと成り立たなかった。結果として求人メディアは**営業人員を大量に抱える労働集約型**になる。

```
  ＜掲載課金型の営業フロー＞
  企業を訪問 ──▶ ヒアリング ──▶ 原稿制作 ──▶ 掲載（2週間〜4週間の枠） ──▶ 効果報告 ──▶ 再掲載提案
   営業人員     営業人員        制作スタッフ    売上はここで確定         営業人員      ここで回る
      ▲                                                                                  │
      └──────────────────── 人手が売上に直結。だから固定費（人件費）が重い ◀───────────┘
```

## 2. アグリゲーターが業界を変えた

**求人アグリゲーター**（集約型求人検索エンジン）＝自社では求人原稿を作らず、
世の中の求人サイト・企業の採用ページを**クローラで集めて検索させる**サービス。
Indeed（リクルート傘下）、求人ボックス（カカクコム）、スタンバイ（ビズリーチ＝Visional）が国内の代表格。

何が変わったのか。3点に集約できる。

| 変わったこと | 従来の求人メディア | アグリゲーター |
| --- | --- | --- |
| 求人の集め方 | 営業が1件ずつ取ってくる | **クロール＋無料掲載**で自動的に集まる |
| 求職者の入口 | 各サイトのブランドで直接集客 | **検索エンジン経由**（「地名＋職種」で流入） |
| 課金 | 掲載枠の前払い | **クリック課金**（無料掲載も可） |
| 在庫（求人数） | 営業力の上限が在庫の上限 | ほぼ無制限。掲載件数で圧勝 |

```
  ＜アグリゲーター登場前＞            ＜登場後＞
  求職者                              求職者
   │ サイトを1つずつ回る               │ 検索でまず到達
   ├─▶ 求人サイトA                    └─▶ ★アグリゲーター★
   ├─▶ 求人サイトB                          │ クリック課金で送客
   └─▶ 求人サイトC                          ├─▶ 求人サイトA
                                            ├─▶ 求人サイトB
      各サイトが直接集客で競う               └─▶ 企業の採用ページ（直接）
                                     サイトAやBは「集客の下請け」側に回る
```

> ここが最大の転換点：**求人メディアは、集客の主導権をアグリゲーターに渡した**。
> 自社サイトへの応募の相当部分がアグリゲーター経由になり、
> 「掲載料をもらいつつ、集客費をアグリゲーターに払う」という板挟みが生まれた。

## 3. クリック課金への移行と「応募単価」という共通言語

クリック課金（CPC＝Cost Per Click）になると、採用企業の見る指標が変わる。
掲載課金時代は「掲載料◯万円」という**固定費**だったものが、
CPC では「1応募あたりいくらで採れたか」という**変動費**になる。

```
  広告費 ── ÷ クリック数 ──▶ CPC（クリック単価）        例：80円
  広告費 ── ÷ 応募数   ──▶ CPA＝応募単価               例：4,000円
  広告費 ── ÷ 採用人数 ──▶ 採用単価（Cost Per Hire）   例：60,000円

  応募単価 = CPC ÷ 応募率（クリックした人のうち応募する割合）
  採用単価 = 応募単価 ÷ 採用率（応募者のうち採用に至る割合）
```

**応募単価**が業界の共通言語になったことの意味は大きい。
求人原稿の良し悪しが「クリエイティブの好み」ではなく**数字で比較できる**ようになり、
採用がネット広告の運用と同じ手触りになった → [ネット広告](../07_ネット広告/README.md) と同じ運用代理店が育った。

職種・地域によって応募単価は桁で違う（飲食のアルバイトで数千円、専門職で数万円〜）。
**人手不足の職種ほど応募単価が上がる**ので、この数字自体が労働需給の温度計になっている。

## 4. リクルート＝HRテクノロジー事業の収益構造

リクルートホールディングスの事業は大きく3つに分かれ、
そのうち **HRテクノロジー**（Indeed・Glassdoor）が利益の柱になっている。

| セグメント | 中身 | 課金の性格 |
| --- | --- | --- |
| **HRテクノロジー** | Indeed、Glassdoor（主に米国） | クリック課金＋成果連動型の有料商品 |
| マッチング＆ソリューション | 国内の人材・販促（リクナビ、タウンワーク、ホットペッパー等） | 掲載課金＋SaaS |
| 人材派遣 | 国内外の派遣（Staffmark、RGF 等） | 時間単価×稼働 → [人材派遣](../../15_サービス・生活関連/01_人材派遣/README.md) |

2026年3月期の連結売上収益は約3兆6,973億円（前年比+3.9%）、営業利益は約6,305億円（同+28.5%）と報じられる。
米国 HRテクノロジー売上は96.7億ドル（前年比+7.6%）で、
**求人件数そのものは減っているのに売上が伸びた**点が特徴（報道ベース、詳細は同社IRで確認）。

なぜ求人が減っても売上が伸びるのか。答えは**単価の引き上げ**にある。

```
  売上 = 求人件数 × 1件あたり課金額
         ▼ 減っている     ▼ 上げている
         労働市場の冷え    「Premium Sponsored Jobs」など
         込み（後述）      成果に近い課金商品への移行
```

単純なクリック課金から、**応募や採用に近いところで課金する商品**（スポンサー求人の上位枠、
応募課金、採用課金）へ寄せていくのが2020年代後半の一貫した方向で、
2026年3月期第1四半期（2026年8月公表）にはHRテクノロジー売上が前年同期比+20.9%と報じられた。

> 要するに：アグリゲーターの勝ち筋は「求人をたくさん集めて安く出す」ではなく、
> **集めた求職者データを使って、採用に近い瞬間に高く課金する**こと。
> ここが後述の [HRテックの各領域](02_HRテックの各領域.md) と地続きになる。

## 5. Indeed PLUS ─ 媒体とアグリゲーターの関係が反転した

2023年に始まった **Indeed PLUS** は、1つの求人原稿を Indeed に入稿すると、
リクルート系（タウンワーク、リクナビNEXT 等）や提携する他社媒体へ**まとめて配信**される仕組み。

| 立場 | Indeed PLUS 以前 | 以後 |
| --- | --- | --- |
| 採用企業 | 媒体ごとに原稿を作り、別々に発注 | **一度の入稿で複数媒体に配信**。予算も一元管理 |
| 求人媒体 | 自前で集客し、自前で課金 | Indeed の配信先の1つになる（＝在庫の供給元／表示先） |
| 代理店 | 媒体ごとの枠を販売 | Indeed PLUS の運用（予算配分・原稿改善）を売る |

つまり、**媒体がアグリゲーターの「面」として組み込まれた**。
媒体側は自社集客の苦労が減る代わりに、価格決定権と顧客接点をアグリゲーターに一段譲っている。

2026年3月18日には Indeed の掲載ポリシー改定が施行され、求人情報の品質基準
（曖昧な待遇表記、実在しない求人、応募後の離脱など）が厳格化されたと報じられる。
アルゴリズムも「広く表示する」から「行動データで合いそうな人に当てる」方向へ動いている。

## 6. このモデルの弱点

| リスク | 中身 | 効いてくる場面 |
| --- | --- | --- |
| **景気連動が激しい** | 採用広告費は真っ先に削られる裁量経費 | 2025〜2026年は新規求人が減少傾向 |
| **在庫が他人のもの** | 求人はクロール元に依存。取引条件で消える | ポリシー改定、媒体との関係悪化 |
| **検索エンジン依存** | 集客の多くが検索由来。仕様変更に弱い | SEO変動、AI検索への遷移 |
| **成果課金は景気で焦げる** | 採用が止まると売上も止まる | 不況期に成功報酬型は先に痛む |
| **AI応募の増加** | 生成AIで量産された応募が応募率を歪める | 応募単価の指標としての信頼性 |

参考として、国内の労働需給は緩んできている。厚生労働省の一般職業紹介状況では
2025年度（令和7年度）平均の有効求人倍率は1.20倍で、前年度の1.25倍から3年連続の低下。
2026年3〜4月は1.18倍で推移している。求人メディアの売上はこの数字にほぼ連動する。

また公益社団法人全国求人情報協会の調査では、2024年度の求人情報提供サービス市場規模は
約6,661億円。2025年の求人広告掲載件数は2,887万件で、2025年4〜12月は前年同期比 -4.6% だった。

## 7. モデル別に見た「事業の性格」まとめ

```
            収益の読みやすさ
                  高
                   │  掲載課金型
                   │  ・売上は掲載時に確定
                   │  ・営業人員が固定費として重い
                   │  ・不況で掲載社数が落ちると即減収
   顧客の ◀────────┼────────▶ サービス側が
   リスク大         │            リスク大
                   │  クリック課金型（中間）
                   │  ・反響に連動。企業の納得感は高い
                   │  ・単価×量で売上が決まる＝運用力が効く
                   │
                   │  成功報酬型
                   │  ・決まるまで0円。企業は使いやすい
                  低 ・人材の質と量を自前で抱える必要
```

日本の求人メディア各社は、掲載課金のストック的な安定性を残しつつ、
アグリゲーターに対抗するためクリック課金・成果課金へ寄せてきた、というのが2020年代の総括になる。

## 用語メモ

| 用語 | 意味 |
| --- | --- |
| **掲載課金型** | 求人を掲載した時点で料金が発生する広告モデル。採用できなくても返金されない |
| **成功報酬型** | 採用決定時に課金するモデル。理論年収の一定割合が相場 |
| **CPC（クリック課金）** | クリック1回あたりで課金。Indeed 等の基本形 |
| **応募単価（CPA）** | 広告費 ÷ 応募数。求人広告の効率を測る最重要指標 |
| **採用単価（Cost Per Hire）** | 広告費 ÷ 採用人数。採用担当が最終的に見る数字 |
| **求人アグリゲーター** | 世の中の求人を集約して検索させるサービス。Indeed、求人ボックス、スタンバイ |
| **Indeed PLUS** | 1回の入稿で Indeed と提携媒体へまとめて配信する仕組み（2023年開始） |
| **有効求人倍率** | 求職者1人あたりの求人数。厚労省が毎月公表。1を超えると人手不足側 |
| **スポンサー求人** | 有料で上位表示される求人枠。無料掲載との対比で使う |
