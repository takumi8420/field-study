# HRテックの各領域 ─ 制度改正が需要を作る

このノートで分かること：HRテック（人事業務のソフト化）が**採用・労務・評価などの領域に分かれている理由**と、
それぞれの商売の性格。そしてこの分野の最大の特徴である
**「法律が変わると、全企業が一斉に買わされる」**という需要の作られ方。

## 1. 人事の仕事を時間軸に並べると、領域の地図になる

HRテック（HR Technology）＝人事・労務の業務をクラウドソフトで置き換える分野。
バラバラの製品に見えるが、**従業員が入社してから退職するまでの流れ**に沿って並べると整理できる。

```
 募集   選考   内定・入社     在籍中（毎月くり返す）          異動・評価      退職
  │      │       │                │                            │            │
  ▼      ▼       ▼                ▼                            ▼            ▼
┌──────────────┐┌────────────┐┌──────────────────────────┐┌──────────────┐┌────────┐
│ 求人メディア  ││ 入社手続き ││ 勤怠管理 ─▶ 給与計算      ││ 人事評価     ││ 退職手続│
│ ATS（採用管理）││ 電子申請   ││   ▲          ▲            ││ 目標管理(MBO)││ 離職分析│
│ 適性検査・面接 ││ 労務管理   ││   └─ 打刻・残業・36協定   ││ サーベイ     ││        │
└──────────────┘└────────────┘└──────────────────────────┘└──────────────┘└────────┘
            └──────────── 従業員データベース（タレントマネジメント） ────────────┘
                    ここに全部たまる。だから「誰がDBを押さえるか」が競争の本丸
```

> ポイント：HRテックの競争は**機能競争ではなく「従業員データベースの所有権」の争い**。
> 最初にどの領域から入っても、最後はみな中央の従業員DBを取りに行く。

## 2. 領域別の一覧

| 領域 | やること | 代表的なサービス | 商売の性格 |
| --- | --- | --- | --- |
| **ATS（採用管理）** | 応募者の一元管理、選考ステータス、面接日程調整 | HRMOS採用、ジョブカン採用管理、sonar ATS、Talentio | 採用数に連動。景気の影響を受けやすい |
| **タレントマネジメント** | 従業員のスキル・経歴・評価を可視化し、配置・育成に使う | カオナビ、タレントパレット、HRBrain | 継続利用されやすい。単価が上げやすい |
| **労務管理・人事DB** | 入退社手続き、社会保険の電子申請、年末調整 | SmartHR、ジョブカン労務、freee人事労務 | **制度改正が需要を作る**。解約されにくい |
| **給与計算** | 毎月の給与・賞与計算、明細発行 | 奉行クラウド、マネーフォワード クラウド給与、SmartHR給与計算 | 止められない基幹業務。乗り換えが重い |
| **勤怠管理** | 打刻、残業時間の把握、シフト管理 | KING OF TIME、ジョブカン勤怠、TeamSpirit | 従業員数×月額。導入社数が効く |
| **評価・エンゲージメント調査** | 目標管理、1on1、従業員満足度の定点観測 | モチベーションクラウド、Wevox、Geppo | 経営課題として売る。効果測定が難しい |
| **スキル可視化・学習** | スキルの棚卸し、eラーニング、リスキリング | Schoo、Udemy Business、LMS各種 | → [通信教育・EdTech](../../15_サービス・生活関連/16_通信教育・EdTech/README.md) と重なる |
| **人的資本開示支援** | 開示項目の集計・レポート作成 | 各社が既存製品の拡張として提供 | 制度でできた新領域。まだ小さい |

市場規模は定義で大きく振れるが、参考値として次のとおり。

| 指標 | 数値 | 時点・出所 |
| --- | --- | --- |
| 日本のHRテック市場 | 2025年 約21.6億ドル → 2034年 約39.3億ドル（年率6.87%） | IMARC Group の推計（2026年公表） |
| 国内タレントマネジメントシステム市場 | 2020年 約211億円 → 2026年 約447億円 | 民間調査の推計。定義により幅あり |
| SmartHR の ARR | 2026年7月に300億円を突破（登録社数7万社超） | 同社発表（2026年7月7日） |

ARR（年間経常収益）の考え方や SaaS としての採算は → [SaaSの経済学](../06_ソフトウェア・SaaS/01_SaaSの経済学.md)。

## 3. 制度改正が需要を作る ─ この業界の一番の特徴

普通のソフトは「便利だから買う」。HRテックの労務・勤怠・給与領域は違って、
**「法律が変わったので対応しないと違法になる」から買う**。つまり需要が法改正カレンダーで決まる。

```
 国会・省令で制度改正 ──▶ 施行日が決まる ──▶ 全企業が期限までに対応義務
                                                    │
                        ┌───────────────────────────┴────────────────┐
                        ▼                                             ▼
             自社で対応（人手・Excel・改修）              クラウドで対応（買う）
                        │                                             │
                     中小ほど無理                          ★HRテックの新規需要★
                                                          しかも一度入れたら外せない
```

近年の主な「需要を作った制度」を並べると、この構造がはっきりする。

| 時期 | 制度 | 生まれた需要 |
| --- | --- | --- |
| 2019年4月〜 | 働き方改革関連法（残業上限規制、年5日の有給取得義務） | **勤怠管理**の総入れ替え |
| 2020年〜 | 社会保険手続きの電子申請義務化（大企業） | **労務管理クラウド**の普及 |
| 2022年4月〜 | 育児・介護休業法改正、パワハラ防止義務の全社拡大 | 規程管理・研修 |
| 2023年3月期〜 | 有価証券報告書での人的資本開示が義務化 | **タレントマネジメント／開示支援** |
| 2024年4月〜 | 建設・運輸・医師の時間外上限適用（いわゆる2024年問題） | 業種特化の勤怠・シフト |
| **2026年3月期〜** | 有報の人的資本開示を拡充（人材戦略、給与決定方針、平均年間給与の前年度比増減率） | 人事データの集計・監査対応 |
| **2026年4月〜** | 労働安全衛生法改正で**全事業場にストレスチェック義務化**（規模を問わず） | 健康管理・ストレスチェック機能 |
| **2026年4月〜** | 女性活躍推進法改正で男女賃金差・女性管理職比率の公表義務が拡大 | 属性別の賃金集計 |
| 2026年〜（検討中） | 労働基準法改正（連続勤務上限、勤務間インターバル）は2026年5月時点で法案提出が見送りと報じられる | 前倒しの勤怠改修需要 |

> なぜこれが効くのか：制度対応は**買わない選択肢がない**うえ、
> 対応のために従業員データを1か所に集める必要がある。
> つまり制度改正のたびに、HRテック各社は**無料で背中を押される営業**を受けているのと同じ。

逆に言えば、制度改正が途切れる年は新規需要が細る。
この業界の売上計画は、**法改正カレンダーとほぼ一体**で作られている。

## 4. なぜ「労務」から入る会社が強いのか ─ SmartHR の型

SmartHR は入社手続き・社会保険の電子申請という、**一番地味で一番避けられない業務**から入った。
ここが入口として強いのには理由がある。

```
  ①入社手続きを電子化する        ②結果として、全従業員の
     ＝人事が必ず通る業務           氏名・住所・扶養・給与の
        │                          正確なデータが自動でたまる
        ▼                                   │
  ③そのDBの上に機能を足せる ◀──────────────┘
     ・年末調整（毎年必ず使う）
     ・給与計算（基幹業務に昇格）
     ・従業員サーベイ／タレントマネジメント
     ・従業員ポータル、AIアシスタント
        │
        ▼
  ④1社あたりの単価が上がり、乗り換えコストも上がる
```

SmartHR は2026年7月に ARR 300億円突破を発表し（同社発表）、給与計算と従業員ポータル領域が
伸びを牽引したとしている。2030年に売上1,000億円という目標を掲げ、
コンサルティング会社の買収など、ソフト以外への拡張も進めていると報じられる。

**単価の考え方**：HRテックの多くは PEPM（Per Employee Per Month＝従業員1人あたり月額）で課金する。

```
  年間売上 = 従業員数 × 月額単価 × 12

  例：従業員500人 × 600円/人月 × 12ヵ月 = 360万円/年
      ここに給与計算オプション（+300円/人月）を足すと 540万円/年
      ▲ 顧客企業が成長すれば自動的に増収（＝ネットレベニューリテンションが上がる）
      ▼ 逆に顧客が人員削減すると自動的に減収
```

**顧客の従業員数がそのまま売上になる**ので、HRテックの業績は顧客企業の雇用動向に連動する。
人員削減が広がる局面では、解約されなくても売上が目減りする。ここが他のSaaSと違う点。

## 5. 導入の壁

| 壁 | 中身 |
| --- | --- |
| **データが散らばっている** | 人事DB・勤怠・給与が別ベンダーで、社員番号すら一致しない |
| **給与計算は失敗できない** | 1円でも間違えば全社の信頼を失う。乗り換えが極端に慎重になる |
| **例外的な人事制度** | 日本企業は手当・等級・締め日の例外が多く、標準機能に収まらない |
| **中小企業は紙とExcel** | 買う理由が「便利」では足りない。制度対応が最後の一押しになる |
| **導入するのは人事部門** | ITに強いとは限らず、導入支援（オンボーディング）の人件費がかさむ |

この「標準品に収まらない」問題は日本のSaaS全般の課題でもある → [作り方と売り方](../06_ソフトウェア・SaaS/02_作り方と売り方.md)。

## 6. AIはどこに入っているか

2025〜2026年に各社が投入しているAI機能は、大きく3層に分けられる。

| 層 | 例 | 経済的な意味 |
| --- | --- | --- |
| **入力補助** | 求人原稿の自動生成、スカウト文面の下書き、規程の要約 | 単価を上げにくい。差別化しづらい |
| **判断支援** | 書類選考のスコアリング、離職予兆の検知、配置シミュレーション | データを持つ側が強い。DB保有が効く |
| **業務代行（エージェント）** | 問い合わせ対応、面接日程の自動調整、手続きの自動起票 | **人件費と直接比較される**＝成果課金に向く |

第3層は「席数（シート）課金」と相性が悪い。人が減るほど価値が出る機能を、
人数課金で売ると自社の売上が縮むからだ。このため課金方式の見直しが始まっている
→ [直近トピック_2026](04_直近トピック_2026.md)、[SaaS市場の構造](../06_ソフトウェア・SaaS/03_市場の構造.md)。

## 用語メモ

| 用語 | 意味 |
| --- | --- |
| **HRテック** | 人事・労務業務をクラウドやAIで置き換える分野の総称 |
| **ATS** | Applicant Tracking System。応募者管理システム。選考の進捗を一元管理する |
| **タレントマネジメント** | 従業員のスキル・経歴・評価を可視化し、配置や育成に活かす仕組み |
| **PEPM** | Per Employee Per Month。従業員1人あたり月額の課金方式 |
| **ARR** | Annual Recurring Revenue。年間経常収益。継続課金分の年換算値 |
| **エンゲージメント調査** | 従業員の働きがい・組織への愛着を定点で測るアンケート |
| **人的資本開示** | 人材に関する情報を有価証券報告書等で開示する制度。2023年3月期から義務化 |
| **ストレスチェック** | 労働安全衛生法に基づく心理的負担の検査。2026年4月から全事業場で義務化 |
| **年末調整** | 従業員ごとの所得税を年末に精算する手続き。毎年必ず発生する繁忙業務 |
| **電子申請** | 社会保険・労働保険の手続きをオンラインで行うこと。大企業は義務 |
