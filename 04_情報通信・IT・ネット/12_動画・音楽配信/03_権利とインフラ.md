# ③ 権利とインフラ

このノートで分かること：配信事業者が本当に買っているのは「動画ファイル」ではなく **「送信していい権利」** であること。
そして、その権利を処理する仕組み（JASRAC/NexTone）と、実際に映像を届ける仕組み（CDN）、
その両方を揺さぶっている海賊版と生成AIの問題。

---

## 1. 権利の地図 ── 誰が何を持っているか

著作権法は権利を **「著作権」** と **「著作隣接権」** の二階建てで設計している。
配信するには、**関係する全員から許諾を取る**必要がある。1人でも欠けると配信できない。

| 権利                             | 対象                                               | 持っている人                             | 配信で必要な支分権           |
| -------------------------------- | -------------------------------------------------- | ---------------------------------------- | ---------------------------- |
| **著作権**                       | 脚本・原作・楽曲・歌詞・美術など「創作された表現」 | 作家、作詞作曲家、音楽出版社、原作出版社 | **公衆送信権／送信可能化権** |
| **著作隣接権（実演家）**         | 演技・歌唱・演奏という「行為」                     | 俳優、歌手、演奏家（事務所が窓口）       | 送信可能化権                 |
| **著作隣接権（レコード製作者）** | 録音物そのもの＝**原盤**                           | レコード会社、原盤制作出資者             | 送信可能化権                 |
| **著作隣接権（放送事業者）**     | 放送された番組の信号                               | 放送局                                   | 送信可能化権                 |

**送信可能化権**とは、「サーバにアップロードして、誰でもアクセスできる状態にする権利」のこと。
アップロードした時点で権利が働くので、**誰も再生していなくても無断アップロードは侵害になる**。

```
【ドラマ1本を配信するのに必要な許諾の例】

   原作小説 ──── 出版社／原作者
   脚本    ──── 脚本家
   劇伴音楽 ──── 作曲家＋音楽出版社（JASRAC等経由）
   主題歌  ──── 著作権（JASRAC等）＋ 原盤権（レコード会社）
   出演    ──── 俳優（事務所）×出演者の人数ぶん
   映像    ──── 製作委員会（幹事社が窓口）
   美術・写真 ── 劇中に映り込む絵画・写真の権利者
                   │
                   ▼
        全員から「配信してよい」を取って、はじめて公開できる

  ▲ 「昔の番組が配信されない」理由の大半はこれ。
    当時の契約書に「配信」という概念が無く、取り直しが必要になる。
```

## 2. 権利を「まとめて」処理する仕組み ── JASRAC と NexTone

音楽は使われる場面が多すぎて、**1曲ごとに作詞家へ電話していたら配信が成立しない**。
そこで著作権を預かってまとめて許諾・徴収・分配する事業者が存在する。これが **著作権等管理事業者**。

| 事業者                           | 位置づけ                                               | 数値                                                                                                                              |
| -------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| **JASRAC（日本音楽著作権協会）** | 国内最大。1939年設立の一般社団法人                     | 2025年度の使用料徴収額 **1,523億2千万円**、分配額1,518億5千万円。**いずれも過去最高で、初めて1,500億円を超えた**（2026年5月公表） |
| **NexTone**                      | 2016年発足の民間企業（東証グロース上場）。JASRACの競合 | 著作権使用料の徴収額シェアは **7.8%**（2024年3月期時点、同社開示）                                                                |

JASRAC の2025年度が過去最高になった要因は、**音楽サブスクと動画配信が好調だったインタラクティブ配信**と、
大規模コンサートの増加による演奏使用料の伸びと説明されている。
配信が伸びると、著作権管理事業者の徴収額も連動して伸びる関係にある。

```
【包括契約（ブランケット契約）の考え方】

  配信事業者                         管理事業者
  ┌──────────┐              ┌──────────┐
  │ 管理楽曲をまとめて  │  ──許諾──▶  │ JASRAC       │
  │ 使ってよい          │              │ NexTone      │
  │                      │  ◀─使用料──  │              │
  │ 代わりに             │              │  ├ 手数料を控除 │
  │ 「売上の◯%」または   │              │  └ 再生実績に基づき│
  │ 「1再生あたり◯円」   │              │     分配        │
  │ を払う               │              └──┬───────┘
  └──────────┘                  ▼
                                     音楽出版社 → 作詞家・作曲家

  ▲ 重要：包括契約でカバーされるのは **著作権だけ**。
    **原盤権（レーベルの権利）は別途、直接交渉が必要**。
    音楽サブスクの支払いの大半が原盤側に行くのはこのため。
```

> ポイント：**「JASRACに払ったから音楽を自由に使える」は誤り**。
> 配信で音源をそのまま流すなら、原盤権者（レコード会社）の許諾が別に要る。
> 権利処理でトラブルになるのはほぼ必ずこの線引きのところ。

配信事業者向けの使用料は「インタラクティブ配信」の使用料規程で定められており、
**売上の一定率と、1再生あたりの最低額の高い方**といった形で設計されていることが多い。

## 3. 映像を届ける仕組み ── CDN・トランスコード・ABR

権利を買っても、届かなければ商売にならない。配信の技術側は3層で理解すると早い。

```
【動画が視聴者に届くまで】

 ① 素材        ② トランスコード（変換）        ③ 配信
 ┌──────┐   ┌────────────────┐   ┌─────────┐
 │ 制作会社  │──▶│ 1本を十数種類に作り分け     │──▶│ オリジン    │
 │ からの    │   │ 4K / 1080p / 720p / 480p... │   │ サーバ      │
 │ マスター  │   │ × コーデック（H.264/HEVC/  │   │   │         │
 │ 映像      │   │    AV1）× 音声トラック     │   │   ▼         │
 └──────┘   │ ＋ 字幕・吹替・DRM暗号化    │   │ CDN         │
                  └────────────────┘   │ (世界各地の  │
                                                │  キャッシュ) │
                                                └──┬──────┘
                                                      ▼
                                             視聴者（スマホ／CTV）
                                                回線状況に応じて
                                                ABRが画質を自動で切替
```

| 用語                                  | 何をするものか                                                                      | なぜコストに効くか                                                                  |
| ------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **トランスコード**                    | 1本のマスター映像を、解像度・ビットレート・コーデック違いの多数のファイルに変換する | 同じ作品を十数バージョン作るので、**計算資源と保管容量が本数×バージョン数で膨らむ** |
| **ABR（アダプティブ・ビットレート）** | 視聴者の回線速度に合わせて画質を自動で切り替える                                    | 途切れを防ぐ＝解約を防ぐ。同時に、高画質ほど帯域費が増える                          |
| **CDN**                               | 世界各地のキャッシュサーバから配信し、距離と混雑を減らす                            | **配信費の主要部分**。転送量（GB）課金なので、視聴時間に比例して増える              |
| **オリジンサーバ**                    | 大元のファイルを置く場所                                                            | CDNがヒットしなかった分だけ負荷がかかる                                             |
| **DRM**                               | 暗号化してライセンスを持つ端末だけが再生できるようにする                            | Widevine／FairPlay／PlayReady の3方式への対応が必要で、開発コストがかかる           |

**コスト感の要点**：CDN の単価は年々下がっているが、**画質の向上（HD→4K）と視聴時間の増加が単価下落を上回る**ため、
配信費の総額は減らない。大手はトラフィック量を武器に単価交渉するか、自前のCDNを持つ方向に進む。
この負荷は最終的に [データセンター](../03_データセンター/README.md) と
[通信キャリア](../01_通信キャリア/README.md) の設備投資に転嫁される。

## 4. 海賊版対策 ── 技術だけでは止まらない

配信の商品は「複製がタダでできるデータ」なので、海賊版は構造的な宿命である。

CODA（コンテンツ海外流通促進機構）の推計では、
日本発コンテンツの **オンライン上のデジタル海賊版被害額は2025年で約5.7兆円**。
2022年調査の約2.0兆円から **3年で約3倍**に拡大したとされる（経産省委託調査、2026年1月公表）。
加えて2025年から調査を始めた **偽キャラクターグッズの被害額は約4.7兆円**。

※ これらは消費者アンケートに基づく推計値であり、実際の逸失利益と同額ではない点に注意。

| 対策                                                | 中身                                                                   | 限界                                                           |
| --------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------- |
| **DRM＋透かし（フォレンジック・ウォーターマーク）** | 端末ごとに見えない識別情報を埋め、流出元を特定する                     | 画面を別カメラで撮る「カムコーディング」は止められない         |
| **リーチサイト規制**（2020年改正著作権法）          | 侵害コンテンツへのリンクを集めたサイト・アプリの運営を規制             | 運営者が海外にいると執行が難しい                               |
| **ダウンロード違法化の拡大**（2021年施行）          | 違法にアップされた著作物と知りながらダウンロードする行為を規制         | ストリーミング視聴は対象外                                     |
| **削除要請の自動化**                                | 自動コンテンツ監視・削除センターの運用など、権利者団体が共同で削除要請 | イタチごっこ。新規ドメインで即復活する                         |
| **広告出稿の遮断**                                  | 海賊版サイトの収入源である広告を止める（業界団体の取り組み）           | 詐欺広告など、正規でない広告主が残る                           |
| **ブロッキング**                                    | ISPにアクセス遮断させる案                                              | 通信の秘密との関係で国内では慎重論が強く、恒久制度化していない |

> ポイント：**海賊版に勝つ最も確実な手段は「正規が便利で安いこと」**。
> 音楽業界がサブスクで売上を回復した経緯（→ [②](02_音楽配信の経済.md)）が最大の証拠で、
> 動画でも「見たい作品が分散し、契約が増えるほど海賊版に戻る」傾向が指摘されている。

## 5. 生成AIという新しい権利処理の問題

生成AIは、**この業界の権利処理の前提を2か所で壊した**。

### (1) 学習段階 ── 許諾なしに使ってよいのか

日本の著作権法 **第30条の4** は、「著作物に表現された思想又は感情の享受を目的としない利用」
（＝情報解析など）については、原則として権利者の許諾なく利用できると定める。
機械学習はこれに当たると整理されるのが一般的だが、無制限ではない。

文化審議会著作権分科会「AIと著作権に関する考え方について」（2024年3月）と
文化庁のチェックリスト＆ガイダンス（2024年7月）の要点を整理すると、次のようになる。

| 段階             | 原則                                             | 侵害になりうる場合                                                                                       |
| ---------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| **学習（開発）** | 情報解析目的なら原則OK（30条の4）                | 特定の作品の表現を出力させる目的での学習／**権利者の市場を直接害する利用**（例：作風データセットの代替） |
| **生成・利用**   | 生成する行為自体は私的使用等で許される場合がある | **生成物を配信・販売する**行為は権利制限の外。既存作品との**類似性＋依拠性**があれば侵害                 |
| **権利者の救済** | ―                                                | 侵害物の生成・配信の差止請求、生成物の廃棄請求が可能                                                     |

**類似性＋依拠性**という2条件がポイント。「似ている」だけでは足りず、
「元の作品を知って（AIが学習して）作られた」ことが必要になる、という枠組みで議論されている。

### (2) 分配段階 ── ストリーミング詐欺という新種の攻撃

音楽サブスクの分配がプロラタ方式（→ [②](02_音楽配信の経済.md)）である以上、
**総再生数を水増しすれば、他人の取り分を自分に移せる**。
生成AIは、その水増し用の楽曲を無限に安く作れてしまう。

```
【AI×プロラタ方式の脆弱性】

 正常                          攻撃
 プール 7億円                  プール 7億円（変わらない）
 ÷ 総再生 10億回               ÷ 総再生 13億回（うち3億回はBotによる偽再生）
 = 0.70円／再生                = 0.54円／再生
                                        │
 正規アーティストの取り分 ────────┘ 目減りする
 攻撃者は AI量産曲 × Bot再生 で そのぶんを持っていく

 ▲ 誰かが盗んでいるのではなく、**分母を膨らませて全員から薄く抜く**。
   だから発見が遅れる。
```

Spotify は2025年9月に新しいAI音楽ポリシーを発表し、
**過去1年で7,500万曲以上の「スパム的な楽曲」を削除した**と公表した。
同ポリシーには、①新しい音楽スパムフィルター、②許諾のない声のクローンの削除、
③楽曲のどの部分にAIを使ったかを示すクレジット表示、が含まれる。

日本では、**AIのみで生成した楽曲をJASRAC等に信託登録することは現状一般に難しい**とされ、
メロディの調整や編曲指示といった人間の創作的関与が必要、という解釈が広がっている
（法解釈は流動的で、最新は文化庁の資料で確認すること）。

## 6. この構造から言えること

1. 配信事業者は **権利のポートフォリオを運用する会社**であって、技術の会社ではない
2. **著作権と原盤権を分けて考えられるかどうか**が、この業界の話が分かるかどうかの分水嶺
3. インフラ（CDN・トランスコード）は**コモディティ化した代わりに、量が効く固定費**になった
4. 海賊版は執行だけでは止まらず、**正規サービスの便利さと価格**が最大の対策
5. 生成AIは「学習の合法性」と「分配の公平性」の**2つの別問題**を同時に持ち込んだ。
   前者は法解釈、後者はプラットフォームの運用でしか対処できない
   → [④ 直近トピック](04_直近トピック_2026.md)、[生成AI](../../01_注目テーマ/01_生成AI/README.md)

## 用語メモ

| 用語                                 | 意味                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| **公衆送信権**                       | 著作物を公衆に送信する権利。配信はここに当たる                                       |
| **送信可能化権**                     | サーバへアップして誰でもアクセスできる状態にする権利。**アップした時点**で働く       |
| **著作隣接権**                       | 実演家・レコード製作者・放送事業者に認められる権利。著作権とは別建て                 |
| **原盤権**                           | 録音物（マスター音源）に対する権利。レコード製作者が持つ                             |
| **著作権等管理事業者**               | 権利者から著作権を預かり、まとめて許諾・徴収・分配する事業者。JASRAC、NexTone など   |
| **包括契約（ブランケット契約）**     | 管理楽曲をまとめて利用できる契約。使用料は売上比例などで決める                       |
| **インタラクティブ配信**             | 利用者の求めに応じて送信する形式。オンデマンド配信の法令上の呼び方                   |
| **トランスコード**                   | 映像を複数の解像度・ビットレート・コーデックに変換する処理                           |
| **ABR**                              | Adaptive Bitrate。回線状況に応じて画質を自動で切り替える仕組み                       |
| **CDN**                              | Content Delivery Network。各地のキャッシュサーバから配信し、遅延と負荷を減らす仕組み |
| **DRM**                              | Digital Rights Management。暗号化して正規端末だけが再生できるようにする技術          |
| **フォレンジック・ウォーターマーク** | 端末ごとに見えない識別情報を埋め込み、流出元を特定する仕組み                         |
| **リーチサイト**                     | 侵害コンテンツへのリンクを集約したサイト。2020年改正で規制対象になった               |
| **著作権法30条の4**                  | 享受を目的としない利用（情報解析など）を原則自由とする規定。AI学習の根拠とされる     |
| **類似性・依拠性**                   | 著作権侵害の判断基準。「似ている」ことと「元作品に基づいて作られた」ことの両方が必要 |
