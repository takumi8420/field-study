# 変化と論点 ── 人月モデルはどこまで持つのか

このノートで分かること：クラウド移行でSIerの売上から何が消えたのか、内製化はどこまで本物か、
DX案件でのコンサル化、SAP「2027年問題」という一時的な特需、
そして**生成AIによる開発効率化が人月モデルに何をもたらすか**という最大の論点。

## 1. 4つの変化が同時に効いている

```
      ① クラウドシフト          ② 内製化
      ハード・ライセンス         ユーザー企業が
      再販売上が消える           自分で作り始める
              ＼                      ／
               ＼                    ／
                ▼                  ▼
            ┌──────────────────────────┐
            │  人月モデル（工数×単価）  │
            └──────────────────────────┘
                ▲                  ▲
               ／                    ＼
              ／                      ＼
      ③ コンサル化              ④ 生成AI
      上流を取れないと           工数そのものが減る
      利益が出ない              ＝売上が減る
```

①②は**すでに起きたこと**、③は**各社の対応策**、④は**これから効くこと**。

## 2. クラウドシフト ── 「売上が消える」という現象

従来のシステム構築では、SIerがサーバ・ストレージ・ソフトライセンスを仕入れて顧客に売っていた。
クラウドに移ると、顧客はAWS/Azure/Google Cloudに直接利用料を払う。

```
 【オンプレミス時代】                     【クラウド時代】
  顧客 ──▶ SIer ──▶ ハードメーカー       顧客 ──┬─▶ クラウド事業者（従量課金）
      1億円      8,000万円                 2,000万円│   ← SIerの売上には計上されない
                                                    └─▶ SIer（設計・移行・運用代行）
  SIer売上：1億円（粗利2,000万円）          SIer売上：2,000〜4,000万円
                                            粗利率は上がるが、売上は大きく減る
```

| 論点           | 中身                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| 売上の消失     | ハード・ライセンス再販という**低粗利だが巨額の売上**が丸ごと外へ出る             |
| 利益率への影響 | 低粗利売上が減るので、**利益率は上がる**が利益額は必ずしも増えない               |
| 構築工数の減少 | サーバの調達・設置・設定という工数が消える。数か月かかった作業が数時間に         |
| 新しい収益源   | クラウドのリセール（代理販売）、マネージドサービス、移行（マイグレーション）案件 |
| 利益相反       | クラウド移行を勧めると自社の売上が減る。だから提案が遅れたと批判されてきた       |

> ポイント：SIerにとってクラウドは**技術の問題ではなくビジネスモデルの問題**だった。
> 「SIerがクラウドに消極的だった」と言われる理由はここにある。
> → [クラウド・IaaS](../04_クラウド・IaaS/README.md)、[データセンター](../03_データセンター/README.md)

なお、クラウド移行の受け皿として**移行案件そのものは特需**になっている。
レガシーシステムの刷新（いわゆる「2025年の崖」問題）は2026年時点でもなお継続中で、
IDC Japanは国内ITサービス市場が2030年に10兆円を超えると予測している（2026年3月、推計）。

## 3. 内製化 ── 進んでいるが、限界もある

ユーザー企業が自社でエンジニアを採用し、自分で作る動きは実際に広がった。

| 内製化が進んだ領域                       | 内製化が進みにくい領域                           |
| ---------------------------------------- | ------------------------------------------------ |
| 顧客向けWeb・アプリ（差別化に直結）      | 勘定系・生産管理などの基幹系（規模と責任が重い） |
| データ分析基盤、AI活用                   | 法改正対応・制度対応（専門知識が必要）           |
| 社内の小規模業務ツール（ノーコード含む） | 24時間365日の運用監視                            |
| アジャイルで作り変え続けるもの           | 数百人規模を数年動員するプロジェクト             |

内製化の壁は、結局**人が採れないこと**である。
経済産業省の試算では2030年時点で約16万〜79万人のITエンジニア不足が見込まれる（2019年公表、推計）。
[日本のIT産業の構造](01_日本のIT産業の構造.md) で見たとおり、エンジニアの7割はベンダー側にいるので、
ユーザー企業が内製化するには**ベンダーから引き抜くしかない**。

```
  ユーザー企業の内製化の現実

  ①「内製する」と宣言       ②エンジニア採用    ③採れない／定着しない
        ▼                        ▼                   ▼
   情シス部門を拡張  ──▶  給与水準・評価制度  ──▶  結局SIerの
                           が合わない              「内製化支援」を買う
                                                        ▲
                             ここが新しい市場になっている（準委任で伴走）
```

つまり内製化はSIerにとって**脅威であると同時に新しい商品**でもある。
「内製化支援」「アジャイル伴走」「技術者の育成支援」は準委任契約で提供され、単価も高い。

## 4. コンサル化 ── 上流を取らないと利益が出ない

各社が揃って掲げているのが「上流シフト」である。理由は単純で、**上流の単価が高いから**。

| 工程             | 誰がやるか         | 単価の目安（月、推計） | 生成AIの影響 |
| ---------------- | ------------------ | ---------------------- | ------------ |
| 構想・企画       | コンサル、上流SE   | 200〜400万円           | 小さい       |
| 要件定義         | 上流SE             | 120〜180万円           | 中程度       |
| 基本設計         | SE                 | 90〜130万円            | 中程度       |
| 詳細設計・製造   | プログラマ、下請け | 50〜90万円             | **大きい**   |
| 単体・結合テスト | テスト要員、下請け | 40〜70万円             | **大きい**   |
| 運用・保守       | 運用要員           | 40〜80万円             | 中程度       |

- 上流は**顧客の業務と経営を理解していないとできない**ので、参入障壁が高く価格も落ちにくい
- 下流（製造・テスト）は標準化しやすく、オフショア・下請け・そしてAIに置き換えられやすい
- 大手SIerが「コンサル会社を買収する」「コンサル職種を新設する」のはこの狙い
- ただし**外資コンサル系との正面衝突**になる → [プレイヤーの類型](03_プレイヤーの類型.md)、
  [コンサルティング](../../15_サービス・生活関連/04_コンサルティング/README.md)

## 5. SAP「2027年問題」── 期限のある特需

**SAP ERP 6.0（ECC 6.0）の標準保守が2027年末に終了する**。
国内には約2,000社のSAP導入企業があるとされ、後継の「S/4HANA」等へ移行するか、別のERPに替えるかの判断を迫られている。

```
   2027年末：標準保守終了
       │
   ────┼──────────────────────────────▶
       │
   移行に必要な期間：中堅で1〜2年、大企業で2〜4年
       ↑
   2026年時点で未着手だと、間に合わない企業が出る
   → 「駆け込み需要」で人材が取り合いになる
```

| 論点               | 中身                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------- |
| 移行の進捗         | 2024年時点で移行完了は6割程度、国内でS/4HANA移行を支援できるベンダーは約100社と報じられる（推計値を含む） |
| 人材の枯渇         | SAPコンサルは慢性的に不足。単価が跳ね上がっている                                                         |
| SIerにとっての意味 | **期限つきの大型特需**。ただし2028年以降に反動で需要が落ちるリスクがある                                  |
| 移行の中身         | 単なるバージョンアップではなく、アドオン（独自改修）をどこまで捨てるかの業務改革                          |
| 延長保守           | 有償の延長保守という選択肢もあるが、コストと将来の詰みを先送りするだけとも言われる                        |

**日本固有の事情**：日本企業はSAPを標準のまま使わず、自社業務に合わせて大量のアドオンを作り込んだ。
この「作り込み」が移行コストを膨らませている。**業務をパッケージに合わせる**という発想が弱かったことの請求書が来ている。

## 6. 生成AI ── 効率化は売上減に直結する

ここが最大の論点である。人月モデルでは、**工数が売上そのもの**なので、
効率化に成功するほど自社の売上が減る。

```
  【従来】   工数 1,000人月 × 単価100万円 ＝ 売上 10億円

  【AI活用で生産性が2倍になったら】

   (a) 工数500人月 × 単価100万円 ＝ 売上 5億円   ← 半分になる
   (b) 工数500人月 × 単価200万円 ＝ 売上10億円   ← 顧客が納得するか？
   (c) 固定価格 10億円で受注し、原価を半分に     ← 成果報酬・固定価格モデル
```

| シナリオ                 | 起きること                                                                |
| ------------------------ | ------------------------------------------------------------------------- |
| (a) 単価据え置き・工数減 | **売上と利益が減る**。顧客は値下げを要求する。最も起こりやすい            |
| (b) 単価を上げる         | 「同じ成果なのになぜ単価が上がるのか」を説明できない限り通らない          |
| (c) 固定価格・成果報酬へ | 効率化の果実を自社に残せる。ただし**見積りリスクを全部背負う**            |
| (d) 案件数を増やす       | 1件あたりの工数が減っても件数が増えれば総額は維持できる。需要が伸びる前提 |

各社の2026年時点の動き（『週刊BCN+』2026年6月ほか）：

- **TIS**：2030年3月期までに**生産性50%向上**を目標に設定
- **NTTデータ**：AIエージェント開発とAIプラットフォーム構築を成長戦略の柱に
- **NRI**：複雑な大規模システム向けの独自開発モデルを2030年度までに実用化する計画
- 共通するのは「**人的リソースを上流工程へシフトする**」という言い方。
  下流の工数が減る前提で、人を上流に配置換えするという戦略

> ポイント：AIで生産性が上がった分を、**値下げとして顧客に返すのか、利益として自社に残すのか**。
> これを決めるのは技術ではなく契約形態である。だから「脱・人月」が急務だと言われている。

ただし冷静に見ると、AIが効くのは**コード生成・テスト・ドキュメント作成**が中心で、
要件の合意形成、他システムとの調整、移行計画、障害時の責任といった**人と組織の仕事**には効きにくい。
SIerの仕事の相当部分は後者である、というのが業界側の反論になる。

## 7. 人月モデルの代替案と、それぞれの壁

| 代替モデル               | 中身                                 | 壁                                                 |
| ------------------------ | ------------------------------------ | -------------------------------------------------- |
| **固定価格・成果報酬**   | 成果物や業務成果に対して課金         | 見積りリスクを全部背負う。失敗すると大赤字         |
| **サブスクリプション**   | 月額でシステムと運用をまとめて提供   | 初期投資を自社で持つ必要がある。資金負担が重い     |
| **自社プロダクト／SaaS** | 作ったものを多数の顧客へ複製して売る | 商習慣・組織文化が受託と真逆。開発投資の回収が長い |
| **従量課金**             | 取引件数・ユーザー数に連動           | 顧客のビジネスが縮むと自社も縮む                   |
| **共同利用型**           | 同業他社が同じ基盤を使う             | 競合同士を同じ基盤に乗せる調整が難しい             |

日本のSIerが最も苦手なのは**プロダクトを作って売ること**である。
受託は「顧客の要望どおりに作る」仕事、プロダクトは「顧客の要望を切り捨てて標準を決める」仕事で、
必要な判断が正反対になる。組織の評価制度も稼働率で回っているため、
プロダクト開発は「稼働していない人」として扱われてしまう。

## 8. 労働市場の変化

- エンジニアの**転職が普通になった**。特にクラウド・AI系は売り手市場で、単価も年収も上昇
- 2026年時点でSES単価は上昇傾向。AI/ML・LLM関連スキルは月100万円超が標準化しつつあると報じられる（推計）
- 一方で、**レガシー言語（COBOL等）の技術者は高齢化**。人がいなくなることが移行の圧力になっている
- 取適法（2026年1月施行）で下請け取引の適正化が進めば、**中間マージンが削られ、現場の単価は上がる**方向に働く
  → [直近トピック_2026](05_直近トピック_2026.md)

## 9. まとめ：2030年ごろのSIerはどうなるか

```
              売上規模
                ▲
   従来型SI ────┼──────╲
   （工数販売） │        ╲___ 縮小（AI＋内製化）
                │
   上流・コンサル├──────────╱ 拡大（単価が高い）
                │        ╱
   運用・保守    ├────────── 横ばい〜微増（ストックは強い）
                │
   自社プロダクト├──╱ ごく一部の会社だけ成功
                └─────────────────────────▶ 時間
```

- **消えはしない**。基幹系を作り替え、動かし続ける仕事は残る
- ただし**工数を売る部分は確実に縮む**。人を増やして売上を増やすモデルは効かなくなる
- 勝敗を分けるのは、**上流を取れるか**と**効率化の果実を自社に残す契約に変えられるか**の2点

| **アドオン**                 | パッケージソフトに独自機能を追加すること。日本企業は作り込みが多く移行の重荷に                   |

| **脱・人月**                 | 工数課金から成果・価値に応じた課金へ移すこと。業界共通の課題認識                                 |
