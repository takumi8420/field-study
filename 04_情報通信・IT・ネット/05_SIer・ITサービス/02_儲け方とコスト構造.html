このノートで分かること：SIerの売上がどんな式で決まるのか、原価の中身（人件費と外注費）、
固定価格の請負がなぜ赤字プロジェクトを生むのか、保守運用というストック収益の位置づけ、

1. 売上の式は1行で書ける

   売上高 ＝ 人月単価 × 稼働率 × 要員数 × 12か月
              （円/人月）   （%）    （人）

   例：平均単価 90万円 × 稼働率 92% × 要員 1,000人 × 12
     ＝ 約 99億円／年

この式は、人材派遣 や
コンサルティング とまったく同じ構造である。
違うのは「成果物の完成責任を負う一括請負が混ざる」点だけ。

変数 上げる方法 上げにくい理由
人月単価上流工程を取る、希少スキル、元請けになる顧客の予算は前年比で決まる。値上げ交渉が年1回しかない
稼働率案件間の空き（ベンチ）を減らす100%にすると教育・研究の時間が消える。実務上の上限は9割台
要員数採用、外注、M&A採用競争が激しい。育成に2〜3年かかる

ポイント：この式に「作ったものが売れる」という項がない。
同じソフトを2社に売っても売上は2倍にならない（工数が2倍かかるので）。
ソフトウェア本来の複製の効きが、この商売モデルでは効かない。

2. 1人月の中身を分解する

エンジニア1人を1か月客先に出したときの、元請け目線の典型的な内訳（業界の一般的なレンジからの模式。
実際は案件・会社で大きく振れる）。

項目 金額イメージ 説明
顧客への請求単価（人月単価）100万円契約書に書かれる金額
─ 自社要員の場合：人件費（給与＋法定福利＋賞与）55〜65万円年収600万円のSEなら月50万円＋会社負担分
─ 外注要員の場合：外注費60〜75万円2次請けへの支払い。ここが元請けの主な原価
間接費（管理部門、オフィス、教育）15〜20万円稼働していない時間もここに乗る
残り＝営業利益5〜15万円利益率にして5〜15%
  顧客が払う 100万円
  ├──────────────────────────────┬──────────┬──────┐
  │  人件費 or 外注費 60〜75万円  │ 間接費   │ 利益 │
  └──────────────────────────────┴──────────┴──────┘
                                              ▲
                              薄い。ここが数%ぶれると赤字になる
  • 原価の大半が人なので、設備投資も在庫もほぼない。だから資本はあまり要らない
  • 逆に言えば、固定費を圧縮して利益を出す余地が小さい。稼働率が命
  • 単価相場は2026年時点でSES市場の目安として初級40万〜中堅60万〜シニア80万〜スペシャリスト100万円超（各種調査・事業者公表、いずれも推計）。
    AI/ML・クラウド系は上昇が著しく、月100万円超が珍しくないと報じられる

3. 原価に占める外注費 ── ここが日本のSIerの最大の特徴

大手SIerの売上原価のうち、外注費（協力会社への支払い）が3〜5割を占めるのが一般的とされる。
つまり、大手の損益は「自社エンジニアの生産性」よりも「外注をいくらで調達できるか」で動く。

   売上原価の構成（大手元請けの模式）

   ┌────────────────┬──────────────────────┬────────┬──────┐
   │ 自社人件費 30% │   外注費 40%         │ 経費   │ 仕入 │
   │                │ （協力会社への支払） │ 15%    │ 15%  │
   └────────────────┴──────────────────────┴────────┴──────┘
                          ▲
       ここが上がると利益が消える。エンジニア不足＝原価インフレ

この構造から、2つの帰結が出る。

  1. エンジニアの賃上げは元請けにとって原価上昇。単価転嫁できなければ利益率が落ちる
  2. 需要が減ると外注を切って自社は守れる。だから元請けは不況に強く、下請けが振れを全部かぶる
    → 構造の背景は 日本のIT産業の構造

4. 固定価格請負のリスク ── 赤字プロジェクトはこう生まれる

一括請負は金額が先に決まる。工数が増えても追加請求できない（契約変更に応じてもらえるとは限らない）。

   見積時          着手          中盤             終盤
   100人月 ────▶ 120人月 ────▶ 180人月 ────▶ 260人月
     │             │             │               │
   受注額         仕様の追加    設計漏れ発覚     テストで
   1.0億円        （無償対応）  （手戻り）       バグ大量
     │                                             │
     └── 売上は1.0億円のまま ──────────────────────┘
          原価 2.6億円 ＝ 損失 1.6億円 ＝【不採算案件】
赤字化の典型パターン 何が起きているか
要件の膨張「当然入ってると思った」機能を無償で作らされる。契約書の範囲記述が甘い
見積りの楽観受注を取りたい営業が工数を削って提示。技術部門の見積りと乖離
キーパーソン依存できる人が抜けた瞬間に進まなくなる
顧客側の意思決定が遅い仕様確定が遅れ、後工程が圧縮される
移行・連携の見落とし既存システムからのデータ移行、他社システムとの接続が想定外に重い
  • 会計上は、収益認識に関する会計基準（2021年4月以降、原則適用）により、
    受託開発は進捗度に応じて売上を計上する（旧・工事進行基準の考え方を引き継ぐ）
  • 損失が見込まれた時点で、受注損失引当金として先に損失を計上する義務がある。
    大手SIerの決算で「不採算案件で◯◯億円の損失」と出るのはこれ
  • 見積りの不確実性が高い領域（新技術・上流不明確）では、一括請負を避けて準委任で入るのが実務の防御策

5. ストック収益としての保守・運用

SIerの収益は、単発の開発（フロー）だけではない。作ったあとの保守・運用がストックになる。

 【フロー】開発案件            【ストック】保守・運用・クラウド運用代行
  ┌─────────────┐              ┌──────────────────────────────┐
  │ 1年〜3年で完了 │ ──────▶  │ 5年〜15年、毎年ほぼ同額が入る  │
  │ 金額は大きい   │  引渡し   │ 金額は開発費の10〜20%／年が目安 │
  │ 赤字リスク大   │           │ 利益率は開発より安定・高い傾向 │
  └─────────────┘              └──────────────────────────────┘
        ▲                                      │
        │  次の大型更改（10年前後）で再びフローへ │
        └──────────────────────────────────────┘
収益タイプ 内容 経済的な性質
システム開発（SI）新規構築・更改フロー。金額大、変動大、赤字リスクあり
保守障害対応、法改正対応、小規模改修ストック。年間契約で更新される
運用（アウトソーシング）監視、バッチ運用、ヘルプデスク、データセンター利用ストック。人数×期間で長期に固定
ハード・ソフト再販サーバ、ネットワーク機器、ライセンス薄利。売上は大きいが利益はほぼ乗らない
自社サービス／SaaS自社開発の製品を多数の顧客へ理想形だが日本のSIerでは比率が小さい

顧客を握り続ける最大の武器は、実はここ。動いているシステムの中身を知っている会社を
他社に切り替えるのは高くつくので、保守を持つ会社が次の更改案件でも有利になる（スイッチングコスト）。

6. ライセンス再販とハード再販 ── 売上は膨らむが利益は乗らない

  • SIerはサーバ、ストレージ、DB（Oracle等）、ERP（SAP等）を仕入れて顧客に売る
  • 粗利率は数%〜十数%。売上の見かけを大きくするだけで利益貢献は小さい
  • クラウドへ移ると、この再販売上がAWS/Azure/Google Cloudの利用料に置き換わり、SIerの売上から消える
    → クラウド・IaaS、詳細は 変化と論点
  • 代わりにクラウドのリセール（代理販売）やマネージドサービスで取り返そうとするのが各社の戦略

7. なぜ営業利益率が10%前後で頭打ちなのか

理由 説明
規模の経済が効かない売上を2倍にするには人を2倍にするしかない。固定費が薄まらない
原価が人で、インフレするエンジニアの賃金は上がり続ける。単価転嫁は年1回の交渉に依存
顧客が価格を知っている人月という単位で買うので、顧客は「何人×何か月」で原価を推定できる。利益を隠せない
競合が同じ構造差別化しにくい。入札では価格勝負になりやすい（特に官公庁案件）
不採算案件が定期的に出る数年に一度、大型案件の損失で利益が吹き飛ぶ
再販売上が利益を薄める低粗利のハード・ライセンス売上が分母を膨らませる

比較として、製品を複製して売るソフトウェア企業（営業利益率20〜40%）、
クラウド事業者（同20〜30%）とは桁が違う。人で稼ぐ商売の上限がここにある。

実績（2026年3月期・連結）

企業 売上高 営業利益 営業利益率 備考
NTTデータグループ5兆46億円4,882億円約9.8%売上高が初の5兆円超。営業利益は50.7%増
NEC3兆5,827億円3,599億円約10.0%増収増益（営業利益40%増）
富士通3兆5,029億円3,483億円約9.9%減収だが営業利益31%増
野村総合研究所8,147億円582億円約7.1%海外事業の減損（1,000億円近く）で大幅減益
TIS5,964億円762億円約12.8%国内中心・高収益。上流と運用の比率が高い

出典：『週刊BCN+』2026年6月1日「主要SIerの2026年3月期決算」、日経クロステック、各社IR。
NEC・富士通はIT以外の事業（ネットワーク機器、電子部品等）を含むため純粋比較ではない。

読み取り：どの大手も概ね10%前後に収束する。TISのように国内特化で運用比率を高めると10%台前半まで行くが、
20%を超える会社は出てこない。これが人月モデルの構造的な天井である。

8. この商売の損益分岐を感覚で掴む

   利益
    ▲
    │                     ／
    │                  ／
  0 ┼───────────────●──────────────▶ 稼働率
    │            ／  85%
    │         ／
    │      ／
    ▼   ／
   損失

   ・稼働率が数ポイント落ちるだけで利益が消える
   ・人件費は稼働率に関係なく出ていく（≒固定費）
   ・だから案件が切れそうな時期に、値引きしてでも席を埋める動機が働く

これが期末の駆け込み値引きや、低単価でも受ける行動の説明になる。
「赤字でも受けたほうがマシ」という判断は、この構造では合理的になってしまう。
