# SIer・ITサービス

- 大分類: 情報通信・IT・ネット
- 状態: done
- 更新日: 2026-09-20

企業・官公庁の業務システムを、要件定義から設計・開発・運用まで一括して請け負う産業。
売っているのはソフトウェア製品ではなく**技術者の稼働時間（人月）**であり、損益の構造は
IT業というより [人材派遣](../../15_サービス・生活関連/01_人材派遣/README.md) や
[コンサルティング](../../15_サービス・生活関連/04_コンサルティング/README.md) に近い。
**日本のITエンジニアの約7割がユーザー企業ではなくベンダー側に所属している**という日米の構造差が、
この業界のほぼすべての特徴（多重下請け、人月商売、内製化の遅れ、クラウド移行の鈍さ）を説明する。

## 1. 業界の定義・範囲

**SIer（システムインテグレーター）**＝ハードウェア・ソフトウェア・ネットワークを組み合わせ、
顧客の業務システムを設計・構築し、動かし続ける事業者。**和製英語**であり、海外では
IT services / systems integration と呼ぶ。

| 区別すべき言葉                       | 中身                                                                                                   |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **システムインテグレーション（SI）** | 個別企業の要件に合わせてシステムを作る。**このフォルダの中心**                                         |
| **SES**                              | 準委任契約で技術者を客先に常駐させる。成果物ではなく稼働時間を売る                                     |
| **ITアウトソーシング**               | システムの運用・監視・ヘルプデスクを長期契約で請け負う                                                 |
| **パッケージ／SaaS**                 | 作ったものを多数の顧客に複製して売る → [ソフトウェア・SaaS](../06_ソフトウェア・SaaS/README.md)        |
| **クラウド（IaaS/PaaS）**            | 計算資源をサービスとして売る → [クラウド・IaaS](../04_クラウド・IaaS/README.md)                        |
| **ITコンサルティング**               | 何を作るかを決める上流 → [コンサルティング](../../15_サービス・生活関連/04_コンサルティング/README.md) |

```
  ユーザー企業（発注者）
        │  「こういう業務をシステム化したい」
        ▼
  ┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
  ┃  ★SIer・ITサービス★                          ┃
  ┃  要件定義 → 設計 → 開発 → テスト → 運用保守   ┃
  ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛
     │            │              │           │
     ▼            ▼              ▼           ▼
  コンサル     パッケージ      クラウド    データセンター
  （上流）     ／SaaS          ／IaaS      （箱と電気）
                                            ▲
                          この層がSIerの「材料」であり「競合」でもある
```

**隣接領域との境界**：作る対象がSaaSに置き換わると [ソフトウェア・SaaS](../06_ソフトウェア・SaaS/README.md)、
基盤が自社設備からクラウドに移ると [クラウド・IaaS](../04_クラウド・IaaS/README.md) と
[データセンター](../03_データセンター/README.md)、上流に寄ると
[コンサルティング](../../15_サービス・生活関連/04_コンサルティング/README.md)、
人を貸す商売としては [人材派遣](../../15_サービス・生活関連/01_人材派遣/README.md)、
業務ごと請け負う形は [アウトソーシング・BPO](../../15_サービス・生活関連/03_アウトソーシング・BPO/README.md)、
セキュリティ対策の構築・監視は [情報セキュリティ](../14_情報セキュリティ/README.md) と重なる。

## 2. 市場規模と成長性

| 指標                                 | 数値                               | 時点・出所                     |
| ------------------------------------ | ---------------------------------- | ------------------------------ |
| 国内IT市場（全体）                   | **28兆4,189億円**（前年比3.3%増）  | 2026年、IDC Japan 予測（推計） |
| 国内ITサービス市場                   | **6.7兆円** → 2030年に10兆円超     | 2026年、IDC Japan 予測（推計） |
| 国内AI市場                           | 2029年に**7兆円**に迫る            | IDC Japan 予測（推計）         |
| 国内AIインフラ支出                   | **8,210億円**（前年比18%超増）     | 2026年、IDC Japan 予測（推計） |
| 情報サービス業 売上DI（26年4-6月期） | **＋13.7ポイント**（前期より縮小） | JISA-DI調査（2026年4月公表）   |
| IT人材不足の見込み                   | 2030年に約**16万〜79万人**不足     | 経済産業省（2019年公表、推計） |

- 成長要因：レガシーシステムの刷新（「2025年の崖」）、クラウド移行、SAP 2027年問題、AI投資
- 制約要因：**エンジニアの絶対数不足**。需要があっても受けられる人がいないので市場が伸び切らない
- 統計上の注意：経産省『特定サービス産業動態統計』は2024年12月調査で終了し、
  2025年1月分から総務省『サービス産業動態統計調査』に統合された。時系列の接続に注意

## 3. バリューチェーン（川上 → 川下）

```
 ①企画・構想   ②要件定義   ③設計   ④製造・テスト   ⑤移行   ⑥運用・保守
 ───────────────────────────────────────────────────────────▶
 単価 300万〜   150万〜     100万〜   50〜90万円     ─      40〜80万円/月
 （月額の目安・推計）

 外資コンサル ──────────▶
        国内元請けSIer ─────────────────────────────────────▶
                     2次請け ───────────────▶
                              3次請け・SES ──▶
                                              （AIが最も効く領域）

  ◀── 付加価値が集まるのはここ         薄利・置き換わりやすいのはここ ──▶
```

- **上流ほど単価が高く、下流ほど代替されやすい**。これが業界の基本地形
- 元請けは①〜③を自社で持ち、④を外注する。だから元請けの原価の3〜5割が外注費になる
- ⑥運用・保守は単価こそ低いが**毎年入るストック収益**で、顧客を握り続ける武器になる
- 詳しくは [儲け方とコスト構造](02_儲け方とコスト構造.md)

## 5. 収益モデル・コスト構造

```
   売上高 ＝ 人月単価 × 稼働率 × 要員数 × 12か月
```

| 項目             | 内容                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| 売上の中身       | ①システム開発（フロー）②保守・運用（ストック）③ハード・ライセンス再販（薄利）  |
| 原価の中身       | 自社人件費＋**外注費（大手で原価の3〜5割）**＋経費＋仕入                       |
| 固定費／変動費   | ほぼ人件費。設備投資・在庫はほとんどない。**稼働率が数ポイント落ちると赤字**に |
| 営業利益率の目安 | **9〜13%**。規模を大きくしても上がらない                                       |
| 主なリスク       | 固定価格の一括請負での**不採算案件**（受注損失引当金として計上される）         |

**利益率が10%前後で頭打ちになる理由**：規模の経済が効かない（売上を倍にするには人を倍にする）、
原価である人件費がインフレする、人月という単位のせいで顧客に原価を推定される、
低粗利の再販売上が分母を膨らませる ── の4点。
→ [儲け方とコスト構造](02_儲け方とコスト構造.md)

## 6. 競争要因（KSF）と参入障壁

| KSF                                | 中身                                                       |
| ---------------------------------- | ---------------------------------------------------------- |
| **元請け（プライム）になれること** | 顧客と直接契約できるかで単価も利益も変わる                 |
| **業務知識**                       | 銀行の勘定系、保険の契約管理などは業務を知らないと作れない |
| **既存システムを知っていること**   | 20年動いているシステムの中身は、作った会社しか分からない   |
| **責任を取れる規模**               | 障害で業務が止まったときに賠償・復旧できる体力             |
| **要員を集められること**           | 数百人を短期に動員できる協力会社ネットワーク               |
| **上流人材**                       | 要件定義・構想ができる人材の厚み。ここの不足が成長の制約   |

参入障壁は**技術ではなく、実績と責任と人脈**。
官公庁案件では入札要件に「同規模の類似実績」が入り、新規参入が事実上できない。
一方、SESや小規模受託は設備投資が不要で**参入は極めて容易**（だから数千社が存在する）。

## 7. 規制・法制度

| 制度                               | 内容                                                                                                  |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **労働者派遣法**                   | 派遣には許可が必要。請負・準委任の形で発注者が直接指揮命令すると**偽装請負**として違法                |
| **民法（請負・準委任）**           | 2020年4月改正で瑕疵担保責任が**契約不適合責任**に。請負は完成責任を負う                               |
| **取適法（中小受託取引適正化法）** | **2026年1月施行**。旧下請法。手形払い禁止、一方的な代金決定の禁止、従業員数基準（300人・100人）の追加 |
| **フリーランス新法**               | 2024年11月施行。個人への発注に書面明示・支払期日を義務づけ                                            |
| **収益認識に関する会計基準**       | 2021年4月以降原則適用。受託開発は進捗度に応じて売上計上、損失見込み時は引当金                         |
| **官公庁の調達制度**               | 一般競争入札が原則。公取委が2022年に官公庁の情報システム調達の実態調査を実施                          |
| **個人情報保護法・各業法**         | 金融・医療など業種ごとのシステム要件が発生する → [情報セキュリティ](../14_情報セキュリティ/README.md) |

> ポイント：**この業界を縛る「業法」は存在しない**。免許も要らない。
> 代わりに、労働法（派遣・偽装請負）と取引法（下請法／取適法）が実質的な規制として効く。

## 8. 最近のトピック

→ 詳細は [直近トピック_2026](05_直近トピック_2026.md)

1. **主要各社の2026年3月期は堅調**。NTTデータが売上5兆円超、NECが富士通を売上・利益で逆転。ただし**利益率は各社10%前後**で構造は変わらず
2. **AI駆動開発が数値目標の段階へ**。TISは2030年3月期までに生産性50%向上を掲げる。一方で「生産性が上がるほど人月売上が減る」矛盾が公然と議論されている
3. **取適法が2026年1月施行**。手形払い禁止・一方的な代金決定の禁止で、多重下請けの商習慣に直接効く。中抜き率の透明化圧力が高まっている
4. **SAP 2027年問題の期限が迫る**。国内約2,000社が対象、2024年時点で移行完了は約6割（推計）。期限つきの大型特需だが2028年以降の反動減が見えている
5. **エンジニア単価は上昇継続**。AI/ML関連は月100万円超が標準化しつつある（推計）。元請けにとっては原価インフレで、転嫁が追いつかないと利益率が落ちる

## 9. 用語メモ

各ノート末尾に詳しい用語メモがある。最低限の10語だけここに置く。

| 用語                   | 意味                                                                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------- |
| **SIer**               | システムインテグレーター。業務システムを一括で作り上げる事業者。和製英語                                        |
| **人月**               | 技術者1人が1か月働く量。開発規模と金額の単位 → [02](02_儲け方とコスト構造.md)                                   |
| **SES**                | 準委任契約で技術者を客先常駐させる商売。稼働時間を売る → [01](01_日本のIT産業の構造.md)                         |
| **一括請負／準委任**   | 前者は成果物の完成を約束、後者は労務の提供を約束。責任範囲が根本的に違う                                        |
| **偽装請負**           | 請負・準委任の形式で実態は派遣。発注者が直接指揮命令すると派遣法違反                                            |
| **元請け（プライム）** | 顧客と直接契約し全体責任を負う立場。利益も最も大きい                                                            |
| **多重下請け構造**     | 元請け→2次→3次と外注が重なる構造。需要変動の吸収とリスク移転という合理性もある → [01](01_日本のIT産業の構造.md) |
| **不採算案件**         | 固定価格の請負で工数が超過し赤字になった案件。決算下振れの定番要因                                              |
| **取適法**             | 2026年1月施行の改正下請法。手形払い禁止など → [05](05_直近トピック_2026.md)                                     |
| **SAP 2027年問題**     | SAP ERP 6.0の標準保守が2027年末に終了する問題 → [04](04_変化と論点.md)                                          |
