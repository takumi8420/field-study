# ベンダーの事業構造とプラットフォーム化競争（ARR・買収・Microsoftの影）

このノートで分かること：セキュリティ製品ベンダーが**何を売って何で評価されているのか**、
そして**なぜ買収が止まらないのか**。数字の読み方まで。

## 1. 結論：売り物は「製品」ではなく「毎年更新される契約」になった

2010年代まで、セキュリティ製品は**箱（アプライアンス）＋買い切りライセンス＋保守**で売られていた。
いまは**年額サブスクリプション**が主流で、投資家が見る指標も売上ではなく
**ARR（年間経常収益＝いま契約中の年額の合計）**に移っている。

この変化が事業の性質を根本から変えた。

| | 買い切り時代 | サブスク時代 |
| --- | --- | --- |
| 売上の立ち方 | 売った年にまとめて計上 | 契約期間にわたって毎年 |
| 営業の勝負どころ | 新規導入（入れたら勝ち） | 新規＋**毎年の更新**＋**追加販売** |
| 失注の意味 | 次の更改まで数年待ち | **解約はその年の業績に直撃** |
| 成長の作り方 | 新規顧客を増やす | 既存顧客に**モジュールを足す**（単価を上げる） |
| 設備 | 製造・在庫がある | ソフトなので原価が軽い（粗利7〜8割） |

> ポイント：サブスクになった瞬間、セキュリティベンダーの競争は
> **「良い製品を作る競争」から「既存顧客に何本売り足せるかの競争」へ**移った。
> プラットフォーム化（＝一社で何でも揃える）はその必然的な帰結である。

## 2. 決算で見る指標：ARR・NRR・RPO

はじめて決算資料を見ると略語で詰まるので、最低限の4つだけ押さえる。

| 指標 | 意味 | 噛み砕くと | 目安 |
| --- | --- | --- | --- |
| **ARR** | Annual Recurring Revenue | いま契約中の年額契約を全部足した金額。「毎年入る約束の金」 | 伸び率が20%を超えると高成長 |
| **NRR（DBNR）** | Net Revenue Retention | 1年前からいる顧客が、今年いくら払っているかの比率。解約と増額の差し引き | 100%超で「何もしなくても増える」。110%超は強い |
| **GRR** | Gross Retention | 増額を除いた純粋な残存率。解約の痛みだけを見る | 95%以上が健全 |
| **RPO** | Remaining Performance Obligation | 契約済みでまだ売上計上していない残高。将来の売上の予約 | 売上の数年分あると安定 |

### 主要ベンダーの数字（2026年時点）

| 企業 | 直近の数字 | 年・出典 |
| --- | --- | --- |
| CrowdStrike | ARR 52.5億ドル（前年比＋24%）。サブスク粗利率 79%（GAAP）／81%（非GAAP）。NRR 115%、GRR 97% | 2026年1月期（FY2026）、同社IR |
| Palo Alto Networks | 第4四半期売上 34.1億ドル（前年比＋34%）。**NGS ARR 91億ドル（＋63%）**、RPO 212億ドル | 2026年7月期（FY2026）、同社IR |
| 同・CyberArk統合 | 買収後、CyberArkのACV成長率が20%（Q2）→27%（Q4）へ加速と説明 | 2026年、同社決算説明（会社側説明） |
| Google Cloud | Wiz買収を完了（約320億ドル）。**専業セキュリティ企業の買収として過去最大** | 2026年3月完了、報道・会社発表 |
| トレンドマイクロ | 2025年12月期決算短信を2026年2月18日公表。2026年12月期第1四半期の連結経常利益は前年同期比＋42.3%の176億円 | 報道ベース |

> 「NGS ARR」は Palo Alto が使う**次世代セキュリティ（クラウド・AI系）のARR**という自社定義の指標。
> ベンダー各社は**自社に都合のよい指標を定義して出す**ので、
> 他社と横並び比較するときは定義を確認する必要がある。

## 3. なぜ買収が止まらないのか：作るより買うほうが速い

セキュリティでは**「新しい攻撃面に対応する製品を、社内開発で間に合わせる」ことがほぼ不可能**である。
新しい技術が普及してから攻撃が始まるまで1〜2年、その間にスタートアップが数社立ち上がる。
大手が同じものをゼロから作ると2〜3年かかり、出来たときには市場が決まっている。

```
  新技術の普及 ──▶ 攻撃が始まる ──▶ 専業スタートアップが解決策を出す
      t=0             t=+1年             t=+1.5年
                                              │
   大手の選択肢 ───────────────────────────────┤
                                              ├─ 自社開発 → t=+4年に完成（遅い）
                                              └─ 買収    → t=+2年に製品化（速い）
                                                           ↑ こちらが選ばれ続ける
```

買い手（大手ベンダー）にとって買収は3つ同時に手に入る取引になる。

| 手に入るもの | なぜ金額が跳ね上がるか |
| --- | --- |
| 製品と技術 | ゼロから作る時間を買っている |
| **顧客とARR** | 既存の年額契約がそのまま乗る。ARRの倍率（売上の10〜20倍）で値がつく |
| **人材** | その分野を分かっている技術者ごと確保できる。採用では集まらない |

### 大型案件の例

| 買い手 → 対象 | 金額（報道ベース） | 完了 | 狙い |
| --- | --- | --- | --- |
| Alphabet（Google）→ Wiz | 約320億ドル | 2026年3月 | クラウドセキュリティ。専業買収として過去最大 |
| Palo Alto Networks → CyberArk | 約250億ドル | 2026年3月 | ID・特権管理をプラットフォームの中核に |
| Cisco → Splunk | 約280億ドル | 2024年 | ログ基盤（SIEM）を通信と束ねる |
| CrowdStrike → Seraphic Security | 非公表 | 2026年1月 | ブラウザセキュリティ |
| Zscaler → SquareX | 非公表 | 2026年2月 | 同上（ブラウザ領域の争奪） |

2026年上半期だけで**M&Aは219件**（Momentum Cyber集計）とされ、半期として過去最速のペースと報じられた。

## 4. プラットフォーム化競争：3つの戦い方

同じ「まとめ売り」でも、上位3社のやり方はまったく違う。

| 陣営 | やり方 | 収益上の狙い | 買い手にとっての釣り針 |
| --- | --- | --- | --- |
| **Palo Alto Networks** | 「プラットフォーム化」と名付けた**乗り換え促進**。他社製品の残契約期間を実質無償にして自社に寄せる | 短期の売上を犠牲にしてARRを積む。RPO（契約残高）で将来を示す | 契約本数と管理画面が減る |
| **CrowdStrike** | 1つのエージェント（端末に入れるソフト）に**モジュールを足していく** | 既存顧客の単価上昇＝NRRで伸ばす。追加導入の工事が不要 | 既に入っているので追加が楽 |
| **Microsoft** | OS・Office・クラウドの**ライセンスに同梱**（Defender、Entra、Purview、Sentinel） | セキュリティ単体では儲けず、上位プランへの引き上げで回収 | 「もう払っている分に入っている」 |

```
   ┌──────────── 買い手の予算（一定） ────────────┐
   │                                              │
   │  Microsoft: 上位ライセンスに同梱して「ゼロ円」に見せる
   │        ↓ 単体ベンダーの価格の土台を崩す
   │  Palo Alto: 残契約を肩代わりして束ねる（乗り換えコストを消す）
   │        ↓ 一度束ねると外しにくい
   │  CrowdStrike: 既に入っている足場にモジュールを足す
   │        ↓ 導入工数ゼロで単価だけ上がる
   │                                              │
   └── 専業ベンダーは「3社に挟まれた残りの面積」を取り合う ──┘
```

> Microsoftが最大の構造的脅威と言われるのは、**セキュリティで利益を出す必要がない**からである。
> 単体ベンダーは製品価格で食べているが、Microsoftはライセンス階層を上げてもらえればよい。
> 「同じ機能なら追加費用ゼロ」と言われると、単体製品は**性能ではなく価格で説明を迫られる**。

## 5. それでも単品最良（ベスト・オブ・ブリード）が残る理由

統合が進んでも専業ベンダーが消えないのには理由がある。

1. **検知性能の差が事故の有無に直結する**。束ねた製品の各機能は「そこそこ」になりやすい
2. **一社依存のリスク**。その1社に障害や脆弱性が出ると、守りが一斉に効かなくなる
3. **調達の交渉力**。1社にまとめると値上げを断れない
4. **監査・規制で「独立した第三者の目」が求められる**場面がある（診断・監査は同じ会社に任せにくい）
5. **新しい攻撃面には常に専業が先に現れる**（第1章のカテゴリの一生）

現実の落とし所は「**土台は1〜2社のプラットフォーム、尖った領域だけ専業**」という二層構成で、
このとき専業側は「プラットフォームに載る部品」として設計されるようになる。

## 6. 流通（チャネル）：誰が最終ユーザーに届けているか

海外ベンダーは日本で直販をほとんどしない。**代理店・ディストリビュータ経由**が基本である。

```
  海外ベンダー ─▶ ディストリビュータ ─▶ 販売代理店（SIer・商社・専業）─▶ ユーザー企業
   製品と価格表      在庫・与信・物流      提案・導入・保守・一次サポート      稟議・検収
        │                 │                       │
    値引き権限を持つ    為替と在庫リスク        **粗利の源泉は導入・運用役務**
```

| 層 | 何で稼ぐか | 取り分の感覚（業界の一般論） |
| --- | --- | --- |
| ベンダー | ライセンス収入 | 定価の大半。値引き原資を代理店に配分する |
| ディストリビュータ | 卸の差益 | 薄い（数%）。与信と在庫を引き受ける対価 |
| 販売代理店・SIer | 販売差益＋**導入・運用の役務** | 製品差益は薄く、**役務で稼ぐ**のが実態 |

この構造があるため、日本では**「製品を売る会社」と「運用を売る会社」が同じ顔をしている**。
SIerにとってセキュリティ製品は、後段の構築・運用案件を取るための入口になる。
くわしくは[03_サービス事業と買い手の経済学](03_サービス事業と買い手の経済学.md)。

## 7. このビジネスのリスク

| リスク | 何が起きるか | 過去の例 |
| --- | --- | --- |
| **更新の逸失** | サブスクなので解約は即業績に出る。NRRが数ポイント落ちるだけで株価が動く | 各社の決算で最重要の説明項目 |
| **自社製品が事故を起こす** | 端末に深く入る製品ほど、不具合が顧客の業務停止に直結する | 2024年のEDR配信不具合による大規模障害（報道ベース） |
| **自社製品の脆弱性が狙われる** | セキュリティ機器は「全社の通信が通る場所」なので攻撃者に人気 | VPN機器・FW製品の脆弱性悪用が繰り返し報告されている |
| **バンドルによる価格崩壊** | 大手クラウドが同梱すると、その機能単体の値付けが崩れる | Microsoftの同梱戦略 |
| **買収後の統合失敗** | 製品が繋がらず、値段だけ高い寄せ集めになる | 統合の巧拙が各社の評価差になっている |
| **為替** | 日本の買い手は円安局面で実質値上げを受ける | 更新交渉が毎年の恒例行事になる |

## 用語メモ

| 用語 | 意味 |
| --- | --- |
| **ARR** | 年間経常収益。契約中の年額の合計。サブスク型ベンダーの事実上の売上指標 |
| **NRR（DBNR）** | 既存顧客の支払額が1年で何倍になったか。解約と増額の差し引き。100%超なら純増 |
| **GRR** | 解約だけを見た残存率。増額を含めないため実力が出やすい |
| **RPO** | 契約済みで未計上の残高。将来の売上の予約分 |
| **ACV** | Annual Contract Value。1契約あたりの年額 |
| **プラットフォーム化** | 複数カテゴリを一社にまとめて売る戦略。乗り換え費用の肩代わりを伴うことが多い |
| **ベスト・オブ・ブリード** | 分野ごとに最良製品を選ぶ買い方 |
| **エージェント** | 端末やサーバに常駐させる監視用ソフト。1本で複数機能を載せられるかが競争点 |
| **ディストリビュータ** | 代理店に卸す一次販売元。在庫と与信を担う |
| **バンドル** | 別商品に同梱して売ること。単体商品の価格を崩す最も強い手段 |
