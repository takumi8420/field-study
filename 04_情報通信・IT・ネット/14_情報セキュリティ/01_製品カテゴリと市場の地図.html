1. 結論：セキュリティ市場は「ひとつの市場」ではなく、数十の小さな市場の束

「セキュリティ業界の市場規模は◯兆円」という言い方は、実務ではほとんど役に立たない。
実際に売り買いされているのは、守る対象ごとに分かれた別々の商品だからである。

端末を守る製品（EDR）を買う稟議と、社員のIDを管理する製品（IDaaS）を買う稟議と、
Webサイトを守る製品（WAF）を買う稟議は、部署も予算も検討時期も担当営業も違う。
同じ会社が3つとも買うことはあっても、3つは競合していない。

ポイント：セキュリティは「攻撃される面（アタックサーフェス）が増えるたびに
新しい商品カテゴリが生まれる」産業である。だから統合が進んでもカテゴリの数は減らない。

カテゴリが増える仕組みを図にすると次のようになる。

  新しいIT要素が普及する       それが攻撃される       専用の守る製品が生まれる
 ─────────────────      ──────────      ──────────────────
  PC・サーバ            ─▶  ウイルス       ─▶  ウイルス対策 → EDR
  社内ネットワーク       ─▶  侵入          ─▶  FW / IDS / IPS
  電子メール            ─▶  なりすまし     ─▶  メールセキュリティ
  Webサイト             ─▶  改ざん・不正入力 ─▶ WAF
  クラウド（IaaS/SaaS）  ─▶  設定ミス       ─▶  CSPM / CNAPP
  在宅勤務・SaaS直結     ─▶  境界の消滅     ─▶  SASE / ZTNA
  IDそのもの            ─▶  ID乗っ取り     ─▶  IAM / IDaaS / PAM
  ブラウザ              ─▶  拡張機能・偽サイト ─▶ ブラウザセキュリティ
  AIエージェント         ─▶  権限の暴走     ─▶  （2026年時点で形成中）

  ＝ 攻撃される面が1つ増えるたび、売り物が1つ増える

2. カテゴリの地図：何を守る商品なのかで整理する

略語が多いのは、カテゴリ名がそのまま商品名になる業界だからである。
まず「何を守るか」で並べ直すと全体が見える。

守る対象 主なカテゴリ（略語） 噛み砕くと 代表的な売り手
端末（PC・サーバ）EPP / EDR / XDRウイルス対策の次の世代。端末の「動き」を記録して異常を見つけ、隔離するCrowdStrike、Microsoft、SentinelOne、トレンドマイクロ
ネットワークの出入口FW（ファイアウォール）/ IPS通信を通す・止めるを判断する関所。物理の機器で売られてきたPalo Alto、Fortinet、Check Point、Cisco
社外からの接続SASE / ZTNA / SWG関所をクラウド側に置き、どこから繋いでも同じ検査をするZscaler、Netskope、Cloudflare、Palo Alto
人・機械の「誰であるか」IAM / IDaaS / PAM誰に何を許すかを管理する。PAMは管理者権限の金庫番Okta、Microsoft Entra、CyberArk（Palo Alto傘下）
クラウドの設定と稼働CSPM / CWPP / CNAPPクラウドの設定ミスや危ない権限を洗い出す。CNAPPはその統合版Wiz（Google傘下）、Palo Alto、Orca
メールメールセキュリティ / DMARC偽メールを止める。侵入経路として今も最大級Proofpoint、Mimecast、各社クラウド付属
WebアプリWAF / Bot対策 / DDoS対策公開サイトへの不正な入力や大量アクセスを弾くAkamai、Cloudflare、Imperva、F5
データそのものDLP / 暗号化 / データ分類持ち出しを検知する、読めなくするMicrosoft Purview、Forcepoint
ログと検知の土台SIEM / SOAR各所のログを1か所に集めて相関を見る／対応を自動化するSplunk（Cisco傘下）、Microsoft Sentinel、Elastic
ソフトの作り込みSAST / DAST / SCA / ASPM開発中のコードや使っている部品の弱点を見つけるSnyk、Veracode、GitHub Advanced Security
運用（人が見る）MDR / MSS監視と一次対応を丸ごと請け負うサービス各ベンダー＋MSSP（03）

覚え方：「E＝端末、N＝ネットワーク、C＝クラウド、I＝ID、D＝データ」。
頭文字の3〜4文字略語は、だいたいこの5つのどれかに「管理」「検知」「対応」を
付け足したものだと思えば、初見の略語でもおおよその見当がつく。

注意：セグメントの単純合計は「合計」に一致しない。機関ごとに
「ネットワークセキュリティをソフトに含めるか」「機器の保守を services に入れるか」が違い、
集計の版によっても定義が動くためである。市場規模の数字は
総額を比べるのではなく、同じ機関の同じ版の中で伸び率を比べるのが正しい使い方になる。

伸びの中身にはっきり差がある。Gartnerが追う41カテゴリのうち、
クラウドの設定管理（CSPM）が成長率33.4%で最も速い（2026年、Gartner）。
サービス側ではマネージドセキュリティサービス（監視の代行）が11.1%増で最速とされる。
つまり伸びているのは「クラウドの守り」と「人手の代行」の2か所であり、
どちらも自社で抱えきれなくなった仕事を外に出す動きである点が共通している。

読み方のコツが2つある。

① 構成比が語る国内の特徴。ソフトウェア約5,900億円（2024年）に対し、
サービスが1兆円規模。つまり日本では「製品を買う金」より「人に見てもらう金」のほうが大きい。
これは人材不足の裏返しであり、国内事業者の稼ぎ方を決めている（→03）。

② 予測はよく外れる。IDCが2022年に出した予測では
国内セキュリティソフトウェア市場は2026年に4,637億円とされていた。
ところが実績は2024年の時点で5,861億円。2年前倒しで予測値を追い抜いている。
市場規模の数字を引くときは、「いつ出された予測か」を必ず添える必要がある。

5. カテゴリの一生：新語 → 定番 → 買収か消滅

セキュリティのカテゴリ名には寿命がある。この流れを知っていると、
「新しい略語」を見たときに騒ぐべきか様子を見るべきかの判断がつく。

 ①新語が生まれる      ②調査会社が                ③大手が買う          ④名前が消える
  スタートアップが     カテゴリとして採番          プラットフォームに    単独カテゴリでは
  問題を切り出す   ─▶  （象限図・ハイプ曲線）─▶  組み込まれる     ─▶  売られなくなる
                                                                        （機能の一つへ）
  例：CSPM(2019頃) ──▶ CNAPPへ統合(2021頃) ──▶ Wiz買収(2026年3月) ──▶ クラウド基盤の一機能へ
  例：SIEM(2005頃) ──▶ 定番化           ──▶ Splunk買収(2024年) ──▶ ログ基盤に吸収
段階 起きていること 買い手（企業）から見た注意点
①新語尖った機能だが単体。専業スタートアップが数社効果は高いが、数年で買収され製品方針が変わる可能性
②定番化調査会社が市場として認定。比較表ができる選定しやすい。価格競争が始まり値ごろ感が出る
③統合大手が買収し、プラットフォームの一機能に単体契約が更新できなくなる／束で買わされる
④吸収カテゴリ名として語られなくなる「入れ替え」ではなく「棚卸し」の対象になる

この一生があるので、専業ベンダーの出口は基本的に「買われること」になる。
市場の新陳代謝がM&Aで回る理由は02で扱う。

6. ツール疲弊：カテゴリが割れていることのコスト

カテゴリが分かれているぶん、企業には製品が積み上がる。
セキュリティ部門が60〜80種類のツールを抱えている状態は珍しくないとされ（2026年、業界分析）、
2020年代後半はこれを減らす動きが続いている。

起きる問題 具体的に何が困るか
管理画面が多すぎる警報が別々に出る。誰も全部は見られない
契約・更新が多すぎる調達部門の負荷。更新時期がバラバラで交渉力も落ちる
人が足りない製品ごとに習熟が必要。運用できる人が育つ前に製品が変わる
重複投資同じ機能を2社から買っている（EDRとXDR、SWGとSASEなど）

ここがベンダー側の商機になっている。「本数を減らしたい」という買い手の疲れが、
プラットフォーム化を売る最大の営業トークになった。
一方で「ひとまとめにすると一社依存になる」という逆の懸念もあり、
統合派（プラットフォーム）と単品最良派（ベスト・オブ・ブリード）の綱引きが続いている。

  （円安の影響を受ける）      （人件費がそのまま原価）     （人数がボトルネック）

日本の買い手にとって重要なのは、左側（製品）の値段はドル建てで決まることである。
主要な製品ベンダーが海外勢なので、為替が動くと中身が同じでも更新時に値上がりする。
これが国内で「製品を絞って運用に寄せる」判断を後押ししている。

用語メモ

用語 意味
アタックサーフェス攻撃されうる面。公開サーバ、社員のID、取引先の接続口など。増えるほど守る商品も増える
EDREndpoint Detection and Response。端末の挙動を記録して異常を検知・隔離する仕組み
SASE（サッシー）Secure Access Service Edge。通信の検査をクラウド側に集約する方式。SWG・ZTNA・FWの束
ZTNAZero Trust Network Access。社内ネットに入れるのではなく、アプリ単位で毎回許可する接続方式
IAM / IDaaSID・アクセス管理。誰に何を許すかの管理。クラウドサービスとして提供されるものがIDaaS
PAMPrivileged Access Management。管理者権限の貸し出しと記録を管理する「鍵の金庫」
CSPM / CNAPPクラウドの設定ミスや危険な権限を洗い出す製品／それらを統合した製品群
WAFWeb Application Firewall。Webサイトへの不正な入力や攻撃通信を手前で弾く
SIEMSecurity Information and Event Management。各所のログを集約し相関分析する基盤
SOAR検知後の対応手順を自動実行する仕組み。人手不足の直接の回答として使われる
MDR / MSS監視と一次対応を外部に委託するサービス。製品ではなく人の稼働を買う
ベスト・オブ・ブリード分野ごとに最良の製品を選ぶ買い方。プラットフォーム（一社にまとめる）の対義
