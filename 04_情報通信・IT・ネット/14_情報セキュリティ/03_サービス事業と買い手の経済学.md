# サービス事業と買い手の経済学（MSSP・診断・人材単価・日本市場・稟議の通し方）

このノートで分かること：日本のセキュリティ市場で**最も大きいのに一番見えにくい「サービス」**が
どういう商売なのか。そして**買う側はどんな理由で金を出すのか**。

> 攻撃の手口・防御技術そのものは
> [注目テーマ側](../../01_注目テーマ/10_サイバーセキュリティ/README.md) が扱う。
> ここは**値段・原価・稟議**の話に絞る。

## 1. 結論：日本では「製品を買う金」より「人に見てもらう金」のほうが大きい

国内のセキュリティソフトウェア市場が2024年に5,861億円（IDC Japan）なのに対し、
サービス市場は**1兆円規模**（IDC Japanは2025年に1兆230億円と予測、2021年公表）。
つまり市場の重心は**人の稼働**にある。

理由は単純で、**製品を入れても見る人がいない**からである。
警報は出るが判断できない。判断できても24時間は張り付けない。
だから「製品＋見る人」をセットで外に出す。これがサービス市場の正体である。

> ポイント：セキュリティのサービス事業は、突き詰めると
> **「専門家の時間を、何社で割り算できるか」**という商売になる。
> 割り算の分母（担当社数）を増やせるかどうかが利益率のすべてを決める。

## 2. サービスの類型と値段の目安

| 類型 | 何を売るか | 課金の形 | 価格の目安（2026年時点） | 利益の出方 |
| --- | --- | --- | --- | --- |
| **MSS / MDR**（監視代行） | ログ監視・検知・一次対応 | 月額（端末数・ログ量） | 端末単価×台数の月額課金が主流 | 労働集約。**1人で何社見られるか**が命 |
| **SOC構築支援** | 自社SOCの立ち上げ | 請負（人月） | 案件規模次第 | 人月商売。スポット |
| **脆弱性診断（Web）** | サイトの弱点を洗い出す | 案件ごと | 簡易は数十万円、手動込みで**50万〜300万円** | 人月商売だがツール自動化で利幅を作れる |
| **脆弱性診断（スマホアプリ）** | アプリの弱点 | 案件ごと | **1OSあたり50万〜300万円** | 同上 |
| **ペネトレーションテスト** | 実際の攻撃者を模して侵入を試す | 案件ごと | **50万〜500万円超**。高度なものは**200万〜1,000万円以上** | 単価は最高。ただし人が増やせない |
| **インシデント対応・フォレンジック** | 事故時の調査・封じ込め | 時間単価／緊急対応 | 緊急対応は割増。平時は顧問契約で埋める | **事故がないと売上が立たない**のが構造的弱点 |
| **コンサル・認証支援** | ISMS取得、規程整備、規制対応 | 案件ごと | 人月ベース | 規制強化が直接の需要になる |
| **教育・訓練** | 標的型メール訓練、研修 | 年額／回数 | 比較的安価 | 単価は低いが継続しやすい |

※価格は診断事業者が公開する相場情報（2026年時点）に基づく**推計レンジ**。
対象範囲・手動確認の深さ・報告会や再診断の有無で大きく動くため、同じ「Web診断」でも
**見積りは数倍ぶれる**のが普通である。

## 3. MSSP／SOCの原価構造：24時間365日は「4.5人」から始まる

24時間365日の監視を1席ぶん維持するには、交代制のため**最低でも4.5〜5人**が必要になる。
これは労働法上の休日・有給・教育時間を織り込んだ現場の目安で、
つまり**「1席＝年間の人件費の約5人分」が固定費として先に乗る**。

```
 【MSSPの損益の考え方】

  固定費：1席×5人分の人件費 ＋ 監視基盤（SIEM等）のライセンス
     │
     ▼
  ─────────────────────────────────────────
   顧客1社目   ：赤字（固定費を1社で背負う）
   顧客10社目  ：損益分岐点あたり
   顧客50社目  ：黒字。1社あたり固定費が1/50に
   顧客200社目 ：**警報の量が人の限界を超える** → 自動化しないと崩れる
  ─────────────────────────────────────────
     │
     ▼
  だから MSSP の経営課題は常に2つだけ
   ①社数を増やす（営業） ②1人あたり担当社数を増やす（自動化・AI）
```

| コスト項目 | 割合の感覚 | 効いてくるポイント |
| --- | --- | --- |
| 人件費 | 最大。売上原価の中心 | 採用できないと売上が伸ばせない＝成長が人数で頭打ち |
| 監視基盤ライセンス | 次点 | ログ量に比例して増える。顧客のログが増えると原価も増える |
| 教育・資格維持 | 小さいが必須 | 人が辞めると即座に品質が落ちる |

> 製品ベンダーの粗利が7〜8割なのに対し、**監視サービスの粗利は3〜4割の世界**になりやすい。
> この差が、製品ベンダーがサービスまで取りに来る理由でもあり、
> サービス事業者がAI・自動化に賭ける理由でもある（→[04_直近トピック_2026](04_直近トピック_2026.md)）。

## 4. 人材市場：足りないのは「人数」ではなく「経験の階段」

| 指標 | 数値 | 年・出典 |
| --- | --- | --- |
| セキュリティ人材の不足見通し | 2030年に約19万人不足 | 経済産業省の試算として広く引用（元調査は2016年。**数字は古く、引用時は注意**） |
| セキュリティエンジニア平均年収 | 約600万円（経験者646万円／未経験507万円） | 2026年、転職媒体の自社データ（推計） |
| 同・別媒体の集計 | 約496万円 | 2026年、求人サイト集計（推計） |
| 転職支援事例の想定年収 | 平均875.9万円。ボリュームゾーン700〜1,000万円 | 人材紹介会社の公表（推計） |
| SOCアナリスト（Tier2以上） | 600万〜800万円が目安 | 2026年、求人情報ベース |
| SOCアナリスト（エキスパート求人） | 700万〜1,100万円 | 同上 |

数字のばらつきが大きいのは、**「セキュリティ人材」が一つの職種ではない**からである。

```
  ①運用の担い手          ②検知・分析            ③攻める側の技術           ④制度・管理
  SOC Tier1             SOC Tier2/3           ペンテスター・             CISO補佐・
  アラートの一次仕分け    相関分析・封じ込め      リバースエンジニア         規程・監査対応
   ────────────         ─────────────         ──────────────            ──────────
   供給あり              **ここが薄い**          極端に少ない               需要が規制で増加
   自動化に置き換え中     経験がないと育たない     育成に年単位              業務知識が要る
        │                      ↑
        └──── 育つ経路が細い ───┘
        （Tier1が自動化されると、Tier2の育つ場が消えるという矛盾）
```

> ここが日本のセキュリティ人材問題の核心である。
> 人数が足りないというより、**一次対応（Tier1）を自動化・外注した結果、
> 中堅（Tier2）が育つ現場がなくなった**。だから単価の高い層だけが慢性的に不足し、
> 診断・ペンテストの価格が下がらない。

資格の役割も大きい。国家資格の**情報処理安全確保支援士（RISS）**や
IPAの**情報セキュリティサービス基準適合サービスリスト**への掲載が、
官公庁・大企業の調達要件になることがあり、**資格が受注要件＝単価の下支え**になっている。

## 5. 日本市場の固有事情：SIerと販社が挟まる

海外では「ベンダー → ユーザー企業」が近いが、日本は**間に必ず誰かが入る**。

```
 海外ベンダー ─▶ 国内ディストリビュータ ─▶ SIer・販社・商社 ─▶ ユーザー企業の情シス
                                              │                      │
                                        ここが提案・導入・          人が1〜数人しかいない
                                        運用・一次窓口を全部持つ     （だから丸投げになる）
                                              │
                                        国内セキュリティ専業
                                        （ラック、NRIセキュア、SBT ほか）
                                        ＝ SIerの下請けにも、直接元請けにもなる
```

| 日本固有の特徴 | なぜそうなるか | 帰結 |
| --- | --- | --- |
| 情シスが小さい | ITを外注する文化（→[SIer・ITサービス](../05_SIer・ITサービス/01_日本のIT産業の構造.md)） | 運用ごと外に出す。サービス市場が大きくなる |
| 製品はほぼ海外製 | 国内ベンダーは総合製品で世界と競えていない | 為替で実質値上げ。更新交渉が毎年発生 |
| 国内勢の強みは運用・診断・コンサル | 日本語対応、商習慣、官公庁の実績 | **人の商売で生き残る**構造 |
| 官公庁・重要インフラは別枠 | 実績・資格・国内対応が調達要件 | 大手SIerと専業の寡占になりやすい |

## 6. 中小企業市場：制度が需要を作っている

中小企業は「予算がない・人がいない・被害の実感がない」の三重苦で、放っておくと市場にならない。
そこで**公的な制度が需要を作りにいっている**のがこの層の特徴である。

| 仕組み | 内容 | 時点 |
| --- | --- | --- |
| **サイバーセキュリティお助け隊サービス**（経産省・IPA） | 異常監視・緊急対応・相談窓口・簡易サイバー保険をパッケージ化。**全国1万社超が導入** | 2026年時点 |
| 同・価格 | 補助金を使うと**月額1万円以下**の水準になる場合がある | 同上 |
| **デジタル化・AI導入補助金2026**（旧IT導入補助金） | **セキュリティ対策推進枠**を設置。制度全体の補助上限は1者あたり最大450万円、補助率は原則1/2（小規模事業者は要件を満たせば最大4/5） | 中小企業庁、2026年4月公表資料。※枠ごとの上限は最新の公募要領で要確認 |

### サイバー保険

| 指標 | 数値 | 年・出典 |
| --- | --- | --- |
| 日本のサイバー保険市場 | 2025年 約10.1億ドル → 2034年 約48.0億ドル（CAGR約19%） | 調査会社の推計（IMARC等） |
| 中小企業の加入率 | 約4.8% | 日本損害保険協会 調査 |
| 中小企業の認知率 | 2021年度36.6% → 2023年度46.9% | 同上 |
| 大企業の加入 | 約6割が加入との報道 | 報道・解説記事ベース |

> 保険が普及しきらない理由は、**「いくら払えばいくら戻るか」が分かりにくい**ことに尽きる。
> 被害の大半は身代金そのものではなく**業務が止まった間の逸失利益と復旧費**で、
> ここは免責や算定条件が複雑になる。**保険は「買う理由」を作る装置**としては有効だが、
> 対策の代替にはならない、というのが実務の相場観である。
> 損害保険の商品構造そのものは [損害保険](../../05_金融/08_損害保険/README.md) を参照。

## 7. 買う側の意思決定：予算は「恐怖」ではなく「外圧」で動く

セキュリティ投資の稟議で最も誤解されているのは、
**「怖いから買う」で決裁が下りることはほとんどない**という点である。
実際に金が動くのは、次の3つのどれかが起きたときに限られる。

| トリガー | 中身 | 決裁の速さ | 売り手の動き方 |
| --- | --- | --- | --- |
| ①**事故**（自社・同業） | 実際に止まった、漏れた。同業の事故も効く | 最速。補正予算が付く | 事故直後の同業界への提案が最も通る |
| ②**規制・監査** | 法令、業界基準、監査法人の指摘 | 期限が決まっており確実 | 「いつまでに何が必要か」で語る |
| ③**取引先要請** | 親会社・発注元のチェックシート、ISMS等の要求 | 取引継続がかかるので断れない | 「この項目を満たせます」と書式に合わせる |

```
 【経営がYesと言う理由の順番】

   売上が増える？ ──── いいえ  ─┐
                                │
   コストが減る？ ──── いいえ  ─┤ ← ROIでは説明できない
                                │
   止まったら困る？ ── **はい** ─┤ ← 事業継続の話に翻訳できると通る
                                │
   怒られる？（規制・取引先）── **はい** ─┤ ← 期限があるので最も通る
                                │
   同業がやられた？ ── **はい** ─┘ ← 比較で通る（「うちだけ未対応」）
```

## 8. ROIを示せない商材をどう売るか

セキュリティは「買っても何も起きないのが成功」という商材で、投資回収（ROI）が原理的に示せない。
そこで実際の営業・稟議では、次の4つの言い換えが使われる。

| 言い換え | 具体的な語り方 | 効く相手 |
| --- | --- | --- |
| **停止時間に換算する** | 「1日止まると売上◯億円。復旧の平均は数週間」 | 事業部門・CFO |
| **他社事例に並べる** | 同業の事故と対応状況を並べ、**未対応であることの説明責任**を作る | 経営会議 |
| **監査・規制の指摘に変える** | 「次の監査で指摘対象になる」「取引先の要求項目を満たせない」 | 内部統制・法務 |
| **保険・格付の条件にする** | 保険の引受条件、取引先の与信・審査項目 | 調達・財務 |

> 実務上いちばん強いのは③で、**「守るために買う」ではなく「取引を続けるために買う」**
> と言い換えた瞬間に、稟議はセキュリティ案件から事業案件に変わる。
> だから売り手側も、規制改正や大手の調達基準の変更を**営業カレンダーとして追いかけている**。

参考として、日本企業のセキュリティ予算はIT予算の**1割前後**にとどまる企業が多数派で
（「10%未満」が6〜7割という調査が複数ある）、一方で**「15%以上」と答える企業も近年最高水準**という
二極化が報告されている（JUAS「企業IT動向調査」ほか、2024〜2026年）。
この差は業種より**「過去に事故を経験したか」**で説明されることが多い。

## 用語メモ

| 用語 | 意味 |
| --- | --- |
| **MSSP** | Managed Security Service Provider。監視・運用を代行する事業者 |
| **MDR** | Managed Detection and Response。検知から一次対応まで含む代行サービス。MSSより踏み込む |
| **Tier1／Tier2／Tier3** | SOC内の役割階層。1が一次仕分け、2が分析・封じ込め、3が高度解析 |
| **脆弱性診断** | 既知の弱点が存在するかを網羅的に確認する。ツール＋手動の組み合わせ |
| **ペネトレーションテスト** | 実際に侵入できるかを目標を決めて試す。診断より高度で高価 |
| **フォレンジック** | 事故後に、いつ何が起きたかを証跡から再構成する調査 |
| **情報処理安全確保支援士（RISS）** | セキュリティ分野の国家資格。調達要件に使われることがある |
| **情報セキュリティサービス基準適合サービスリスト** | IPAが公開する、一定の品質基準を満たすサービスの一覧。公共調達で参照される |
| **お助け隊サービス** | 中小企業向けに監視・対応・相談・簡易保険を低価格でまとめた経産省の制度 |
| **サイバー保険** | 事故時の費用・賠償を補償する損害保険。中小の加入率は約4.8%（損保協会調査） |
| **人月** | 技術者1人が1か月働く量を単位にした見積り方式。サービス事業の基本単位 |
