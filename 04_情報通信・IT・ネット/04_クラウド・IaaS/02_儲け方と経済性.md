# 儲け方と経済性 ── 粗利は稼働率と自社設計ハードから出る

このノートで分かること：なぜ巨額の設備投資を続けながら高い利益率を出せるのか。
そして「何度も値下げできた」からくりと、値下げが止まった理由。

## 1. 結論：粗利の源泉は「稼働率」と「自社設計ハード」

クラウド事業は、資産構成だけ見れば **データセンター業と同じ装置産業**である。
違うのは、同じ機械を**多数の顧客で同時に使い回せる**ことと、
**機械そのものを自分で設計して原価を下げられる**こと。この2つが粗利を作っている。

```
   ① 調達を安くする          ② 使い切る                ③ 高く売る
  ┌───────────────┐    ┌────────────────┐    ┌──────────────────┐
  │ 自社設計チップ  │    │ 多数顧客で共有   │    │ マネージドサービス │
  │ 自社設計サーバ  │──▶│ 稼働率を上げる   │──▶│ で単価を上げる     │
  │ 大量購買・自家発 │    │ 余剰はスポット   │    │ 転送料で固定化     │
  └───────────────┘    └────────────────┘    └──────────────────┘
      原価を下げる            分母を減らす            分子を増やす
```

> ポイント：**同じ1台のサーバから何人分の売上を立てられるか**が、この商売の生死を分ける。
> データセンター事業者が「空室率」を見るのと同じ指標を、クラウドは「使用率」と呼んでいるだけ。

## 2. AWSの数字を読む ── 売上13%、利益74%という歪み

上場企業の中で唯一、クラウド単体の損益が長期にわたり開示されているのがAWSである。

| 指標 | 数値 | 時点・出所 |
| --- | --- | --- |
| AWS四半期売上 | 376億ドル（前年比+28%） | 2026年1〜3月期、Amazon IR |
| AWS四半期売上 | 422億ドル（前年比+36.7%） | 2026年4〜6月期、Amazon IR |
| AWS四半期営業利益 | 166億ドル、**営業利益率39%** | 2026年4〜6月期、Amazon IR |
| Amazon全社に占めるAWSの比率 | 売上の約13%、**営業利益の約74%** | 2026年、報道ベースの集計 |
| AWSの受注残（backlog） | 約4,960億ドル（前年比100%超増） | 2026年4〜6月期、Amazon IR |
| Amazonの2026年通期設備投資 | 約2,200億ドル（会社計画） | 2026年、Amazon IR |

**読み方の要点**：

- 小売の会社に見えるが、**利益のほぼ全部をクラウドが稼いでいる**。EC本体は薄利多売
- 営業利益率39%は償却後の数字。データセンター業のEBITDAマージン（償却前）とは比較できない
- 一方で設備投資2,200億ドルは巨額で、**利益率が高いのに現金は出ていく**。受注残の急増は、AI案件が**長期コミット型**に変わったため

他社も同じ方向にある。Microsoftは商用RPO（受注残に相当）が6,780億ドルで前年比+84%、
Azureの年間売上は1,000億ドルを超えたとされる（2026年、同社IRおよび報道）。
Google Cloudの受注残は5,140億ドル規模で前年比約2倍と報じられる（2026年）。

## 3. コスト構造 ── 何にお金が出ていくか

1MW分の計算資源を1年動かしたときの費用イメージ（**構成比の感覚をつかむための模型**であり、実数値ではない）。

| 費目 | 構成比の目安 | 性質 |
| --- | --- | --- |
| サーバ・GPU・ストレージの減価償却 | 40〜55% | 固定費。耐用年数の設定で利益が大きく動く |
| データセンター費用（自社償却または賃借料） | 10〜20% | 固定費。→ [データセンター](../03_データセンター/README.md) |
| 電力 | 10〜20% | 準変動費。AI用途で比重が上昇 |
| ネットワーク・回線 | 5〜10% | 固定費に近い |
| 人件費（開発・運用・サポート） | 5〜15% | 規模が大きいほど希薄化する |
| ソフトウェアライセンス | 数% | 自社開発比率が高いほど小さい |

**ここが効く論点**：

- **耐用年数**：サーバの償却年数を4年から6年へ延ばすと、年間の償却費が3分の2になり利益が増える。
  実際にMicrosoftは2026年の設備投資見通しを示す際にデータセンター資産の想定耐用年数を延ばしたと報じられており、
  各社の利益率比較では**償却前提の違いに注意が要る**
- **電力**：AI向けは1ラックあたりの消費電力が従来の10倍規模になり、電気代の比重が上がる
- **人件費が薄い**：数百万台規模を数千人で運用するため、売上が増えても人が比例して増えない。
  これが [SIer・ITサービス](../05_SIer・ITサービス/README.md) の人月商売と決定的に違う点

## 4. 稼働率とマルチテナンシー ── 粗利を作る仕組み

企業が自社で持つサーバの平均CPU使用率は、**一般に10〜20%台**と言われる。
ピークに備えて買うため、普段は遊んでいるからである。

クラウドは多数の顧客を1つの物理サーバに同居させる（**マルチテナンシー**）ことで、
この遊びを消す。日中に使う企業と夜間バッチの企業、日本の昼と米国の昼を重ね合わせれば、
同じ機械の使用率は上がる。

```
  自社保有（1社だけ）              クラウド（多数の顧客を重ねる）
  使用率                            使用率
   100%│                            100%│▓▓▓▓▓▓▓▓▓▓▓▓▓▓
       │      ╱╲                        │▒▒▒▒▒▒▒▒▒▒▒▒▒▒
    50%│     ╱  ╲                    50%│░░░░░░░░░░░░░░
       │____╱    ╲____                  │██████████████
     0%└────────────────             0%└────────────────
       ピークに合わせて買う             谷を他社の山で埋める
       → 平均20%しか使わない           → 平均70〜80%まで上げられる
```

> ポイント：**顧客の「無駄」を集めて束ねると、それ自体が商品になる**。
> クラウドが顧客より安く提供できる根拠の半分はここにある。

さらに余った容量は**スポットインスタンス**（中断される可能性がある代わりに大幅割引の枠）として
売りに出せる。捨てるはずの在庫を値引きして売る航空券やホテルと同じ発想で、
限界費用はほぼ電気代だけなので**売れれば全部粗利**になる。

## 5. 自社設計ハード ── Graviton／Trainiumはなぜ利益率に効くか

もう一つの粗利の源泉が、**サーバとチップを自分で設計すること**。

| 種類 | 例 | 何が得か |
| --- | --- | --- |
| 自社設計サーバ | 各社のカスタムラック | 要らない部品（映像出力、筐体の飾り）を削り、冷却も自社仕様に |
| 自社設計CPU | AWS Graviton、Google Axion、Microsoft Cobalt | Intel/AMDへのマージンを払わずに済む。電力効率も自社最適 |
| 自社設計AIチップ | AWS Trainium/Inferentia、Google TPU、Microsoft Maia | **NVIDIAのマージンを外せる**。ここが最大の論点 |
| 自社設計ネットワーク | 独自スイッチ・光配線 | 機器メーカーのマージンを外す → [通信機器](../02_通信機器/README.md) |

AI用GPUは供給が絞られ、価格決定権がNVIDIA側にある。
**GPUを買って貸す商売は、原価の大半を1社に握られた商売**になってしまう。
自社チップはこの構図を崩すための投資である。

- Amazonは2026年4月時点で、Trainium/Gravitonを含む半導体事業の年換算売上が
  **200億ドルを超えた**とCEOが述べたと報じられる
- Trainiumは「NVIDIA GPU比で価格性能3割改善」をうたうが、これは**ベンダー側の主張**であり
  ワークロードにより結果は大きく変わる
- NVIDIAはAIアクセラレータ市場で依然6割超のシェアを持つとされる（2026年、推計）
  → [半導体・先端半導体](../../01_注目テーマ/02_半導体・先端半導体/README.md)

**自社チップの落とし穴**：顧客が使ってくれなければ意味がない。
既存のAIソフトウェアはNVIDIAのCUDAを前提に書かれており、移植コストが顧客側に発生する。
だから各社は「自社チップだと安い」という価格差でしか顧客を動かせない。

## 6. データ転送料（エグレス）とロックイン

クラウドの価格表には独特の非対称がある。**入れるのは無料、出すのは有料**。

```
   ユーザー企業 ──── データを入れる（インバウンド）────▶ クラウド
                         ほぼ無料
   ユーザー企業 ◀─── データを出す（エグレス）─────── クラウド
                    GBあたり課金。数円〜十数円/GB
```

100TBのデータを別のクラウドへ移すと、転送料だけで数百万円規模になりうる。
さらに移行中は両方に課金が発生し、アプリの書き換え工数もかかる。
結果として**「出ていくほうが高い」状態が続き、事実上の乗り換え抑止**になっていた。

この構造に規制が入った。

| 動き | 内容 | 時点 |
| --- | --- | --- |
| EU Data Act | クラウド間の乗り換え支援料・エグレス料の上限を「実費」に制限 | 2024年1月11日〜 |
| EU Data Act | **スイッチング料金の徴収を全面禁止** | **2027年1月12日から** |
| 主要3社の対応 | 「全面撤退時のデータ転送を無償化」を相次いで発表（条件・除外サービスあり） | 2024年 |

重要な区別として、禁止されるのは**乗り換えに伴うエグレス**であって、
日常運用のエグレス（エンドユーザーへの配信、リージョン間複製など）は引き続き有料である。
「エグレス料が消える」という見出しは正確ではない。

## 7. コミット割引 ── リザーブド、Savings Plans、EDP

従量課金がクラウドの入口だとすれば、**出口は長期コミット契約**である。

| 仕組み | 顧客が約束すること | 割引率の目安 | 事業者側の狙い |
| --- | --- | --- | --- |
| リザーブドインスタンス（RI） | 特定タイプのサーバを1〜3年使う | 30〜70% | 稼働率の下限を確定させる |
| Savings Plans 等 | 1時間あたり一定額を1〜3年使う | 20〜70% | 柔軟性を残しつつ金額を固定 |
| 企業割引契約（EDPなど） | 数年で総額いくら使う | 個別交渉 | **総額の囲い込み** |
| キャパシティ予約 | GPUなど希少資源の枠を押さえる | 割引より「確保」が目的 | 高単価資源の先売り |

> ポイント：事業者から見るとコミット割引は**値引きではなく、受注残（backlog）への変換**である。
> AWSの約4,960億ドル、Microsoftの約6,780億ドル、Google Cloudの約5,140億ドルという受注残（いずれも2026年）は、
> この仕組みが動いた結果であり、巨額の設備投資を正当化する担保にもなっている。

顧客側から見ると、コミットは**使い切れなければ払い損**になる。
使い切るために不要なワークロードを載せ続ける、という本末転倒も起きる。

## 8. なぜ何度も値下げできたのか、そしてなぜ止まったのか

AWSは2006年のサービス開始から2010年代を通じて**100回以上の値下げ**を行ったとされる。
これは善意ではなく、構造的に可能だったからである。

```
  ① ムーアの法則で同じ価格の機械が速くなる
        ↓
  ② 規模が増えて調達単価・運用単価が下がる
        ↓
  ③ 値下げする → 需要がさらに増える → ②へ戻る
        ↓
  ④ 一度下げた価格は競合も追随せざるを得ない（新規参入の芽を摘む）
```

これは**デフレを武器にした参入障壁**であり、追随できない中小事業者を振り落とす効果があった。

2020年代後半にこのループが鈍った理由は3つ。

1. **半導体の微細化が減速**し、性能当たりコストの低下が以前ほど効かなくなった
2. **AI向けは電力と冷却が制約**になり、規模拡大が単価低下に直結しなくなった
   （→ [データセンター](../03_データセンター/README.md) の受電制約）
3. **GPUの供給が逼迫**し、原価側が下がるどころか上がった

結果として競争の軸は「安さ」から**「容量をいつ渡せるか」**へ移っている。
値引きではなく確保が売り文句になったのが2026年の特徴で、詳しくは
[04_直近トピック_2026](04_直近トピック_2026.md) を参照。

## 9. FinOps ── コスト最適化という新職種

従量課金は請求が読めない。そこで生まれたのが**FinOps**（Financial Operations）という職能で、
エンジニア・財務・経営をまたいで**クラウド支出の可視化・配賦・最適化**を回す役割を指す。

| FinOpsの仕事 | 具体例 |
| --- | --- |
| 可視化 | 誰の・どのプロダクトの費用かをタグで分解する |
| 配賦 | 共有基盤の費用を事業部へ割り戻す |
| 最適化 | 使っていない資源の停止、サイズ適正化、コミット購入の設計 |
| 予測 | 来期の支出見通しを作り、コミット契約の量を決める |
| 単位経済性 | 「顧客1人あたりのクラウド費用」で追う |

| 調査からの数字 | 内容 | 時点・出所 |
| --- | --- | --- |
| 無駄になっているクラウド支出 | **29%**（前年27%から上昇。5年ぶりの悪化） | 2026年、Flexera State of the Cloud（推計） |
| AI支出を管理下に置く実務者の割合 | 2024年31% → 2025年63% → **2026年98%** | FinOps Foundation State of FinOps 2026 |
| 自動最適化まで到達した組織 | 約14%（調査対象は実務者1,192名、年間クラウド支出830億ドル超） | 同上（推計） |

> ポイント：**無駄が5年ぶりに増えた原因はAI**とされる。
> GPUクラスタや実験中の推論エンドポイントが、タグ付けも停止も追いつかない速度で立ち上がるため。
> クラウドの経済性は「安く借りる」より「止め忘れない」で決まる段階に入った。

## 10. この事業を見るときの指標

| 指標 | 何が分かるか | 注意点 |
| --- | --- | --- |
| 売上成長率（YoY） | 需要の勢い | AI需要で各社の伸びが不連続に変わった |
| 営業利益率 | 装置産業としての効率 | 償却年数の前提で数ポイント動く |
| 受注残（backlog / RPO） | 将来の売上の確度 | 顧客が偏っていれば信用リスクになる |
| 設備投資額（capex） | 将来の容量 | 利益と逆相関。現金の出方を必ず併せて見る |
| 顧客集中度 | 1社依存の度合い | ネオクラウドでは致命的なリスク |
| 電力確保量（MW／GW） | 実際に増やせる容量 | 2026年の事実上の成長率上限 |

## 用語メモ

| 用語 | 意味 |
| --- | --- |
| **マルチテナンシー** | 1つの物理基盤を多数の顧客で共有すること。稼働率を上げる仕組み |
| **スポットインスタンス** | 中断の可能性と引き換えに大幅割引される余剰容量の枠 |
| **リザーブドインスタンス（RI）** | 1〜3年の利用を約束して割引を得る契約 |
| **Savings Plans** | 時間あたりの利用額を約束して割引を得る契約 |
| **EDP** | 総額コミットに対する企業向け包括割引契約 |
| **受注残（backlog／RPO）** | 契約済みでまだ売上計上していない金額 |
| **エグレス（データ転送料）** | クラウドからデータを外へ出す際の課金 |
| **Graviton / Trainium / TPU / Maia** | 各社の自社設計CPU・AIチップ |
| **FinOps** | クラウド支出を可視化・最適化する職能と実践 |
| **耐用年数** | 資産を何年で償却するかの前提。利益率を左右する |
