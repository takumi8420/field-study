# 競争構造 ── 3強、中国勢、国産クラウド、そしてGPUクラウド

このノートで分かること：誰がどこで戦っているのか。3強の強みの中身、
日本の国産クラウドとガバメントクラウドの位置づけ、AI時代に現れた新勢力の意味。

## 1. 結論：3強で6割超。ただし勝負の軸が「容量の確保」へ移った

世界のクラウドインフラ支出におけるシェアは、Synergy Research Groupの推計で
**AWS 28%、Microsoft Azure 20%、Google Cloud 15%**（2026年4〜6月期）。3社で6割を超える。

同四半期の世界支出額は**1,434億ドル、前年比約43%増**で8年ぶりの高い伸びとされる。
成長率はAWS約37%、Azure約43%、Google Cloud約82%と差が大きい（同期間、推計・IR）。
AI関連のクラウド支出比率は**2023年の約8%から2026年には約19%**へ上がったとされる。

```
  世界クラウドインフラ支出シェア（2026年4〜6月期、Synergy Research 推計）

  AWS        ████████████████████████████  28%
  Azure      ████████████████████          20%
  Google     ███████████████               15%
  Alibaba    ████                           4%前後
  Oracle     ███                            3%前後
  その他     ██████████████████████████    30%前後
             └ IBM、Tencent、Huawei、ネオクラウド各社、地域事業者
```

> ポイント：シェアの絶対値より**成長率の差**を見るべき局面。
> Google Cloudの伸びが突出しているのはAI案件と受注残の積み上がりによるもので、
> 2026年の競争は価格でも機能でもなく、**「いつGPU容量を渡せるか」**で決まっている。

## 2. 3強の強みの中身

| 事業者 | 出自・強み | 典型的な勝ち方 | 弱点 |
| --- | --- | --- | --- |
| **AWS**（Amazon） | 2006年開始の先行者。サービス数と実績が最多 | スタートアップと新規開発。デファクトの安心感 | 大企業の既存資産との親和性は相対的に弱い |
| **Microsoft Azure** | Windows Server／Office／ライセンス営業の資産 | **既存の企業契約に抱き合わせて入る**。ハイブリッドに強い | 「Microsoft税」への警戒、ライセンス条件への批判 |
| **Google Cloud** | 検索・広告で培った分散基盤とデータ処理、TPU | データ分析（BigQuery）とAI。Kubernetes発祥 | 企業向け営業とサポートの歴史が浅い |

**なぜAzureが2位になれたのか**が理解の鍵。技術で勝ったというより、
**既に全社契約を持っている相手に追加提案した**からである。企業のIT部門はMicrosoftと毎年
ライセンス交渉をしており、その場でクラウドを載せられる。新規開拓するAWSより獲得コストが圧倒的に安く、
[ソフトウェア・SaaS](../06_ソフトウェア・SaaS/README.md) の販売網がそのままインフラの販売網になった例。

**AI時代の差別化軸**は次の3つに整理できる。

```
   ①モデル             ②チップ              ③容量
  ┌──────────┐      ┌──────────┐       ┌──────────┐
  │ AWS      │      │ Trainium │       │ 電力・DC  │
  │ →Anthropic│      │ Inferentia│      │ の確保量  │
  ├──────────┤      ├──────────┤       │           │
  │ Azure    │      │ Maia     │       │ 2026年の  │
  │ →OpenAI  │      │ Cobalt   │       │ 事実上の  │
  ├──────────┤      ├──────────┤       │ 成長上限  │
  │ Google   │      │ TPU      │       │           │
  │ →Gemini  │      │ Axion    │       │           │
  └──────────┘      └──────────┘       └──────────┘
```

有力モデルへの出資・提携でワークロードを引き込み、自社チップで原価を下げ、最後は物理的な容量で決着する。
**3つとも持っているのが3強の実体**である（→ [生成AI](../../01_注目テーマ/01_生成AI/README.md)）。

## 3. 第2グループ ── Oracleの逆転狙いとIBMの立ち位置

| 事業者 | 位置づけ | 特徴 |
| --- | --- | --- |
| **Oracle（OCI）** | 出遅れたが、AI案件の大量受注で存在感が急拡大 | データベースの顧客基盤＋大口AI契約に全振り |
| **IBM Cloud** | 規模では後退。ハイブリッドとコンサルへ転換 | Red Hat（OpenShift）を軸にした「どこでも動く」提案 |
| **Salesforce、SAP など** | 自社SaaSのための基盤 | 純粋なIaaS競争には参加しない |
| **地域事業者（欧州OVH等）** | データ主権需要 | 規模は小さいが規制を追い風にする |

Oracleの動きは2026年のクラウド業界で最も特異なので、数字で押さえておきたい。

| 指標 | 数値 | 時点・出所 |
| --- | --- | --- |
| 残存履行義務（RPO＝受注残） | 約6,640億ドル | 2026年8月末、Oracle 10-Q |
| 1年前のRPO | 約4,550億ドル | 2025年8月末、同社開示 |
| うちOpenAI関連 | 半分前後を占めると報じられる | 2026年、報道・アナリスト推計 |
| 信用格付 | S&Pが2026年7月に格下げ、OpenAI集中を理由に挙げたと報じられる | 2026年、報道ベース |

> ポイント：Oracleは**受注残では3強を上回る数字を出したが、顧客が極端に偏っている**。
> 1社が計画を縮小すれば受注残が一気に毀損する構造で、格付会社が問題視したのもそこ。
> 受注残は「大きいほど良い」ではなく**誰との契約か**とセットで読む。

## 4. 中国勢 ── 別のリーグで戦っている

中国市場は外資が実質的に入れず、国内勢で完結している。

| 事業者 | 位置づけ |
| --- | --- |
| **Alibaba Cloud（阿里雲）** | 中国最大。AI投資を加速 |
| Huawei Cloud | 政府・国有企業に強い |
| Tencent Cloud | ゲーム・SNS基盤が出自 |
| 中国移動／中国電信など通信系 | 国有系の官公需 |

Alibaba Cloudの直近（2026年、同社決算・報道）：AIクラウド／コンピューティング関連売上は四半期で
**484億元、前年比+45%**、AI関連製品は**12四半期連続で3桁成長**とされる。
設備投資は四半期677億元で、3年3,800億元の投資計画を上振れさせる可能性に言及。
2030年までに海外クラウド売上1,000億ドルを目指すと述べたと報じられる。
海外展開は東南アジア・中東が中心で、**米国の輸出規制で最新GPUを調達しにくい**点が構造的なハンデ
（→ [半導体・先端半導体](../../01_注目テーマ/02_半導体・先端半導体/README.md)）。

## 5. 国産クラウドとソブリンクラウド

日本の論点は「なぜ国産が育たなかったのか」と「それでも要るのはなぜか」の2つ。

| 用語 | 定義 | 注意点 |
| --- | --- | --- |
| **国産クラウド** | 日本の事業者が提供するクラウド | 国産であっても主権要件を満たすとは限らない |
| **ソブリンクラウド** | データの所在・運用主体・適用法令まで自国内で完結させるクラウド | 「国内リージョン」だけでは不十分 |
| **データ主権** | データがどの国の法域に服するか | 事業者の本社所在国の法（米CLOUD Act等）も効く |

**国産が育たなかった理由**は感情論ではなく経済性で説明できる。

```
  規模 ─▶ 調達単価が下がる ─▶ 値下げできる ─▶ 顧客が増える ─▶ 規模
   ▲                                                          │
   └──────────────────────────────────────────────────────────┘
   このループを先に回した者が勝つ。日本市場だけを相手にすると
   ①規模が10分の1以下 ②自社チップの開発費を回収できない ③サービス数で勝負にならない
```

国内主要プレイヤー：

| 企業 | 立ち位置 |
| --- | --- |
| **さくらインターネット** | 国産IaaSの代表格。石狩DCを基盤にガバメントクラウド対象に |
| **NTTグループ**（NTTデータ、NTT Com） | 企業向けプライベート／ハイブリッドと海外DC |
| **富士通、NEC** | 官公庁・金融の基幹系。自社クラウド＋ハイパースケーラーの組み合わせ |
| **IIJ、IDCフロンティア、ニフクラ（富士通クラウド）** | 中堅企業向け・特定用途 |
| **KDDI、ソフトバンク** | 通信網と組み合わせた提供。AI向けDC投資も → [通信キャリア](../01_通信キャリア/README.md) |

**それでもソブリンクラウドが要る理由**はコストではなく、
①法執行の域外適用（外国政府が外国事業者にデータ開示を命じうる）
②地政学リスク（制裁・輸出規制でサービスが止まる可能性）
③値上げ・仕様変更への交渉力（依存が深いと受け入れるしかない）の3点。

## 6. ガバメントクラウド ── 制度が需要を作った例

**ガバメントクラウド**＝デジタル庁が整備する、国と地方自治体の共通クラウド基盤。
住民記録・地方税・国民健康保険など**20の基幹業務**を標準準拠システムへ移し、
1,700超の自治体がこの基盤上へ移行することが求められている。

| 論点 | 内容 |
| --- | --- |
| 対象サービス | AWS、Microsoft Azure、Google Cloud、Oracle Cloud Infrastructure に加え、**さくらのクラウド**（2026年4月時点） |
| さくらインターネット | 2023年11月に**条件付き**採択 → 2026年3月27日に全技術要件を満たし正式採択（同社リリース） |
| 狙い | 個別調達をやめて共通基盤に集約し、コストと運用負荷を下げる |
| 現実 | 移行の遅れやコスト増が各所で報じられており、「3割削減」の当初想定どおりには進んでいないとされる（報道ベース） |

> ポイント：ガバメントクラウドは**技術の話ではなく制度設計の話**。
> 「国内事業者が1社でも土俵に上がっている」こと自体が政策目的であり、
> 価格競争力で外資に並んだから選ばれたわけではない。条件付き採択から正式採択まで約2年半かかった。

自治体側の移行実務は [SIer・ITサービス](../05_SIer・ITサービス/README.md) が担い、
標準準拠システムへの改修と移行が同時に走るため、SIerには数年分の需要になっている。

## 7. GPUクラウド（ネオクラウド）という新勢力

2023年以降、**AI学習・推論向けGPUだけを貸す専業事業者**が急成長した。
総称して「ネオクラウド」と呼ばれる。

| 事業者 | 出自 | 2026年の状況（決算・報道ベース） |
| --- | --- | --- |
| **CoreWeave** | 暗号資産マイニングから転換 | 四半期売上約25.8億ドル（前年比+112%）、受注残約1,040億ドル、2026年設備投資350〜390億ドル |
| **Nebius** | 旧Yandexの欧州事業から分離 | 四半期売上5.82億ドル（前年比+454%）、顧客コミット400億ドル超 |
| Lambda、Crusoe、Nscale 等 | GPU専業・電力起点 | 電力確保と組み合わせた展開 |
| IREN、TeraWulf 等 | マイニング事業者からの転換 | 既存の電力契約を武器にする |

**なぜ専業が成立したのか**：

```
  ハイパースケーラー              ネオクラウド
  ┌────────────────┐         ┌────────────────┐
  │ 数百のサービス   │         │ GPUだけ          │
  │ 全業種の顧客     │         │ AI企業数社        │
  │ 多重の冗長性     │  対比   │ 冗長性は最小限     │
  │ 長い設計・調達   │ ──────▶ │ 最短で立ち上げる   │
  │ 汎用の価格表     │         │ 大口の相対契約     │
  └────────────────┘         └────────────────┘
     「何でも屋」                 「単機能・速い・安い」
```

AI事業者が欲しいのは総合商社型のクラウドではなく、**今すぐ使える大量のGPUと、それを冷やせる電力**。
機能を削ぎ落とした分だけ早く安く提供できる余地があり、そこに専業が入り込んだ。
**ただしリスク構造は3強とまるで違う**。

| リスク | 中身 |
| --- | --- |
| 顧客集中 | 数社への依存。1社の契約見直しで事業が傾く |
| 資金調達 | GPU購入を借入や社債で賄う。金利と評価額に敏感 |
| 陳腐化 | GPUの世代交代が速く、償却期間の前提が崩れうる |
| 循環取引の疑念 | GPUメーカーが顧客にも出資する構図が指摘されている（報道ベース） |

粗利の構造が「自社設計ハードで原価を下げる」3強と異なり、ネオクラウドは**原価の大半をNVIDIAに握られている**。
この差は [02_儲け方と経済性](02_儲け方と経済性.md) の観点で決定的である。

## 8. マルチクラウドの実態 ── 建前と現場

「特定ベンダーに依存しないためマルチクラウドにする」は建前としてよく語られるが、
実務での姿はもう少し散文的である。

| よくある実態 | 説明 |
| --- | --- |
| **成り行きのマルチクラウド** | 買収した会社が別クラウドを使っていた、部署ごとに別々に契約した |
| **用途別の使い分け** | 基幹はAzure、データ分析はGoogle Cloud、AI学習はGPUクラウド |
| **交渉カードとしての第2社** | 実際の移行はしないが、見積比較の材料にする |
| **真の冗長化** | 同じシステムを2クラウドで動かす。コストが跳ね上がるため稀 |

国内上場企業向け調査では、マルチクラウド運用の課題の上位は
「セキュリティ・ID管理」「ガバナンスとポリシー管理」「コストの可視化と最適化」（2026年、調査ベース）。
つまり**技術的に動かせるかより、統制できるか**が問題になっている。

EU Data Actによる乗り換え料金の禁止（2027年1月12日から）はこの状態を制度で緩める試みだが、
**本当のロックインは転送料ではなくマネージドサービスへの依存**にある。
固有APIで書かれたアプリは、転送料がゼロでも書き直さないと動かない。

## 9. 参入障壁と、それでも崩れうる点

| 障壁 | 高さ | 崩れうる条件 |
| --- | --- | --- |
| 資本（年間1,000億ドル超の設備投資） | 非常に高い | 特定用途に絞れば小規模でも成立（ネオクラウドの例） |
| サービス数・エコシステム | 高い | AI用途では「GPUだけ」で足りるため効かない |
| 自社設計チップ | 高い | 開発費を回収できる規模が要る |
| **電力・用地の確保** | **2026年時点で最も高い** | → [データセンター](../03_データセンター/README.md) |
| ロックイン（エグレス・固有API） | 中〜高 | EU規制で転送料側は弱まる。API依存は残る |
| 政府調達・主権要件 | 制度次第 | **制度が国内勢に市場を作る**（ガバメントクラウド） |

> 結論：総合クラウドとして3強に正面から挑むのは事実上不可能に近い。崩しうるのは
> **①用途を絞る ②制度で守られた領域に立つ ③物理資源（電力）を先に押さえる**の3つ。日本が狙えるのは②と③。

## 用語メモ

| 用語 | 意味 |
| --- | --- |
| **ハイパースケーラー** | AWS／Azure／Google Cloud等の超大規模クラウド事業者 |
| **ネオクラウド（GPUクラウド）** | AI向けGPU提供に特化した新興事業者。CoreWeave、Nebius等 |
| **RPO（残存履行義務）** | 契約済みで未計上の売上。受注残に相当する会計用語 |
| **ソブリンクラウド／データ主権** | データの所在・運用・適用法令を自国内で完結させるクラウド。どの国の法域に服するかという論点 |
| **CLOUD Act** | 米国事業者に対し国外保管データの開示を求めうる米国法 |
| **ガバメントクラウド** | デジタル庁が整備する国・自治体共通のクラウド基盤 |
| **標準準拠システム** | 自治体の基幹20業務を国の標準仕様に合わせたシステム |
| **マルチクラウド** | 複数のパブリッククラウドを併用すること |
| **EU Data Act** | EUのデータ法。乗り換え料金を2027年1月12日から禁止 |
