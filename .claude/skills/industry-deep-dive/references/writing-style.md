# 執筆の作法

## 1. 基本姿勢

- 読者は**その業界を知らない人**。前提知識を要求しない
- **結論を先に書く**。「つまり何なのか」を最初の2行で言う
- **「なぜそうなるか」を必ず添える**。事実の列挙は教科書にならない
  - ✕「ファウンドリの利益率は装置償却に左右される」
  - ○「コストの大半が装置の減価償却なので、**稼働率が落ちた瞬間に赤字**になる」
- 専門用語は**初出で必ず噛み砕く**。カッコ書きで一言でよい
- 読み方を推測しにくい外国企業名は、ページ内の初出で **`NVIDIA（エヌビディア）`** のようにカタカナ読みを添える。企業名を用語集へ載せる場合も説明の冒頭を「読み：〜」にする
- 断定できないことは断定しない（「〜とされる」「推計」「報道ベース」）

## 2. 構成の作法

- 見出しは `## 1. 〜` と**番号を振る**。目次（TOC）が読みやすくなる
- 1見出しあたり 5〜15 行。長くなったら小見出し `###` に割る
- 各ノートの末尾に **「用語メモ」** を置く。原則として `用語 | 意味` の2列表にし、用語だけの列挙や空欄で終わらせない
- 冒頭に「このノートで分かること」を1〜2行書く

## 3. 図と表を使う

文章の羅列にしない。以下を積極的に使う。

**比較・分類 → 表**

```markdown
| 類型 | やること | 代表企業 | 経済的な特徴 |
| --- | --- | --- | --- |
```

**流れ・構造 → ASCIIの図**（コードブロックに入れる。サイト側で等幅・横スクロール対応）

```
仕様・設計 ──▶ 部材調達 ──▶ 製造 ──▶ 販売
 ファブレス      商社        受託      量販店
```

**強調したい因果 → 引用ブロック**

```markdown
> ポイント：設計と製造が分かれていることが、この業界を理解する最大の鍵。
```

## 4. 数値の書き方

- **必ず年を添える**：「2024年時点で約6,000億ドル」
- 出典の種類を書く：統計（WSTS、経産省）／IR／報道／推計
- 桁と単位を揃える。国内と世界を混ぜない
- 変動が激しい数値には「最新は◯◯で確認」と添える
- 為替が絡む数値は前提レートに触れる

## 5. リンクの作法

- 同じフォルダ内：`[前工程](02_前工程.md)`
- 別業界：`[電力](../../11_資源・エネルギー・鉄鋼金属/04_電力/README.md)`
- **`.md` のまま書く**。サイト生成時に `.html` へ自動変換される
- 相互リンクを張る（片方向で終わらせない）

## 6. 品質チェックリスト（提出前に自分で確認）

- [ ] 冒頭2行で「この業界は何か」が分かるか
- [ ] 専門用語がすべて説明されているか
- [ ] 読み方を推測しにくい外国企業名の初出にカタカナ読みがあるか
- [ ] 表または図が**最低2つ**入っているか
- [ ] 数値に年と出典があるか
- [ ] 「なぜそうなるか」の説明が各章にあるか
- [ ] 他ノート・用語集への相互リンクがあるか
- [ ] 末尾に用語メモがあるか
- [ ] README のノート索引表が更新されているか
- [ ] `- 状態:` と `- 更新日:` が更新されているか

## 7. 避けること

- ❌ 企業名の羅列だけで説明した気になる
- ❌ 「重要です」「注目されています」だけで中身がない
- ❌ 一般論（「DXが進んでいます」）。その業界固有の話を書く
- ❌ 感想・評価の押し付け。事実と解釈を分ける
- ❌ 同じ内容を複数ノートに重複して書く
- ❌ 見出しだけ立てて中身が薄い章を作る
