① 技術の仕組み ── ブロックチェーンは何を解決した装置なのか

金融暗号資産

このノートで分かること：暗号資産の土台であるブロックチェーン＝改ざんしにくい共有台帳が、
なぜ銀行のような「信頼できる第三者」なしで動くのか。そして何は解決していないのか。

結論を先に：ブロックチェーンは「誰も管理者がいない状態で、台帳の中身について全員の意見を一致させ続ける」ための仕組み。
高速でも安くでも便利でもない。管理者を置けない／置きたくない場面でだけ、そのコストに見合う。

1. そもそも「お金を送る」とは台帳を書き換えることでしかない

銀行振込で実際に動いているのは、現金ではなく帳簿の数字である。

【銀行の場合】台帳は1つ。銀行だけが書き込める

   Aさん ──「Bに1万円送って」──▶ ┌──────────────┐
                                  │  銀行の台帳    │
                                  │  A: 10万 → 9万 │
                                  │  B:  3万 → 4万 │
                                  └──────────────┘
                                   ↑ 書けるのは銀行だけ
   信頼の根拠 = 銀行が免許を持ち、規制され、潰れにくいこと

この方式は極めて効率がよい。書き込む人が1人なので、順番でもめない。
ただし銀行が書き換えを拒否したり、記録を消したり、破綻したりすると終わる。
国境をまたぐと、この「1つの台帳」が存在せず、銀行同士のコルレス契約を数珠つなぎにするため遅く高くなる
（→ 決済はどう流れ誰が取り分を得るか）。

ブロックチェーンは、ここで「台帳を全員に配る」という逆の解き方をした。

【ブロックチェーンの場合】台帳のコピーを世界中のPCが持つ

   ┌───────┐   ┌───────┐   ┌───────┐   ┌───────┐
   │ 台帳   │◀─▶│ 台帳   │◀─▶│ 台帳   │◀─▶│ 台帳   │  … 数千〜数万台
   │ コピー │   │ コピー │   │ コピー │   │ コピー │
   └───────┘   └───────┘   └───────┘   └───────┘
        ▲  全員が同じ中身を持つ。1台が嘘をついても多数派が正しい版を維持
        │
   取引データはブロックにまとめられ、
   [ブロック1]←[ブロック2]←[ブロック3]← … と「前のブロックの要約」で鎖状につながる
   → 途中を書き換えると以降の全ブロックの要約が合わなくなる = 改ざんがバレる

この「鎖」がブロックチェーンという名前の由来。
要約に使うのがハッシュ関数（どんなデータからも固定長の値を作る計算。元に戻せず、1文字変えると値が全く変わる）である。

2. 「信頼できる第三者なし」を支える3つの部品

管理者を置かずに台帳を保つには、次の3つがそろう必要がある。どれが欠けても成立しない。

部品 解いている問題 使う技術
本人確認「その残高を動かす権利が本当にあるか」公開鍵暗号（電子署名）
改ざん検知「過去の記録が書き換えられていないか」ハッシュ関数による連鎖
順番の合意「同じコインを2回使う取引が2つ来たとき、どちらを正とするか」合意形成（PoW／PoS）

3つめが一番むずかしい。これを二重支払い問題という。
デジタルデータはコピーが自由なので、同じ1BTCを同時に2人へ送る取引を両方ばらまける。
中央の管理者がいれば「先に着いた方が勝ち」と決めればよいが、管理者がいないと
「どちらが先か」を誰が決めるのかが決まらない。2008年のビットコインの論文は、ここに答えを出した点が新しかった。

3. 合意形成 ── PoWとPoSは「嘘をつくと損をする」設計

答えの骨子は、台帳に書き込む権利を得るのにコストを払わせ、不正をするとそのコストが没収されるようにすること。

方式 書き込む権利の取り方 不正のときに失うもの 代表 弱点
PoW（プルーフ・オブ・ワーク／仕事量の証明）大量の計算を最初に解いた人使った電気代と設備ビットコイン電力消費が大きい
PoS（プルーフ・オブ・ステーク／預け入れの証明）通貨を担保として預けた人から抽選預けた通貨（一部没収＝スラッシング）イーサリアム（2022年9月移行）富が集中しやすいという批判

PoWでは、計算競争に勝った人（マイナー＝採掘者）が次のブロックを作り、報酬として新規発行分の通貨と手数料を受け取る。
不正なブロックを作っても他のノードに拒否され、投じた電気代だけが無駄になる。
「正直にやった方が儲かる」から正直になるというのが核心で、道徳ではなく経済の設計である。

ポイント：合意形成は「安全のために電気やお金を燃やしている」。
これは無駄ではなくセキュリティの購入費にあたる。だからブロックチェーンは構造的に高コストになる。

51%攻撃と「確定しない」ファイナリティ

計算力（PoW）や預け入れ量（PoS）の過半を1者が握ると、台帳を書き換えられる。これが51%攻撃。
またPoWでは厳密には「絶対に確定」がなく、ブロックが何個か積み上がるほど覆りにくくなるという確率的な確定しかない。
取引所が入金反映に「6承認待ち」などを課すのはこのためである。
銀行送金のように「着金した＝終わり」ではない点が、決済インフラとして使うときの制約になる。

4. ウォレットと秘密鍵 ── 「銀行口座」ではなく「印鑑そのもの」

一番誤解されやすい部分。ウォレットは財布ではなく、鍵束である。

【鍵の関係】

   秘密鍵（誰にも見せない長い数字）
      │  一方向の計算（戻せない）
      ▼
   公開鍵 ──▶ アドレス（1A1zP1... のような文字列。口座番号にあたる）

   送金するとき = 秘密鍵で取引データに電子署名する
   受け取る人・第三者 = 公開鍵で「確かにその鍵の持ち主が署名した」と検証できる

   ※ コインはウォレットの中に入っていない。
      ブロックチェーン上に「このアドレスの残高」として記録されているだけ。
      ウォレットが持つのは秘密鍵だけ。

つまり秘密鍵を失う＝資産に永久に触れなくなる、秘密鍵が漏れる＝全部持ち去られる。
銀行のような「本人確認して再発行」も「不正送金の取り消し」も、管理者がいない以上できない。

保管方法 秘密鍵を持つ人 長所 短所
取引所に預ける（カストディ）取引所楽。パスワード再発行できる取引所が破綻・流出すると失う（→ 規制と事故の歴史）
ホットウォレット（ネット接続のアプリ）本人すぐ使える端末のマルウェア・フィッシングに弱い
コールドウォレット（専用端末・紙）本人ネットから切り離せる紛失・盗難・相続で詰む

日本の規制が「顧客の暗号資産は原則コールドウォレットで分別管理」を求めるのは、
過去の流出事件がすべてホットウォレットから起きたからである。

5. ビットコインとイーサリアム ── 設計思想がまるで違う

同じ「暗号資産」でも、この2つは目的が別物。混ぜて理解すると必ず混乱する。

ビットコイン（2009年〜） イーサリアム（2015年〜）
目的価値の保存・送金に絞るプログラムを動かす基盤（世界共有のコンピュータ）
台帳が持つもの誰がいくら持つか（UTXO方式）残高＋任意のプログラムの状態
発行量上限2,100万枚。約4年ごとに新規発行が半減（半減期）上限なし。手数料の一部を焼却（バーン）する設計
合意形成PoW2022年9月にPoWからPoSへ移行（The Merge）
思想変えないことが価値。機能追加に極めて保守的機能追加を続ける。アップグレード前提
時価総額約1.54兆ドル（2026年5月時点、報道・集計ベース）約2,556億ドル（同時点）

ビットコインは「書き換えられない金」を目指し、機能を削ぎ落とした。
イーサリアムは「その上でアプリが動く土台」を目指し、複雑さを引き受けた。
後述のDeFiもNFTも、ほぼイーサリアム系の発明である（→ 事業としての暗号資産）。

6. スマートコントラクト ── 自動販売機のような契約

スマートコントラクトとは、ブロックチェーン上に置かれた条件を満たすと自動で実行されるプログラム。
「契約書」という訳語から法律文書を連想しやすいが、実体は止められない自動販売機に近い。

【従来】                        【スマートコントラクト】

 A ──契約書──▶ B                A ──送金──▶ ┌────────────┐
      │                                      │ プログラム │──▶ Bへ自動送付
      ▼ 履行しない                           │ (公開・不変)│
   裁判所・銀行などの                        └────────────┘
   第三者が強制執行                            ↑ 第三者不要。だが
                                                バグも「仕様通り」に実行される

利点は仲介者への信頼が要らないこと。欠点は間違いを直せないこと。
バグを突いた資金流出（The DAO事件、2016年）や、DeFiの脆弱性を突いた盗難が繰り返されてきた。
「コードが法である」は、コードが間違っていても法であるという意味でもある。

7. レイヤー2 ── 「遅い・高い」をどう回避しているか

ブロックチェーンは全員が同じ処理を繰り返す構造なので、本質的に遅い。
ビットコインは毎秒7件程度、イーサリアムも十数件程度とされる（設計値ベース）。
クレジットカードの国際ブランドが毎秒数万件をさばくのと比べると3〜4桁違う。

そこで、本体（レイヤー1）の外で取引をまとめ、結果だけを本体に書き戻す発想が生まれた。これがレイヤー2。

 レイヤー2（Arbitrum, Optimism, Base, Lightning など）
   ├ 1,000件の取引をここで処理
   └ 「まとめた結果＋正しさの証拠」だけをレイヤー1へ1回書き込む
        │
        ▼
 レイヤー1（イーサリアム／ビットコイン本体）＝ 最終的な決着の場

手数料は大幅に下がるが、レイヤー2ごとに前提が違う（誰が結果をまとめるか、不正をどう止めるか）。
「イーサリアムだから安全」とは言えず、L2運営者への信頼が部分的に戻ってくる点は押さえておきたい。

8. 「ブロックチェーンなら何でも解決する」という誤解を潰す

2017〜2018年ごろ、サプライチェーン管理、投票、証明書、医療記録……あらゆる領域に
「ブロックチェーンで」という提案が出て、その多くが実証実験で終わった。理由は単純である。

よくある期待 実際
「改ざんできないから記録が正しくなる」正しいのは書かれた後だけ。嘘を書き込むこと自体は防げない（＝オラクル問題）。産地偽装は入力段階で起きる
「仲介者がいなくなって安くなる」合意形成のコストを全員で払うので、管理者1人の方が普通は安い。データベースで足りるなら DB が正解
「分散しているから落ちない」落ちにくいのは台帳だけ。取引所・ウォレット・ブリッジという周辺のシステムが弱点で、事故はほぼそこで起きる
「匿名だからプライバシーが守れる」逆。取引は全部公開で永久に残る。アドレスと本人が一度でも結びつくと過去が全部たどれる
「スマートコントラクトで自動化すれば安心」バグも自動実行される。修正できないことが弱点にもなる

判定の目安：「管理者を1人決められるか？」 決められるなら普通のデータベースが速くて安くて直せる。
決められない（国をまたぐ、参加者が互いに信用しない、検閲されたくない）場面ではじめてブロックチェーンが効く。

暗号資産がこの条件に当てはまるのは、「誰の許可も得ずに世界中へ価値を動かす」という用途だからである。
逆に言えば、その自由は取り消しができない・保証機関がいないという代償とセットになっている。

9. リスクは技術の性質から出てくる

技術の話は、そのままリスクの話でもある。投資判断とは無関係に、事実として次が成り立つ。

  • 取り消せない：誤送金・詐欺送金の巻き戻しは原則できない。振込の組戻しに相当する手段がない
  • 価格が大きく動く：裏付け資産や利息のない通貨の価格は需給だけで決まり、短期間に数十%動いた例が繰り返しある
  • 鍵を失えば終わり：忘却・故障・相続で到達不能になった残高が相当量あるとされる
  • 周辺が狙われる：取引所・ブリッジ・個人の端末が主な攻撃面。2025年2月のBybit流出（約14〜15億ドル相当と報道）はその最大級の例
  • 詐欺が発生しやすい：高利回りをうたう案件、偽の取引所やサポート、SNS経由の勧誘が継続的に報告されている
