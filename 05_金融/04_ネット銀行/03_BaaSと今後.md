# BaaSと今後 ― 銀行免許を「貸す」商売と、これから効いてくる3つのコスト

このノートで分かること：ネット銀行の次の収益源は **BaaS（バース、Banking as a Service）＝自分の銀行免許とシステムを他社に使わせる商売**。
併せて、今後の損益を左右する3つのコスト ― **本人確認（eKYC）／不正送金・詐欺対策／預金の調達コスト** を分解する。

> ポイント：ネット銀行は「口座を集める会社」から「**銀行機能を卸す会社**」へ軸足を移しつつある。
> 自社ブランドで顧客を取るより、他社ブランドの裏側に回ったほうが、固定費であるシステムをもう一度使い回せるから。

## 1. BaaSとは何か ― 免許を持つ側と、顧客を持つ側の分業

銀行業は**免許事業**である。預金を集めるには銀行免許が要り、取得には自己資本・システム・体制の審査が伴う。
一方、航空会社や鉄道会社やECは**大量の顧客と接点**を持っているが、免許は持っていない。
この2つを組み合わせるのがBaaSで、日本では **銀行代理業**（銀行に代わって預金・貸出の契約を媒介する登録業）という制度の上に成り立っている。

```
【BaaSの三者構造】

   利用者                事業会社（顧客を持つ側）           銀行（免許を持つ側）
 ┌────────┐         ┌───────────────────┐        ┌──────────────────┐
 │ 航空会社の │  口座  │ 自社アプリ／自社ブランド │  API   │ 勘定系システム     │
 │ アプリから │ ────▶ │ 銀行代理業の登録を取る   │ ────▶ │ 預金・為替・貸出   │
 │ 口座を開く │        │ マーケ・顧客対応を担当   │        │ 免許・コンプラを担当│
 └────────┘         └───────────────────┘        └──────────────────┘
       ▲                        │                              │
       │  マイル・ポイント等の特典 ◀─┘                        └─▶ 預金が積まれ、
       └── 利用者は「その会社の銀行」を使っている感覚               システムの固定費が薄まる
```

分業の線はこうなる。

| 担当 | 事業会社（ブランド側） | 銀行（免許側） |
| --- | --- | --- |
| 顧客獲得・広告 | ○（自社会員に告知するだけで済む） | × |
| アプリ・UI | ○（自社アプリに埋め込む） | △（提供する場合もある） |
| 銀行免許・預金保険 | × | ○ |
| 勘定系システム・障害対応 | × | ○ |
| マネロン対策・本人確認の最終責任 | △（一次対応） | **○（免許側が負う）** |
| 経済的な取り分 | 手数料・ポイント原資・自社サービスへの送客 | 口座から生まれる利ざやと手数料の大半 |

> なぜ成立するか：銀行側のシステムは**固定費**（[① ネット銀行の経済性](01_ネット銀行の経済性.md) 参照）。
> 一度作った勘定系に他社ブランドの口座を相乗りさせれば、追加コストはほぼ増えずに預金だけが増える。
> 事業会社側は、免許取得という最大の参入障壁を**登録業（銀行代理業）で迂回**できる。両者の利害が一致する。

## 2. BaaSには2つの型がある

一口にBaaSと言っても、事業会社がどこまで銀行の顔をするかで型が分かれる。

| 型 | 中身 | 利用者から見えるもの | 代表例 |
| --- | --- | --- | --- |
| **① ブランド支店型**（NEOBANK／パートナー支店） | 銀行の中に事業会社ブランドの「支店」を作る。口座は銀行の口座 | 「○○NEOBANK」「○○ BANK」という名前の口座 | ドコモSMTBネット銀行のNEOBANK各種、楽天銀行のJRE BANK、みんなの銀行のパートナー支店 |
| **② API提供型**（組込型金融） | 銀行機能をAPIで切り出し、事業会社のサービスに部品として埋め込む | 送金・入出金明細・口座振替などの機能だけ | GMOあおぞらネット銀行のAPI、みんなの銀行のAPI提供モデル |

```
【①ブランド支店型 と ②API提供型】

  ① ブランド支店型                      ② API提供型
  ┌───────────────┐              ┌───────────────┐
  │ 利用者は「JAL の銀行」 │              │ 利用者は「会計ソフト」 │
  │ を使っていると思う      │              │ を使っていると思う     │
  └────────┬──────┘              └────────┬──────┘
           │ 口座そのものを持たせる                 │ 機能だけ借りる
           ▼                                        ▼
    口座数・預金が直接増える                  件数課金・振込手数料が増える
    → 銀行のバランスシートが厚くなる          → 銀行は「決済のインフラ」になる
```

### 主な担い手（2025〜2026年の公表ベース）

| 銀行 | BaaSの呼び名 | 状況 |
| --- | --- | --- |
| **ドコモSMTBネット銀行**（旧・住信SBIネット銀行） | NEOBANK | BaaSの先行者。JAL、ヤマダ、高島屋、京王、日本ハムファイターズなど事業会社ブランドの銀行サービスが並ぶ |
| **楽天銀行** | BaaS／楽天銀行支店方式 | JR東日本の **JRE BANK** を受託。2024年5月開始で4か月に約39万件、**1年で約54万口座**と報じられる |
| **みんなの銀行**（ふくおかフィナンシャルグループ） | みんなのBaaS | **BaaSパートナー企業30社超**（2025年12月公表）。メルペイ連携は2025年12月開始。2026年度中に1人最大5支店の口座開設に対応予定 |
| **GMOあおぞらネット銀行** | 法人API | 会計・請求SaaSとの接続に特化（→ [② 各社の出自と戦略の違い](02_各社の出自と戦略の違い.md)） |

- 世界のBaaS市場は2025年の約8,360億ドルから2026年に約1兆109億ドルへ、と調査会社は**推計**している（年率20%超）。桁感の参考として扱う。
- 日本の事例は「銀行免許を持たない事業会社がブランド銀行を出した」という**報道・各社リリースベース**の把握で足りる。

## 3. 事業会社はなぜ銀行をやりたがるのか

単に手数料が欲しいのではない。狙いは**顧客の資金が置かれる場所を押さえること**。

1. **解約されにくくなる**。給与振込や公共料金の引落を指定された口座は、乗り換えコストが高くて動かない
2. **自社サービスへの原資が作れる**。口座残高や給与振込を条件にポイント・運賃割引・マイルを配れる
3. **顧客データが増える**。どこでいくら使っているかは、自社のECや会員施策に直結する
4. **免許を取らずに済む**。銀行免許の取得・維持（自己資本、検査対応、システム）を負わない

> 裏返すと、事業会社が受け取るのは「金融の利益」ではなく「**本業の顧客維持**」である。
> だからBaaSの成否は、その事業会社が**どれだけ日常的な接点を持っているか**でほぼ決まる。
> 鉄道・航空・携帯・ECのように「毎月必ず触る」ブランドが強いのはこのため。

## 4. 口座開設のデジタル完結とeKYC ― 2027年に前提が変わる

ネット銀行もBaaSも、**口座開設が画面の中で完結する**ことが大前提。これを支えるのが **eKYC**（electronic Know Your Customer、電子的な本人確認）。
郵送・対面なしで、スマホのカメラや公的個人認証で「本人であること」を確認する仕組みで、**犯罪収益移転防止法（犯収法）**が方式を定めている。

```
【本人確認方式の移り変わり】

  〜2010年代          現在（2026年）              2027年4月〜（改正犯収法）
  ┌──────────┐    ┌───────────────┐     ┌──────────────────┐
  │ 書類を郵送    │ →  │「ホ方式」            │  →  │ 公的個人認証（JPKI）に  │
  │ 転送不要郵便で│    │ 本人の顔＋本人確認書類 │     │ 原則一本化             │
  │ 受取確認      │    │ の画像を撮って送る     │     │ ＝マイナンバーカードの │
  └──────────┘    └───────────────┘     │   ICチップ読み取り     │
    数日〜1週間          数分〜数時間             └──────────────────┘
                         ※偽造書類に弱いと指摘        偽造が事実上できなくなる
```

- 改正犯収法により、**2027年4月から非対面の本人確認は原則としてマイナンバーカードのICチップ読み取り（JPKI）へ一本化**され、
  現在主流の「**ホ方式**（顔と本人確認書類の画像送付）」は廃止される予定。カード未保有者向けに郵送方式は残る見込みと報じられている。
- メガバンク3行はホ方式での口座開設を**2026年度中に取りやめる**方向と報じられている（日本経済新聞、2025年9月）。
- ネット銀行にとっての意味は両面ある。

| 影響 | 内容 |
| --- | --- |
| **プラス** | 偽造書類による不正な口座開設（＝詐欺の道具にされる口座）を根元で減らせる。事後の凍結・調査コストが下がる |
| **プラス** | 確認が機械的に終わるため、目視チェックの人手が要らなくなる＝ネット銀行の経済性と相性が良い |
| **マイナス** | **マイナンバーカードを持っていない／読み取れない人は口座を開けない**。申込の途中離脱が増える |
| **マイナス** | アプリのICチップ読み取り機能の開発・改修が必要。BaaSでは事業会社側のアプリにも波及する |

> 覚え方：**本人確認の厳格化は、口座獲得競争の「入口を狭くする」規制**。
> 会員基盤をすでに持つ経済圏系・BaaSの受託側に有利で、新規に一から顧客を集める銀行には向かい風になる。

## 5. 不正送金・特殊詐欺対策という「全行に等しくかかる固定費」

もう一つの重いコストが、犯罪対策。フィッシング（銀行を装ったSMS・メールで偽サイトに誘導し、IDやワンタイムパスワードを盗む手口）による
インターネットバンキングの不正送金と、詐欺に使われる口座の問題が続いている。

- 金融庁は警察庁と連名で、**2025年9月12日に「法人口座及びインターネットバンキングの利用を含む預貯金口座の不正利用等防止に向けた対策の一層の強化」を要請**している。
- 全国銀行協会は**不正利用口座の情報を金融機関間で共有する枠組み**の検討会を設置した（2025年1月公表）。
- 金融庁は「マネー・ローンダリング等及び金融犯罪対策の取組と課題」を継続的に公表している（直近は2026年7月）。
- 特殊詐欺・SNS型投資詐欺を含む被害は近年急増していると報じられるが、統計の集計範囲が年ごとに変わるため、**最新は警察庁の公表統計で確認**すること。

```
【なぜ対策コストは小さい銀行ほど重いか】

  必要になるもの（規模にかかわらずほぼ同じ一式）
   ├ 不正検知（取引モニタリング）システム
   ├ 24時間の監視・照会対応体制
   ├ 認証の強化（ワンタイム、生体、デバイス認証）
   ├ 当局・警察との照会対応、口座凍結の実務
   └ 被害の補償原資

        1口座あたりの負担
   大手 ──────▏               口座が多いので薄まる
   小規模 ──────────────▏   同じ一式を少ない口座で割る＝重い
```

> ここがネット銀行の構造的な弱点。[① ネット銀行の経済性](01_ネット銀行の経済性.md) で見たとおり、ネット銀行の強さは
> 「固定費を口座数で薄める」ことにある。**犯罪対策コストという新しい固定費**は、その論理をそのまま裏返す。
> 規模のない新規参入行ほど、この一式を背負いきれない。**再編・撤退・BaaS受託への転換**が起きる理由がここにある。

## 6. 金利上昇局面の預金獲得競争 ― 「集める」ことがコストになった

長らく日本の預金金利はほぼゼロで、預金は**ただ同然の調達手段**だった。金利が上がると、この前提が崩れる。

- 日銀の利上げを受け、メガバンク3行の普通預金金利は**2026年2月に年0.2%→0.3%**、**2026年8月3日から年0.4%**へ引き上げられたと報じられている。
- ネット銀行側はさらに上を出しており、2026年には**普通預金で年1%に届く銀行**（あおぞら銀行BANK支店の年1.00%・上限100万円など、比較サイト・報道ベース）も現れた。

```
【預金金利が上がると、どこが痛むか】

  金利0%の世界                     金利1%の世界
  預金 100 ── 調達コスト 0         預金 100 ── 調達コスト 1.0
   ↓                                ↓
  貸出 100 ── 利息 1.0             貸出 100 ── 利息 2.0
   ＝ 利ざや 1.0（丸取り）           ＝ 利ざや 1.0（見かけ上は同じ）
                                     ▲
                        だが実際は ①預金金利は即日上がる
                                   ②住宅ローン変動金利の改定は半年〜1年遅れる
                                   ③金利で集めた預金は、次に高い所へすぐ移る
                                   → 一時的に利ざやが潰れ、調達が不安定になる
```

この「預金金利がどれだけ市場金利に連動して上がってしまうか」の度合いを **預金ベータ** という。

| | 既存の大手・地域銀行 | ネット銀行 |
| --- | --- | --- |
| 預金の集まり方 | 給与振込・事業決済・地縁で自然に集まる | **金利とポイントで集める** |
| 預金ベータ（市場金利への連動度） | 低い（金利を上げなくても逃げにくい） | **高い**（上げないと出ていく） |
| 金利上昇の初期 | 利ざや拡大でプラスになりやすい | 調達コスト先行で**一時マイナス**もある |
| 打ち手 | 手数料ビジネス、法人取引 | 住宅ローン金利の引き上げ、証券・決済との連携強化、BaaSでの受託預金 |

実際、2026年3月期はソニー銀行の当期純利益が115.6億円（前期比−25.3%）、auじぶん銀行が46.1億円（同−68.5%）と、
金利上昇局面にもかかわらず減益となった（各行決算）。**金利上昇＝ネット銀行の追い風、とは限らない**。

## 7. これからの見立て（確定事実ではなく論点の整理）

```
【ネット銀行が向かう2方向】

   自社ブランドで顧客を取り続ける           他社ブランドの裏方に回る
   ┌────────────────┐            ┌────────────────┐
   │ 経済圏の入口として戦う    │            │ BaaSで免許とシステムを卸す │
   │ 楽天・PayPay・au・ドコモ  │            │ ドコモSMTB／楽天／みんなの │
   └────────────────┘            └────────────────┘
        競争軸＝金利・ポイント                    競争軸＝システムの使い勝手
        コスト＝調達コスト・獲得コスト            コスト＝開発・運用・コンプラ
                 ＼                          ／
                  ＼   どちらも効いてくる制約  ／
                   ▼                        ▼
            本人確認の厳格化（2027年4月〜）／犯罪対策の固定費
                   → 規模のない行ほど耐えられない → 再編圧力
```

押さえるべき論点は4つ。

1. **BaaSは「口座数」より「相手の顧客接点の質」で決まる**。毎月触るブランドでなければ口座は死蔵される
2. **免許側の責任は移らない**。マネロン・本人確認の最終責任は銀行側に残るため、受託を増やすほど管理負担も増える
3. **規制コストは固定費**。口座あたりで薄められない小規模行から先に苦しくなる
4. **調達コストが主戦場に戻った**。「安い原価で高い金利を配る」モデルは、原価より調達が高くつく局面で試される

## 用語メモ

| 用語 | 意味 |
| --- | --- |
| **BaaS（Banking as a Service）** | 銀行が免許・勘定系システムを他社に提供し、他社ブランドで銀行サービスを出させる仕組み。「銀行免許を貸す」商売 |
| **銀行代理業** | 銀行に代わって預金・貸出・為替の契約締結を媒介する登録業。事業会社がBaaSでブランド銀行を出す法的な足場 |
| **組込型金融（エンベデッド・ファイナンス）** | 非金融サービスの中に決済・与信・保険などの金融機能を埋め込むこと。BaaSはその供給側の仕組み |
| **eKYC** | electronic Know Your Customer。オンラインで完結する本人確認 |
| **犯収法（犯罪収益移転防止法）** | マネーロンダリング防止のため、本人確認や疑わしい取引の届出を義務づける法律。eKYCの方式もここで定まる |
| **ホ方式** | 本人の容貌と本人確認書類の画像を送信して確認する現行のeKYC方式。2027年4月の改正で廃止予定 |
| **JPKI（公的個人認証）** | マイナンバーカードのICチップの電子証明書で本人性を確認する仕組み。改正後の非対面確認の中心になる |
| **預金ベータ** | 市場金利の上昇分のうち、どれだけを預金金利に反映せざるを得ないかの度合い。高いほど調達コストが跳ねやすい |
| **勘定系システム** | 預金・為替・融資の残高と取引を管理する銀行の基幹システム。BaaSで相乗りさせる対象そのもの |
